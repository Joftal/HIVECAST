# 虎牙画质能力与不可用档位

## 1. 背景

用户反馈（m71711）：虎牙的画质应像哔哩哔哩、斗鱼、抖音一样，按账号能力解锁；当前所有档位都显示可选，选了 4K 后录制几秒就中断，体验上像是“能选但不可用”。

复查确认：

- 虎牙房间页 `vMultiStreamInfo` 会列出 4K HDR、4K、2K HDR、2K、蓝光10M、蓝光4M、超清、流畅等档位，但这是“房间提供了哪些转码档”，不是“当前账号一定能拉流”。
- 660000（虎牙英雄联盟赛事）页面的 `gameLiveInfo.bitRate=10000`，却列出 4K HDR/4K；实际 4K 拉流 4–5 秒后 EOF，应用重试 3 次后进入 5 分钟退避（见 docs/171）。
- chenzihao 的 `bitRate=30000`，但档位里没有 4K 标签。
- 虎牙页面、播放器 JS、`checkLogin` 响应都没有稳定的 VIP/贵族/4K 权限字段；无法像 B 站 `accept_qn` 那样直接读账号能力。

因此本轮采用“登录态 + 房间源码率”的保守能力上限：只有已登录且房间源码率达到 4K 门槛时才开放 4K 档；其余情况把 4K 标为不可用，避免用户选中后必然失败。

## 2. 实现

文件：`src-tauri/src/platform/huya.rs`

### 2.1 能力上限

```rust
fn source_bitrate(stream: &Value) -> u32 {
    // 读 /data/0/gameLiveInfo/bitRate，兼容数字与字符串
}

fn quality_cap(source_bitrate: u32, logged_in: bool) -> u32 {
    if logged_in && source_bitrate >= 20_000 {
        30_000
    } else {
        15_100
    }
}

fn quality_available(qn: u32, cap_qn: u32) -> bool {
    qn <= cap_qn
}
```

- `30_000`：允许 4K HDR（qn=30000）与 4K（qn=20000）。
- `15_100`：最高到 2K HDR（qn=15100），4K/4K HDR 不可用。
- 未登录一律 `15_100`，即使房间源码率很高。

### 2.2 列表与提示

`stream_plan` 在解析 `vMultiStreamInfo` 后：

```rust
let source_bitrate = source_bitrate(&stream);
let logged_in = credential::cookie_for_url(ROOM_HOST)
    .is_some_and(|cookie| !cookie.trim().is_empty());
let cap_qn = quality_cap(source_bitrate, logged_in);
```

每个档位：

```rust
let available = quality_available(qn, cap_qn);
```

不可用的 4K 档追加提示：

- 未登录：`4K HDR HEVC · 20100 kbps · 登录后可用`
- 已登录但源码率不足：`4K HDR HEVC · 20100 kbps · 当前不可用`

已保存过 4K 偏好的房间，`pick_quality` 会把请求 qn 收敛到 `cap_qn`，自动回落到 2K HDR/2K，而不是再次拉 4K 失败：

```rust
let qn = if qn == 0 { qn } else { qn.min(cap_qn) };
```

`qn=0`（跟随全局/自动）仍按原有“接近请求值”的逻辑选最高可用档。

新增/调整：

- `quality_cap_requires_login_and_4k_source`：登录 + 20000/20100 → 30000；未登录 20000 → 15100；登录 10000/0 → 15100。
- `unavailable_4k_falls_back_to_2k_hdr`：源码率 10000 + 登录，请求 20000 时回落到 14100/15100 HEVC；源码率 20000 + 登录保留 20000。
- `parses_numeric_room_fields`（同文件已有）继续覆盖 `totalCount`/`startTime`。

## 5. 限制与后续

1. 虎牙没有公开的“账号 4K 权限”字段，本轮用登录态 + 房间源码率做保守上限，不是精确的 VIP 判定。
2. 660000 的 4K 可能是独立 4K 源而非 `bitRate` 对应的标准源；如果未来确认该房间对某些账号确实可播，当前实现会把 4K 错误地标为不可用。届时应改为读取账号权限，或用一次受控探针检测 4K 能否持续输出。
3. 未登录用户即使房间有 4K 也只会看到“登录后可用”，不会尝试拉流。
4. 只改 `src-tauri/src/platform/huya.rs`，不涉及 B 站/斗鱼/抖音适配器、共享 HTTP、录制器或监控器。
