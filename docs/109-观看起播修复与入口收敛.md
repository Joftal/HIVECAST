# 109-观看起播修复与入口收敛

> 状态：v1 已实施（2026-11-09）；Rust 检查通过，需重启应用后实际点播复看。
> 范围：修复观看 HLS fMP4 起播 404；观看入口只对直播中房间开放；移除详情里的复制房间号。
> 前置阅读：`105-录制详情抽屉重构与播放叠层.md`、`106-录制详情控制台增强.md`。

## 0. 结论速览

- 观看失败的根因不是流解析：ffmpeg 已起播，但 `init.mp4` 被写到了应用工作目录。
- ffmpeg 的 `-hls_fmp4_init_filename` 是相对 **cwd** 的；播放列表却引用会话目录里的 `init.mp4`，流服务器按会话目录读取时自然 404。
- 修复：ffmpeg 以观看会话目录为 `current_dir`，init/分片/播放列表都使用相对文件名。
- `playlist_ready` 现在同时要求 `index.m3u8` 有 `#EXTINF` 且 `init.mp4` 非空，避免播放器抢在 init 落盘前请求。
- 观看入口只对 `room.isLive` 开放；离线房间显示「未开播」，不再允许「离线但录制中」进入必败的观看请求。
- 详情「更多」菜单移除「复制房间号」。

## 1. 现场日志

```text
11:35:09.545 INFO hivecast_lib::view: 观看起播 ... quality=超清 · FLV · H.264
11:35:09.722 DEBUG hivecast_lib::stream::server: 读取播放缓存文件失败
  file=...\view\<session>\init.mp4 error=系统找不到指定的文件
（连续 5 次 404）
11:35:11.606 关闭观看槽位 slot=0
```

- 取流、弹幕、ffmpeg 都正常。
- 播放器请求 `init.mp4` 时文件不存在，hls.js 放弃，用户看到黑屏/起播失败。
- 检查 ffmpeg 命令发现 `-hls_fmp4_init_filename init.mp4` 与 `-hls_segment_filename <绝对路径>` 混用；init 文件落到了进程 cwd（仓库根目录），播放列表却是 `#EXT-X-MAP:URI="init.mp4"`。

## 2. 修复

```rust
command
    .current_dir(&dir)
    .arg("-hls_fmp4_init_filename").arg("init.mp4")
    .arg("-hls_segment_filename").arg("seg_%05d.m4s")
    .arg("index.m3u8");
```

- 会话目录成为 cwd 后：
  - `init.mp4` 写在会话目录；
  - `seg_00000.m4s` 等分片写在会话目录；
  - `index.m3u8` 里的 URI 仍是相对路径，流服务器能直接命中。
- `playlist_ready` 增加 `init.mp4` 非空检查，起播 URL 只在 init 可读后交给播放器。

## 3. 观看入口

- 行内「观看」、详情封面、详情主操作、快捷键 `W` 都只认 `room.isLive`。
- 离线房间：
  - 行内按钮显示「未开播」并禁用；
  - 详情按钮禁用，`title` 说明「直播间未开播，暂不能观看」。
- 修复了之前「离线但正在录制」仍可点观看、但后端 `view_open` 必然拒绝的不一致。

## 4. 验证

- 合成 ffmpeg 命令验证：
  - 修复前 `init.mp4` 出现在进程 cwd，播放列表引用 `init.mp4`；
  - `current_dir=会话目录` 后 `init.mp4`、分片、`index.m3u8` 全部落在会话目录。
- `cargo check --all-targets`、`cargo fmt --check` 通过。
- 需要重启 Tauri 应用后实际点播一次，确认日志中不再出现 `读取播放缓存文件失败 ... init.mp4`。

## 5. 已知限制

- **分片仍可能短暂 404**：ffmpeg 持续写新分片，hls.js 对分片有重试；本轮只保证 init 就绪后起播。
- **修复只影响新观看会话**：旧会话缓存目录关闭时已删除，无需迁移。
- **观看入口依赖 `is_live` 的轮询新鲜度**：平台刚下播但本地还没刷新时，仍可能点进一次失败请求；错误会以 toast 展示。
