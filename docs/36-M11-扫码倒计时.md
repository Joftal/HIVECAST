# 36 · M11 扫码登录有效期与倒计时

> 目标：扫码登录时用户不知道二维码还能用多久；过期后界面有时还要等一次轮询才反应过来。
> 本轮把有效期做成可见的倒计时，并在本地到点就先判失效。

## §2 时间从哪来

B 站二维码有两套时间：

1. **生成接口**（`/x/passport-login/web/qrcode/generate`）只回 `url` 与 `qrcode_key`，**不告诉你多久过期**；
2. **轮询接口**（`/x/passport-login/web/qrcode/poll`）在 `data.expires_in` 里回**剩余秒数**，
   未扫、已扫、已过期都会带。

所以起始时刻只能按官方 180 秒给一个**兜底值**（`QR_TTL_SECONDS`），
真正权威的是轮询回来的剩余秒数——每轮都把本地时刻重新算成 `now + expires_in * 1000`，误差不会累积。

```
// account.rs
let expires_in = fetched.data.data.as_ref().map(|d| d.expires_in.max(0)).unwrap_or(0);
```

`expires_in` 在 Rust 里是 `i64`，ts-rs 默认导出成 `bigint`，
前端 `Date.now() + n * 1000` 会直接编译不过——必须加 `#[ts(type = "number")]`（这是 ts-rs 的既有坑，`Playback.duration_ms` 也踩过）。

## §3 前端状态机

```
type QrState = { ticket; poll; error; expiresAt: number };
```

- `openQr()`：`expiresAt = Date.now() + max(1, ticket.expiresIn) * 1000`；
- 轮询每 1.6 秒一次，拿到 `poll.expiresIn > 0` 就重设 `expiresAt`；
- `useSecondsLeft(qr.expiresAt)` 每 500ms 重算剩余秒；
- 剩余归零且仍是 `pending` / `scanned@@` → 本地把 poll 改成 `state: "expired"`，
  轮询 effect 依赖 `qrState`，状态一变就自动停表（不用额外清理定时器）；
- 过期后照旧走原来的「刷新二维码」按钮，重新生成一张（新的 180 秒）。

界面上倒计时单独一行，`tabular-nums` 保证数字宽度固定不抖动：

```
{counting && secondsLeft !== null && (
  <p className={secondsLeft <= 30 ? "... text-amber-300/80" : "... text-zinc-600"}>
    {t("account.qrExpiresIn", { time: formatCountdown(secondsLeft) })}
  </p>
)}
```

## §4 实测

真机（macOS，`pnpm tauri dev`，为截图临时让设置抽屉自动打开并自动点「扫码登录」）：

| 场景 | 结果 |
| --- | --- |
| 刚生成 | 「等待扫码」+「2:47 后失效」（生成后约 13 秒，服务端 `expires_in` 校准过） |
| 剩余 ≤30 秒 | 倒计时转琥珀色（逻辑 `secondsLeft <= 30`） |
| 本地到点 | 红字「二维码已过期，请刷新」+「刷新二维码」按钮，倒计时行消失 |
| 轮询是否停 | 过期后不再请求 poll（状态机离开 pending/scanned） |

![扫码倒计时](assets/m11-qr-countdown.png)

![过期状态](assets/m11-qr-expired.png)

过期路径是把 `expiresAt` 临时改成 `Date.now() + 4000` 并停掉服务端校准验证的；
真实 180 秒路径由同一段状态机驱动，没有第二套分支。

## §6 踩坑

1. **生成接口不给有效期**，只能按 180 秒兜底；照抄前端 `Date.now()+180s` 是对的，但必须让轮询校准，否则手机端慢一拍就会比真实过期早/晚。
2. **ts-rs 把 i64 导成 bigint**，前端算术直接编译失败；`#[ts(type = "number")]` 不能忘。
3. **i18n JSON 插键要带逗号**：`qrExpiresIn` 后面少了逗号，`node scripts/check-i18n.mjs` 之前的 JSON 解析会直接报
   `Expected ',' or '}' after property value in JSON`。
4. **Fast Refresh 不重跑 `useEffect([])`**：验证「自动打开二维码」这种挂载副作用时，改 `main.tsx` 触发整页重载，
   否则看到的是上一次的界面状态（本轮曾误判「补丁没生效」）。
5. 抽屉是 `overflow-auto`，账号区在首屏之外；截图验证时临时把 `AccountSection` 浮层渲染到顶层，
   比硬滚容器可靠（滚了也会被后续 render 重置）。

## §7 已知缺口

1. 没有「二维码失效倒计时环」（视觉上是纯文字，进度环留给后续打磨）。
2. 扫描成功后没有震动/声音提示，只改文案颜色。
3. 轮询固定 1.6 秒；服务端 `expires_in` 快到 0 时可以拉长间隔，目前没做。
4. 斗鱼/虎牙/抖音仍只支持 Cookie 导入（O4 的既定范围），没有扫码流程。
