## 2. 数据语义

手动转封装与自动后处理共用同一套字段语义：

| 字段 | 手动转封装后 |
| --- | --- |
| `file_path` | 新生成的同目录 mp4 |
| `file_size` | mp4 字节数 |
| `source_path` | 原母带（flv/ts/mkv…），永不覆盖 |
| `post_mode` | `convert` |
| `post_state` | `done`（转封装失败则不写 DB） |
| `source_deleted` | `false`（手动操作保留源） |
| `post_error` | `NULL` |

手动转封装仍走旧的 `postprocess::remux`，没有接新的临时文件 + ffprobe + 回收站链路；它只负责“同目录生成 mp4 + 切主文件”，不会移动源。自动 `convert` 才走 `post::run` 的临时文件、校验、提交 DB、移回收站。

### 3.4 旧数据迁移

首次启动 07:23 的旧 bundle 时，DB 仍是旧 schema，查询报 `no such column: source_path`；那次 48 秒录制不能作为新链路证据。11:43 重新构建并启动后，日志出现：

```
数据库迁移：新增列 column="source_path"
数据库迁移：新增列 column="post_mode"
数据库迁移：新增列 column="post_state"
数据库迁移：新增列 column="source_deleted"
数据库迁移：新增列 column="post_error"
```

随后旧房间被自动续录，新链路才真正开始。结论：**旧 bundle 不会热迁移，必须用包含迁移代码的二进制启动一次**。

## 5. 残余边界

1. 自定义模式只做了单元/合成 ffmpeg 测试，没有真实平台整场验收；其“源永不自动删”的保证由代码路径保证。
2. 手动转封装没有临时文件、ffprobe 校验、回收站和失败重试；失败时不会写 DB，源保持主文件。
3. 已 `failed` 的自动后处理不会自动重试，也没有 post_retry/post_cancel 命令。
4. 媒体库播放中手动转封装后，播放器仍指向旧的 flv 流，直到重新打开；DB/抽屉/卡片已切到 mp4。
5. 多房间同时收尾没有并发上限，会同时跑 ffmpeg。
6. 验收用的媒体根目录来自旧设置，不能当作新安装默认路径。
