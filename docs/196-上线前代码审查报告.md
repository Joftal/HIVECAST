# HIVECAST 上线前代码审查报告

审查日期为 2026-11-23，基线为 `main` 的 `de66ab07cac81f16e1e3c38a03ba6d8d3d6f597c`。审查开始时工作区干净。本文对应这个版本的源码。

**发布判断：建议暂缓正式上线。** Windows 上两条真实 FFmpeg 后处理测试失败。跨平台的分片识别会选中其他文件，整场合并可能在遗漏片段时仍报告成功。这三类问题分别影响产物生成、原始数据安全和交付完整性。

本轮列出 **7 项 P1、14 项 P2、2 项 P3**。P1 建议在公开发布前修复。P2 是特定操作、故障或规模下可触发的问题，建议按发布范围安排回归。P3 涉及界面含义和无效发行内容。

## 发布前优先修复

### 01 · P1 · Windows 会丢弃已成功生成的转封装和自定义转码产物

**真实 FFmpeg 测试复现。** 视频生成并通过校验后，程序以只读方式重新打开临时文件，再调用 `sync_all()`。本机 Windows 返回错误 5，错误分支随即删除临时成品。手动将 FLV 转成 MP4、自动转封装和自定义转码凡是走这条新产物提交路径，都可能只留下源文件和失败记录。用同一个临时文件对照，只读句柄刷盘失败，可写句柄成功。[落盘与错误清理，第 669 行](../src-tauri/src/post.rs#L669)

**修复与验收。** 使用具有写权限的句柄刷盘，并保留真实失败时的源文件保护。在 Windows 上跑通文末列出的两条后处理冒烟测试，核对输出可播放、数据库主文件已切换。

### 02 · P1 · 收尾或自动清理一场录像时可能删掉其他录像的分片

**原函数隔离复现。** 扫描 `room.flv` 时，函数接受所有以 `room.part` 开头且以 `.ts` 结尾的名称。它从最后一个 `.part` 解析编号，解析失败又回退到最大整数。最后一段没有编号上界，两类误匹配都会通过。用项目原函数扫描临时目录，结果同时包含本场的 `room.part0000.ts`、另一场的 `room.part2.part0001.ts` 和普通文件 `room.partial.ts`。合并成功后逐个删除入选文件，保留策略也使用同一份列表。[匹配与筛选，第 56 行](../src-tauri/src/segment.rs#L56) · [删除入选文件，第 227 行](../src-tauri/src/segment.rs#L227) · [保留策略调用，第 151 行](../src-tauri/src/retention.rs#L151)

**修复与验收。** 去掉本场完整前缀及固定后缀之后，要求剩余部分全部为数字并可解析。以两个相似名称的录像和一个普通 TS 文件同时验证收尾、恢复、清理，核对所有旁观文件内容保持完整。

### 03 · P1 · 标题、主播名或目录中的百分号会导致漏录

**真实 FFmpeg 样本复现。** 默认文件名包含主播和标题。代码把完整路径直接拼成 FFmpeg 的序列模板，路径中的字面量 `%` 也被当作格式指令。相同合成音频用普通名称录制成功，用 `100% complete` 或 `room%d` 都报 `Invalid segment filename template`。连续两个百分号则会落成一个，实际文件名与收尾扫描前缀不一致。[默认模板，第 12 行](../src-tauri/src/filename.rs#L12) · [FFmpeg 模板，第 20 行](../src-tauri/src/segment.rs#L20) · [录制入口，第 3366 行](../src-tauri/src/recorder.rs#L3366)

**修复与验收。** 对完整路径的字面量部分做 FFmpeg 百分号转义，再追加唯一的编号占位符。覆盖标题、主播目录、自选媒体根目录和断流续录，验证生成文件能被同一场收尾发现。

### 04 · P1 · 自动清理删文件失败后仍移除录像索引

**静态调用链确认。** 用户启用保留天数或容量限制后，主文件被占用、目录访问被拒绝或外接盘暂不可访问时，清理函数会跳过缺失项或记录错误，随后无条件删除会话并增加成功计数。磁盘上的录像可能完整保留，但媒体页失去入口；设备恢复后也无法通过原记录重试。删除会话还会级联删除媒体文件登记。[文件删除与无条件删库，第 111 行](../src-tauri/src/retention.rs#L111) · [级联关系，第 117 行](../src-tauri/src/db.rs#L117)

**修复与验收。** 区分文件确实已消失、卷不可用和删除失败。持久化未完成的清理项，确认必要文件均处理成功后再删除索引。用临时录像的拒删句柄和暂不可访问的卷分别验收，错误期间保留记录，恢复后可重试。

### 05 · P1 · 仅凭同名和修改时间认领后处理产物，可能归档错误内容

**原函数隔离复现选择错误，后续影响由源码确认。** 同目录先有 `a.flv`，再放入无关的 `a.mp4`，原函数把后者判定为本场派生文件。如果它是可播放媒体，后处理直接登记成功，开启“转封装后删除源”还会把真正的母带移到回收站。如果同名文件未通过校验，在能够成功提交新产物的平台，替换路径会删除原有目标文件。程序在判定归属时没有查询会话登记或恢复清单。[目标选择，第 928 行](../src-tauri/src/post.rs#L928) · [直接复用，第 952 行](../src-tauri/src/post.rs#L952) · [替换目标，第 682 行](../src-tauri/src/post.rs#L682) · [提交后处理母带，第 3788 行](../src-tauri/src/recorder.rs#L3788)

**修复与验收。** 仅复用该会话已经登记或在恢复清单中明确声明的目标。其他同名文件一律保留并原子占用新路径。分别用较新的无关可播放文件、无关普通文件和本场真正的恢复文件验收。

### 06 · P1 · “合并本场 N 段”实际只提交当前页已载入的片段

**前后端调用链确认。** 界面每页加载 60 条，以全场 `clipCount` 显示按钮文案，提交参数却是当前内存的 `group.clips`。即使界面已算出还有片段待加载，合并按钮也可用。一场 61 段的录像首次仅加载 60 段时，后端可以生成只含这 60 段的视频，界面仍提示合并成功。如果当前只加载 1 段，则报至少需要两段。用户必须先手动补齐才能避免这个结果。[分页大小，第 41 行](../src/features/media/RoomRecordingsPage.tsx#L41) · [提交片段，第 689 行](../src/features/media/RoomRecordingsPage.tsx#L689) · [按钮文案与启用条件，第 972 行](../src/features/media/RoomRecordingsPage.tsx#L972)

**修复与验收。** 整场操作按 `groupId` 从数据库获取完整、有序的片段清单，并明确报告缺文件的片段。使用 61 段且带可辨识尾段的样本，从第一页直接合并，确认视频与弹幕均含最后一段。项目已有整组查询可复用。[整组查询，第 1380 行](../src-tauri/src/db.rs#L1380)

### 07 · P1 · 网络异常可能把已脱敏的扫码参数重新写入日志

**静态调用链及锁定依赖实现确认。** 请求失败时先输出脱敏 URL，又直接格式化原始 `reqwest::Error`。项目使用的 reqwest 0.12.28 在错误关联了 URL 时会将原 URL 写入显示文本。B 站扫码轮询的 URL 含 `qrcode_key`，错误会通过 IPC 返回，统一前端封装随后将消息交给 `ui_log`。导出或分享诊断时可能连带分享该参数。审查未使用真实账号或票据。[请求错误组装，第 250 行](../src-tauri/src/platform/http.rs#L250) · [轮询参数，第 282 行](../src-tauri/src/account.rs#L282) · [IPC 错误上报，第 10 行](../src/lib/invoke.ts#L10)

**修复与验收。** 在格式化前移除依赖错误携带的 URL，保留单独脱敏后的地址和错误类型。用虚构标记覆盖连接、超时和解码错误，检查返回消息及落盘日志均不含原始标记。
