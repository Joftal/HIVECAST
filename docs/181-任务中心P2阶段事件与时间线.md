# 任务中心 P2：阶段事件与真实时间线

> 状态：已实现并完成数据库级真机验收；界面视觉复验待解锁屏幕后补做。
> 前置：`180-任务中心全链路追踪实现.md`（P1 聚合、筛选、异常与详情抽屉）。

## 1. 背景

P1 的 Run 详情只有「录制 / 收尾 / 后处理 / 入库」四段汇总，时间来自任务开始和结束的近似值。用户看不到：

- 任务什么时候真正排进队列、什么时候才开始跑；
- 收尾内部在合并分片、切片段、导出弹幕、写库、生成封面中的哪一步；
- 失败发生在哪个阶段、当时进度多少。

P2 把阶段转换写进独立事件表，Run 详情直接展示真实时间线。

## 2. 数据模型

新增 `task_event`：

```sql
CREATE TABLE IF NOT EXISTS task_event (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id TEXT NOT NULL,
    run_id TEXT,
    kind TEXT NOT NULL,
    stage TEXT NOT NULL,
    state TEXT NOT NULL,
    percent INTEGER NOT NULL DEFAULT 0,
    message TEXT,
    at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_task_event_run ON task_event(run_id, at);
CREATE INDEX IF NOT EXISTS idx_task_event_task ON task_event(task_id, at);
```

`task_history` 补两列，把「入队」与「真正开始执行」分开：

- `queued_at`：任务登记时间；
- `started_running_at`：第一次进入非 `queued` 阶段的时间。

旧库由迁移按 `PRAGMA table_info` 补列，不需要重建。

## 3. 写入规则

`src-tauri/src/jobs.rs`：

- `Job` 增加 `queued_at`、`started_running_at`、`persisted`、`last_event_key`。
- 任务登记时写一条 `queued/queued/0%` 事件；不落库的启动恢复任务（`begin_silent`）不写。
- `progress` 只在三种情况追加事件：
  1. `stage` 变化；
  2. `state` 变化；
  3. 进度跨过 25% 桶（0/25/50/75/100）。
  其余 4 Hz 回调只更新内存和 `task_history`，不会把时间线冲成日志。
- 第一次进入 `running` 且 `stage != queued` 时写 `started_running_at`，并强制落库，即使不足 1 秒。
- `finish` 写终态事件；如果 progress 已经写过同一终态则跳过，避免尾部重复两条 `done`。
- `emit_session` 给异步子任务补事件，不写 `task_history`，task_id 形如 `phase:thumbnail:<session>`。

Run id 统一为：

- 有 session：`session:<session_id>`；
- 无 session 的外部任务：`task:<task_id>`。

## 4. 收尾子阶段

`src-tauri/src/recorder.rs` 的 finalize 任务改为 `begin_for(..., session_id, room_id)`，因此所有事件都挂到同一个 `session:<id>` Run：

| 阶段 | 触发 | 进度 |
| --- | --- | --- |
| `finalizing` | 收尾开始，合并分片并生成文件 | 0 |
| `merging` / `splitting` | 单段合并 / 多段按边界切片段 | 5 起，每段 +25/段数 |
| `danmaku` | 切分并导出弹幕 | 75 |
| `commit` | 写入录像库 | 90 |
| `thumbnail` | 生成封面缩略图 | 98 |
| `done` | 收尾完成 | 100 |

缩略图是异步队列，`thumbs.rs` 新增 `ensure_tracked`：排队、成功、失败分别写 `thumbnail` 事件，因此 98% 之后还能看到封面是否真正生成。

## 5. 聚合与前端

`task_center.rs` 在构建 Run 后一次性查 `task_events(run_ids, 4000)`，按 `run_id` 分组塞进 `RunView.events`，按 `at, id` 正序；老数据没有事件时给空数组。

`TasksPage.tsx` 详情抽屉在「链路」与「任务」之间新增「阶段时间线」：

- 事件圆点颜色：失败红、完成绿、排队灰、运行中主题色；
- 每行显示阶段、状态、未满 100% 的进度、`HH:MM:SS` 时间与消息；
- 无事件显示「还没有阶段事件」。

新增 i18n：`stageSplitting`、`stageDanmaku`、`stageThumbnail`、`detailTimeline`、`timelineEmpty`。

## 7. 边界

- 只记录阶段/状态与 25% 里程碑，不按秒存进度，事件量可控。
- 缩略图事件在收尾 `done` 之后异步到达，时间线可能最后多一条 `thumbnail`，属预期。
- 手动合并（命令 `merge`）仍以 `task:job:N` 记录，尚未回填到新会话的 Run；房间录像页的合并结果不受影响。
- 旧会话没有 `task_event`，详情显示空时间线，不回填历史。
- 事件消息沿用任务消息，不包含 Cookie、完整命令行或内部 API URL。
