# 126-全平台画质可用性改造

> 状态：v1 已实施（2026-11-09）；所有平台返回的画质档位都获得唯一、可回选的 qn，虎牙 HEVC 与 B 站杜比开放选择。
> 范围：bilibili / douyu / huya / douyin 画质身份、选择映射、URL 编码与能力清单。

## 0. 结论速览

- 原则改为：**平台能力清单里出现的每一档，都必须能通过 qn 精确回选**；不再用“同一个 qn 合并两个档位”的做法。
- B 站：qn 本身唯一；杜比不再禁用，2K/4K/杜比按 `accept_qn` + MSE 编码门禁展示。
- 斗鱼：`rate4=qn400`、`rate8=qn401`，其它未知 rate 用 `1000+rate`，所有 `multirates` 都能单独选。
- 虎牙：H.264 档使用原 qn；HEVC 4K/2K 使用独立 qn（15000/15100/20000/30000），`pick_quality` 精确按码率取档，取流 URL 使用 `codec=265`。
- 抖音：`ld=80`、`md=79`，未知 sdk_key 用稳定的 2000–9999 qn，避免 `ld/md` 或新档位被合并。
- 观看侧仍按 MSE 编码能力禁用不可播放的 HEVC/AV1；录制侧只按平台能力，不因浏览器不能播放而禁用。
- 真实探测：虎牙 H.264 可正常取流；HEVC/4K 匿名请求返回 403，属于账号/权限限制，不是选择参数丢失。应用已支持按域名注入 Cookie，登录后能否取到 4K 取决于账号权限。

## 1. 为什么必须做唯一 qn

之前部分平台用“平台名称”展示档位，但选择仍只传 u32 qn：

- 虎牙 4K / 4K HDR 都会落到 qn 10000。
- 斗鱼 rate4 / rate8 都会落到 qn 400。
- 抖音 ld / md 都会落到 qn 80。

结果是清单里能看到两档，选择时却只能取到其中一档——违反“平台有就必须可用”。

现在每个平台保证 **qn 唯一且可逆**，`QualityInfo.qn` 直接作为选择值。

## 2. 各平台映射

### Bilibili

- qn 原生唯一：30000 杜比、20000 4K、15000 2K、10000 原画、400 蓝光、250 超清、150 高清、80 流畅。
- `available` 由 `accept_qn` 决定；杜比不再强制禁用。
- 补充（[138](138-B站三态Cookie与取流审计.md)）：匿名（任意探测档）或以最高档探测时还要受 `current_qn` 封顶。匿名下 `accept_qn` 仍列 15000/10000，但实际只回 250，不能再标可用；登录态结果不变。
- `codec` 由各 codec 的 `accept_qn` 汇总：优先 H.264，否则 HEVC/AV1。
- 观看侧用 MSE 支持情况禁用 HEVC/AV1；录制侧允许。

### 斗鱼

| rate | qn | 说明 |
| --- | --- | --- |
| 0 | 10000 | 原画 |
| 1 | 80 | 流畅（平台有才出现） |
| 2 | 150 | 高清 |
| 3 | 250 | 超清 |
| 4 | 400 | 蓝光4M |
| 8 | 401 | 蓝光8M |
| 其它 1–8999 | 1000+rate | 平台新增档位，唯一可回选 |

`rate_for_qn()` 与 `qn_for_rate()` 互为逆映射；测试覆盖 rate 0–20。

### 虎牙

H.264 档：

| 平台名称 | bitrate | qn |
| --- | --- | --- |
| 蓝光10M | 0 | 10000 |
| 蓝光4M | 4000 | 400 |
| 超清 | 2000 | 250 |
| 高清 | 900 | 150 |
| 流畅 | 500 | 80 |

HEVC 档：

| 平台名称 | bitrate | qn |
| --- | --- | --- |
| 4K HDR | 20100 | 30000 |
| 4K | 20000 | 20000 |
| 2K HDR | 14100 | 15100 |
| 2K | 14000 | 15000 |

- `pick_quality()` 对 HEVC qn 精确匹配 bitrate，不再只筛 H.264。
- 取流 URL 的 `codec` 参数按档位写 `264` / `265`。
- 能力清单同时返回 H.264 与 HEVC，`available=true`；观看侧按 MSE 门禁。
- 录制侧允许 HEVC；如果平台账号无权限，实际会取流失败并显示错误。

### 抖音

| sdk_key | qn |
| --- | --- |
| origin | 10000 |
| uhd | 400 |
| hd | 250 |
| sd | 150 |
| ld | 80 |
| md | 79 |
| 未知 key | 2000 + FNV1a(key) % 7000 |

- 未知 key 也进入清单，使用稳定合成 qn；`pick_quality` 按 qn 精确命中。
- `ao`（纯音频）保持 qn 0，不进入画质清单。

## 3. 真实探测结果

### 虎牙 660000

- 页面 `vMultiStreamInfo` 返回：4K HDR、4K、2K HDR、2K、HDR(10M)、蓝光10M、蓝光4M、超清、流畅。
- 用与适配器一致的签名构造 FLV URL：
  - `codec=264&ratio=0` → ffprobe 识别 H.264 1920x1080 + AAC。
  - `codec=264&ratio=4000` → H.264 1920x1080 + AAC。
  - `codec=265&ratio=20100/20000/14000`，以及 `codec=264&ratio=20000` → 403 Forbidden。
- 说明：H.264 基础档可匿名取流；4K/HDR 需要账号权限或特定登录态，当前不是参数编码错误。应用支持按域名注入平台 Cookie，登录后可能可用；无权限时会显示取流错误或降级提示。

### 斗鱼 138243

- `multirates`：原画1080P60(rate0)、蓝光4M(rate4)、超清(rate3)、高清(rate2)。
- `rate_for_qn`/`qn_for_rate` 覆盖全部 rate；如果平台后续出现 rate8/rate1，也有唯一 qn。

### B 站

- `g_qn_desc` 常规返回杜比/4K/2K/原画/蓝光/超清/高清/流畅。
- `accept_qn` 决定当前账号/房间可用档位；杜比与 2K/4K 已进入清单，由 MSE/权限决定能否播放。

## 4. 前端行为

- 平台档位全部渲染，不再因为“同 qn 合并”丢失。
- HEVC/AV1 档位用 `MediaSource.isTypeSupported()` 判断；浏览器不支持时禁用并提示。
- 录制画质不做浏览器 MSE 门禁；观看画质做。
- 自动画质仍优先兼容路径；手动可选 HEVC/4K。
- 自动录制开场后钉住实际 qn，直播中途出现更高档不跳档。

## 5. 仍属于平台/环境边界

- 平台返回档位不代表当前账号一定有权限；虎牙 4K/HDR 匿名 403 已确认。
- 浏览器/硬件不支持 HEVC/AV1 时无法观看，但可以录制。
- B 站杜比音频（E-AC3）是否可播取决于 WebView/系统解码器；已开放选择，失败会显示播放错误。
- 平台完全不返回的档位无法凭空生成；前端通用档位只做解析失败兜底。
