# 176 虎牙弹幕全链路与分段合并复查

> 范围：虎牙弹幕连接（登录态 / 匿名）、消息解析、聊天与礼物落盘、ASS 生成与播放器渲染、分段切片、合并偏移，以及 Cookie 是否影响弹幕内容。
> 结论先行：**登录态与匿名拿到的弹幕内容一致，Cookie 只用于 WS 鉴权，不参与内容下发**；本轮修复了颜色字节序、重复帧、礼物串房、分段与合并偏移四类会造成“丢/错/重”的问题。真机验证覆盖 40 秒双连接对照、672 条分段弹幕、22 段合并与修复后的 13 段合并。

## 1. 结论

| 项目 | 结论 |
| --- | --- |
| 匿名弹幕 | 可用。注册包、心跳、1400 聊天、6501 礼物链路正常 |
| 登录态弹幕 | 可用。连接后发 cmd=10 校验 Cookie，服务端 cmd=11 返回 `valid=0`，仍正常收包 |
| Cookie 是否影响内容 | 不影响。同一房间 40 秒并行采集，登录态与匿名均 389 条聊天、0 礼物、颜色分布一致 |
| 聊天颜色 | 修复为按 `0xRRGGBB` 解析；此前按 `0xBBGGRR` 会把金色解析成天蓝 |
| 重复帧 | 修复。服务端会重复推送同一聊天，现按 `lMsgId` 10 秒 + 文本键 1 秒双重去重 |
| 礼物 | 修复。只接受 `lPresenterUid == room_uid` 的 6501，避免同一 WS 其它房间的礼物混入 |
| 分段 | 修复。切片窗口改用实际容器时长累计，不再用标称 60 秒 |
| 合并 | 修复。弹幕偏移改用 ffprobe 实际时长，并禁止合并产物再次参与合并 |
| 字体 | ASS 使用 `PingFang SC`，Linux 回退 Noto；播放器侧由系统字体渲染 |
| 已知未验证 | 真实礼物样本、cmd=22 批量推送、网页 DOM 颜色对照；见第 6 节 |

## 2. 协议与实现

- 连接：`wss://cdnws.api.huya.com`。`ws.api.huya.com` 的证书 CN 是 `*.cdn.huya.com`，不能直接走 TLS；`cdnws` 证书有效。
- 注册：`WSUserInfo` 字段 0..7；心跳 cmd=1，60 秒一次。
- 登录校验：cmd=10 `WSVerifyCookieReq`（lUid、sUA、sCookie、sGuid、bAutoRegisterUid、sAppSrc），响应 cmd=11 `WSVerifyCookieRsp.iValidate`。
- 推送：`WSPushMessage` 的 uri=1400 为聊天、uri=6501 为礼物；cmd=22 为 `WSPushMessage_V2` 批量列表（field1 是 `WSMsgItem` 列表，每项 uri/sMsg/msgId）。
- 去重键：优先 `lMsgId`（10 秒窗口），没有 id 时用 `(uri, user, content)` 文本键（1 秒窗口）。
- 颜色：`iFontColor` 直接按 24 位 RGB 使用；聊天优先 `tBulletFormat.iFontColor`，回退 `tFormat.iFontColor`。
- 礼物：解析 `sPropsName`（field 20）作为礼物名，旧字段兜底；只保留本房间 `lPresenterUid`。

## 3. 本轮修复

### 3.1 颜色字节序

原实现把 `iFontColor` 当 BGR，`16763904 = 0xFFCC00` 会得到 `0x00CCFF`（天蓝）。虎牙网页/JS 直接按 RGB 使用，现改为 `0xRRGGBB`，同一值得到金色。ASS 行写入 `&H00BBGGRR` 前再做一次字节反转，最终播放器颜色与网页一致。

### 3.2 重复帧

199300 房间 30 秒探针：`frames=107 chats=100 gifts=0 empty=0 dup_keys=45`，同一条聊天会成对出现。旧实现原样写两遍；现按 lMsgId/文本键去重，真机 40 秒双连接 `accepted=206 dropped=183`，落盘不再重复。

### 3.3 礼物串房

虎牙同一 WebSocket 会推送多个房间的礼物，旧实现不过滤 `lPresenterUid`，会把别房礼物写进本场 JSONL。现只接受 `lPresenterUid == room_uid`；没有真实礼物样本，已用单测覆盖“别房礼物丢弃、本房礼物保留”。

### 3.4 分段弹幕

分割录制只有一条整场 JSONL。旧实现按标称 `started_at/ended_at` 切片，而每个 FLV 容器通常比标称 60 秒多 0.2–0.5 秒；6 段累计就能差出数秒，越靠后的片段弹幕相对画面越早。

修复：

- `src-tauri/src/recorder.rs:2583` 起，收尾后对每个片段 ffprobe 实际时长，累加成 `clip_windows`。
- 切片窗口用实际区间 `(actual_start, actual_end)`，而不是标称时间；任一段探测失败则整体退回旧逻辑。
- 片段写库的 `duration_ms` 改用实际时长；首段结束时间也按实际时长修正。
- 真机 15:26 场：4 段实际 60.202 / 60.984 / 60.700 / 34.150 秒，DB 61000 / 60984 / 60700 / 34150 ms；各段 JSONL 末条 t 分别为 58347 / 60478 / 60208 / 33062，均小于容器时长。

### 3.5 合并弹幕偏移

旧实现用数据库 `duration_ms` 累加偏移。分段录制时数据库是整数秒（60000），容器是 60.2–61.0 秒，9 段合并后视频 459.184 秒，而弹幕偏移按 466 秒推进，后半段整体晚约 7 秒。

修复：

- `src-tauri/src/commands.rs:1836` `probe_merge_durations`：合并前逐文件 ffprobe。
- `src-tauri/src/commands.rs:1856` `retime_danmaku_sources`：全部探测成功才替换偏移，避免半新半旧。
- `src-tauri/src/commands.rs:1849` `actual_total_ms`：合并登记时长也用实际总时长。
- 两个合并入口（多选合并、整房合并）都走同一套时长。

### 3.6 禁止合并产物再合并

旧实现允许把已合并的 mp4 再选入合并。实测 14 源（含旧合并产物）生成 37072 秒 mp4、3830 条弹幕，JSONL 出现 3 处时间回退；原因是合并产物的 `started_at` 是“当前时间 - 时长”，会被排到原始录像中间。

现在 `sessions_merge` 遇到 `reason="merge"` 直接返回“合并产物不能再参与合并，请选择原始录像”。整房合并原本就会过滤这类行。真机点“全选 + 合并选中”已显示该提示。

## 4. 真机证据

环境：macOS release bundle，虎牙 199300 陈子豪，数据库为测试库，真实凭据未改。

### 4.1 登录态与匿名对照

- 日志：`虎牙弹幕使用登录态 uid=1199573670219`
- 日志：`Cookie 校验响应 valid=0`
- 40 秒并行探针：两侧均 `389 chats / 0 gifts`，`accepted=206 / dropped=183`，颜色分布一致。
- 结论：Cookie 只参与 WS 鉴权；不给 Cookie 也能收到同样内容，不给内容加权限。

### 4.2 分段切片

- 修复前 370 秒场：7 段，JSONL 183/176/119/117/49/315/20，共 979；ASS 行数一致。
- 修复后 195 秒场：4 段，JSONL 196/347/81/48，共 672；每段 t 从 0 重排，末条不超过容器时长。
- 修复后 15:26 场再次验证 4 段，见 3.4 的时长与 t 范围。

### 4.3 合并

- 修复前 9 源：mp4 459.184 秒，JSONL 1579，偏移按 466 秒推进，尾部晚约 7 秒。
- 含旧合并产物的 14 源：mp4 37072.204 秒，JSONL 3830，3 处回退（387997→382065、847087→841217、922821→919410）。
- 修复后 13 源（仅修复后切片的两场）：mp4 **748.185 秒**，JSONL **1365 条**，末条 **748009 ms**，回退 **0 处**，DB 登记 **748257 ms / 1365 条**。差值 72ms 来自 ffprobe 与写库取整。

## 6. 边界与未验证

1. 两轮真机均未出现真实礼物（`gifts=0`），6501 过滤只有单测与协议字段验证，缺真实样本。
2. cmd=22 批量推送在 40 秒内未出现，解析逻辑只有单测；普通 cmd=7 单条推送已真机覆盖。
3. 颜色只按 JS 协议值修正，未在虎牙网页 DOM 中逐条对照；播放器 ASS 颜色已按 `&H00BBGGRR` 生成。
4. 服务端 `lMsgId` 若在同一房间复用，10 秒窗口内可能误去重；当前未见该情况。
5. 断线重连仍有毫秒级间隙，崩溃最多丢约 200ms（`flush_pending` 周期），这两点与 B 站/斗鱼一致。
6. 旧版本已切坏的 JSONL（例如 14:24 场最后一段 t 超过容器时长）不会被新代码回溯修复，需要重新录制或手工重切。
