# 161 抖音全平台功能复查

- 日期：2026-11-15
- 范围：抖音账号与 Cookie、匿名/登录两态、房间添加与监控、录制/画质/分段/合并/后处理、弹幕、观看、相关设置项，以及对哔哩哔哩与全局功能的影响
- 环境：macOS 14，release bundle，1166×749 窗口；真实账号（抖音 uid 67305272492「执事只食芝士」，哔哩哔哩 uid 352130563，斗鱼 uid 100921751）
- 当前账号方案：抖音**只支持粘贴 Cookie**，保存时用 `profile/self` 校验，每 30 分钟复验、每 6 小时尝试同步服务端轮换的 Cookie；没有扫码登录，也没有可长期续期的凭证。官方登录窗口实现已于 `2df42f4` 回滚。
- 结论：**抖音匿名与登录两态均可监控、录制、出弹幕、观看和切画质；哔哩哔哩与全局功能未发现回归**。本轮修复匿名 ttwid 缓存、弹幕长连接、登录 Cookie 注入、CDN Cookie 泄露风险与两处账号/添加文案问题。

## 1. 账号与 Cookie

| 场景 | 操作 | 结果 |

| 无效 Cookie | 粘贴 `sessionid=fake-invalid` 保存 | toast「抖音 Cookie 已失效或未登录」；日志 `ERROR ui: 界面错误 context=ipc:credential_save`；数据库原 8,635 字节凭据未被覆盖 |

| 失效后回退匿名 | 同上 | 下一轮房间检查日志变为 `saved=false ... 抖音匿名 ttwid 注册完成`，监控继续工作；证明过期凭据不会被继续注入，且匿名兜底可用 |
| 卡片状态 | 失效后打开账号页 | 红色「登录已失效」徽标、`Cookie 已过期，登录态相关的清晰度会回落到游客档位，请重新导入`、`上次检查 ... 需要重新登录` |

本轮修复：失效卡片的说明行仍显示「登录态有效」，与红色徽标矛盾。现在 `src/features/settings/AccountSection.tsx:485` 同时判断 `expired`，失效时显示 warn 色圆点和 `account.autoRefreshExpired`（「登录态已失效，自动复验已暂停」）。

**Cookie 不能真正续期。** 抖音没有可复刻的长期票据：扫码轮询需要 `a_bogus` 与 `x-tt-session-dtrait`，因此 `douyin_auth.rs` 只做「校验 + 复验 + 吸收首页 Set-Cookie」。会话过期后必须重新粘贴，这是产品边界，不是本轮遗漏。

## 2. 登录态与匿名态

| 检查项 | 匿名 | 登录态 |
| --- | --- | --- |
| 房间页 | `saved=false fresh_ttwid=true fresh_cookies=3 has_ttwid=true` | `saved=true fresh_cookies=1 has_ttwid=true` |
| 房间信息 | 正常识别直播/离线 | 正常 |
| 弹幕握手 | `authed=false cookie_names=["ttwid"]` | `authed=true`，Cookie 名 77 个（日志只输出名字，不输出值） |
| 弹幕收到 | 60 秒 `batches=4 messages=4`，聊天房 JSONL 15 条 | 连接稳定，收到真实聊天/礼物事件 |
| 录制画质 | 蓝光 · FLV，`actual_qn=10000`，line=c11 / x0-h5 | 蓝光 · FLV，`actual_qn=10000` |
| 实际分辨率 | 1080×1920（黄二哥聊天房 clip 为 1080×1920） | 1088×1920（姜锦记） |
| 观看画质菜单 | 蓝光 2812 kbps、超清 2000、高清 1600、标清 1000、极速 250、自动 | 蓝光 2870 kbps，其余档位相同 |

两点结论：

1. 登录态主要提升的是**身份与事件完整度**，不是多出一档「原画」。本轮两态最高都只有「蓝光」，没有 4K/原画档；登录后的同档码率只高约 2%，不足以宣称画质档位升级。
2. 匿名不是「功能残废」：房间信息、FLV 取流、录制、弹幕、观看、HLS/FLV 切换都可以走通。匿名首次页面可能被风控到验证码中间页，因此代码主动走 `ttwid.bytedance.com/ttwid/union/register/` 注册 ttwid，并在进程内复用。

需要特别说明的共享改动：

1. **Cookie 不再可能发往抖音 CDN。** `credential::platform_for_host` 不再把 `douyincdn.com` 映射成 `douyin`；取流候选只带 `Referer`/UA（`platform/douyin.rs:906`），不带 Cookie。日志扫描未出现 `sessionid=` 值。
2. **登录 Cookie 注入范围收窄到 `douyin.com` / `iesdouyin.com`**，页面、enter、WS 同域使用；响应里的新 ttwid 会与旧 Cookie 合并，不用旧值覆盖新值。
3. **签名 UA 升到 Chrome 140 / Edge 140**（`platform/abogus.rs:45`），同步更新签名测试向量；这只影响抖音 `a_bogus`，不影响 B 站 WBI 或斗鱼。

## 9. 剩余问题与边界

1. **没有扫码登录**：官方登录窗口提交已回滚；当前只支持粘贴 Cookie。用户若需要「手机扫码」必须重新立项，且要接受 `a_bogus`/dtrait 跟版成本。
2. **不能真正续期**：会话失效只能重新粘贴。每 30 分钟复验、每 6 小时同步只是尽早发现/吸收服务端轮换，不是续期。
3. **「上次轮换」可能长期为空**：服务端若只重发同值 ttwid，`changed=0`，卡片不会出现「上次轮换」；这是语义正确但容易被误读为没工作，建议后续加「已检查，无变化」文案。
4. **未测真实手机扫码/真实账号自然过期**：失效测试是把 DB Cookie 改成无效值后启动，验证了自动复验与匿名回退；没有等待真实会话过期。
5. **未测 `v.douyin.com` 短链**：添加测试用的是 `live.douyin.com` 完整链接与无效别名；短链展开逻辑存在但本轮无真实样本。
6. **抖音没有关注导入**：导入弹窗目前只有哔哩哔哩/斗鱼；抖音监控只能逐个添加。
7. **没有 4K/原画档**：本轮账号与匿名都只拿到「蓝光」，不能据此判断会员/高权限账号的上限；付费/私密/连麦等场景未覆盖。
8. **长稳未压测**：弹幕样本为 60 秒与 481 秒，录制样本约 44 分钟；未做数小时挂机、断网重连、CDN 切换矩阵。
9. **窗口 1166 宽下的全局表格截断**仍在：画质、备注、搜索占位在窄窗口会被裁，属既有布局问题，本轮未改。

## 11. 一句话结论

抖音的匿名/登录两条链路已经能稳定完成「添加 → 监控 → 录制 → 分段合并 → 弹幕/ASS → 媒体库/观看」；登录 Cookie 的校验、复验、失效回退和 CDN 隔离都做了实机验证。当前产品边界是**没有扫码、不能续期、最高只有蓝光**，其余不是回归，而是抖音平台能力与当前方案的限制。
