# 81 录制后处理 P0–P2 修复与真机验收

> 状态：P0–P2 已实现并完成真机验收（2026-11-08）。对应代码为 `e288844` 之后的工作区改动，尚未提交。
> 前置阅读：[77-录制后处理四方对比与设计](77-录制后处理四方对比与设计.md)、[78-录制后处理实现与验收](78-录制后处理实现与验收.md)、[79-录制后处理v1收尾与真机验收](79-录制后处理v1收尾与真机验收.md)、[80-录制后处理v1总结与四方对比](80-录制后处理v1总结与四方对比.md)。
> 本文回答：80 里列的 P0/P1/P2 缺口是怎么补的、补到什么程度、哪些边界仍然没做。

## 0. 结论先行

1. **P0 的“失败可恢复”闭环已经补齐。** 失败/取消的条目可以在媒体库直接重试，运行中的条目可以取消；手动“转 MP4”已收编到 `post.rs` 的 convert 链路，不再走旧的 `postprocess::remux`。
2. **P1 的“批量收尾可控”已经落地。** 自动与手动各 1 个专用槽、全局 2 个槽；转换前按“源大小 × 1.15 + 256 MiB”预检磁盘；ffmpeg 进度映射到 5%–90%，校验 93%，完成 100%；退出时取消全部任务并最多等 6 秒清理临时文件。
3. **P2 的 custom 已用真实整场录制验证。** 不是 `-c copy`，而是真实转码；超时、无输出、路径含中文、失败文案都走到了。手动转封装也复用同一套临时文件、ffprobe、错误映射。
4. **当前剩余的主要是 P3 生态能力，不是后处理内核缺口。** 上传、压制、字幕烧录、封面、Webhook、云同步仍未做；这些应另立产品层，不应再复制一套转换链路。
5. **验收中发现并修掉一个“仅删源”后的状态回退问题。** 手动转封装如果已有 `source_path`，现在会保留原来的 `source_deleted`，不会把已进回收站的源重新标成“可见”。

## 1. P0：失败可恢复

### 1.1 重试

新增 `post_retry(session_id)`（`src-tauri/src/commands.rs:601` 附近）：

- 只接受 `post_state = failed | cancelled`，录制中、已完成、源封装已不存在都直接拒绝。
- 源路径优先取 `source_path`，没有才取 `file_path`；这样“转封装失败但母带还在”时重试的是母带，而不是半成品。
- 执行模式沿用这条录像原来的 `post_mode`，其余参数（目标封装、自定义命令、超时）取当前设置。也就是说：失败后改设置再点重试，会按新设置跑，但不会把 convert 失败偷偷改成 source。
- 成功：主文件切到新产物，`source_path` 保留母带，`post_state=done`，清空错误。
- 失败或取消：主文件保持原来的可播放路径，只更新 `post_state` 与 `post_error`，不会把唯一能播的文件改坏。
- 重试期间同样登记 `jobs` 任务，媒体库能显示进度、能再次取消。

### 1.2 取消

新增 `post_cancel(session_id)`（`src-tauri/src/commands.rs:682` 附近），底层是 `post::cancel_session`：

- **会话级标志**：一场录像收尾可能连续跑多个片段；`begin_session` 在收尾开始登记一个 `Arc<AtomicBool>`，取消会覆盖之后才创建的每个任务。
- **任务级标志**：`tasks()` 按 task id 登记 `TaskSlot{session_id, cancelled}`；排队中和运行中的任务都能收到取消。
- 排队阶段每 120ms 检查一次取消标志，不会等拿到信号量才发现已经取消。
- 运行阶段每 150ms 检查一次；取消后 `start_kill` + 最多等 5 秒，删除 `.{name}.post-{uuid8}.{ext}` 临时文件，返回 `cancelled`。
- 进程退出走 `post::shutdown`：`cancel_all` 置 `shutting_down`、翻全部标志，最多等 6 秒；之后才创建的恢复任务也会立即取消，不会在退出过程中再起 ffmpeg。

### 1.3 媒体库入口

- 卡片左上角第二行是统一的状态徽标：
  - 排队：`排队中`；运行：`N% · 取消`；可点击取消。
  - 失败：`后处理失败 · 重试`；取消：`后处理已取消 · 重试`；点击立刻重试。
  - 完成：`已转封装` / `自定义后处理` / `保留源封装`；源已删时追加 `· 源已删`。
- 详情抽屉同样有进度、取消、重试；失败原因作为徽标 `title` 与抽屉错误文案展示。
- 进度按 `sessionId` 存，自动收尾、手动转封装、重试互不覆盖；`done`/`cancelled` 后清掉进度，`done|failed|cancelled` 500ms 后重新拉列表，等 DB 落库完成再刷新。

### 1.4 手动转封装收编

`session_remux`（`src-tauri/src/commands.rs:525` 附近）不再调用旧的 `postprocess::remux`，而是：

```text
构造 PostConfig{mode=convert, convert_format=mp4, delete_source=false}
  → post::run
  → 临时文件 / 磁盘预检 / 进度 / 取消 / ffprobe / 错误映射
  → 成功：source_path = 原 file_path（若原本没有 source），主文件切到新 mp4
  → 失败：主文件保持原路径，post_state=failed，媒体库可重试
```

保留源的规则：

- 第一次转封装：`source_path` 为空，旧主文件登记为母带，新 mp4 成为主文件。
- 已有 `source_path`：沿用原来的源路径和 `source_deleted`，不把“仅删源”的结果重置。
- 主文件本来就是 mp4：`run_convert` 直接校验后返回原文件，不生成第二份；UI 的转封装按钮对 `.mp4` 主文件禁用。

### 1.5 双文件播放与仅删源

- 详情抽屉只在 `source_path != path` 时显示“文件”区：
  - `播放主文件` / `播放源封装` 两个按钮，切换本地流服务读取的文件。
  - 源已删时“播放源封装”与“仅删源”隐藏，源行显示“源已删”。
- `media_delete_source`（`src-tauri/src/commands.rs:688` 附近）：
  - 拒绝录制中、没有主文件、没有独立源、`source == main`。
  - 源文件已经不存在：直接标记 `source_deleted=1`，不报错。
  - 源还在：先对主文件 `validate_media`，通过后停止回放、把源移入回收站、再写 `source_deleted=1`；主文件校验失败不会动源。
- `media_delete` / `media_delete_group` 在 `delete_file=true` 时同时删除主文件、源封装、弹幕与 sidecar，再删 DB 行；整场删除逐片段尽力删，单段文件删失败会保留该段记录，方便重试。

## 2. P1：并发、磁盘与进度

### 2.1 并发槽

| 通道 | 信号量 | 规则 |
| --- | --- | --- |
| 自动收尾 | `auto_slots = 1` | 同一时刻最多一个自动任务 |
| 手动操作 | `manual_slots = 1` | 手动转封装/重试串行 |
| 全局 | `global_slots = 2` | 自动 + 手动合计最多两个 |

自动任务先拿 `auto` 再拿 `global`，手动先拿 `manual` 再拿 `global`。这样手动最多占一个全局槽，另一个始终留给录制收尾，避免用户连点转封装把收尾饿死。排队中的任务每 120ms 检查取消，不会被信号量卡死。

### 2.2 磁盘预检

`ensure_disk_headroom` 在启动 ffmpeg 前检查源文件所在分区的可用空间：

```text
need = source_size + source_size * 15% + 256 MiB
free = fs4::available_space(source.parent())
free < need → failed：「磁盘剩余空间不足：需要约 X，当前可用 Y」
```

15% 覆盖容器转换的等大产物与索引开销；256 MiB 是给 faststart、日志和文件系统留的余量。custom 可能转码后更小，但仍按源大小预留，宁多勿少。

### 2.3 进度

- `run_convert` 直接带 `-progress pipe:2 -nostats`，不占 stdout。
- `run_custom` 用 `inject_progress_args` 把 `-progress pipe:2 -nostats` 插到输出参数前；用户模板里已经写了 `-progress` 或 `-nostats` 就不重复插。
- `parse_progress` 支持 `out_time_us=`、`out_time_ms=`（ffmpeg 里实际也是微秒）、`time=`；按 ffprobe 时长映射到 5%–90%，上限 90。
- 阶段：0% queued → 2% preparing → 5%–90% running → 93% validating → 100% done；失败/取消回 0 并带文案。
- 时长为 0 或取不到 ffprobe 时不显示百分比，但仍显示阶段与取消按钮。

### 2.4 临时文件、校验与提交顺序

```text
临时文件名：.{原文件名}.post-{uuid8}.{目标扩展名}
  → ffmpeg 写临时文件
  → 退出码 0 且临时文件非空
  → ffprobe 校验（缺 ffprobe 时 ffmpeg 读 1 秒）
  → fsync
  → 目标已存在则先删
  → rename
  → 返回 PostOutcome
  → 调用方写 DB
  → convert + delete_source 且 target != source：DB 提交成功后才移回收站
```

取消、失败、超时、校验失败、fsync 失败、rename 失败都会删临时文件；失败永远返回源文件路径，不会留下“半成品主文件”。

### 2.5 失败文案

`explain_failure` 把 ffmpeg stderr 映射成用户能看懂的原因：

- 磁盘空间不足
- 编码器不可用
- 输入容器或编码无法识别
- 输入文件无法打开
- 没有写入权限
- 没有生成输出文件
- 没有生成有效的音视频流
- ffmpeg 执行失败

后面附退出码与最后 3 行非空 stderr，总截断 300 字符，避免把整页日志塞进徽标。

## 6. 仍存在的边界

1. **没有真正的任务中心。** 并发槽和进度事件已经有了，但没有“全局任务列表/历史任务”页面；任务只活在本次进程内，重启后排队任务不会续跑。
2. **自定义命令仍是本机 ffmpeg 进程。** 不经过 shell，但能读写用户有权限的文件；不是安全沙箱。
3. **回收站跨平台语义不同。** macOS 移入 `~/.Trash`；Linux 只移动文件、不写 `.trashinfo`，桌面环境可能无法“还原”。
4. **同名派生文件按 mtime 复用。** 目标已存在且不早于源文件时会复用，可能误复用用户手工放入的新文件；复用前仍会 ffprobe 校验。
5. **手动转封装主文件扩展名变化时，旧派生文件可能留下。** 例如 custom 产出 MKV、源已删，再手动转 MP4：新 MP4 成为主文件，旧 MKV 不再被 DB 引用。当前不自动删旧派生文件，避免误删；后续可在“派生文件引用计数”里统一清理。
6. **P3 生态未做。** 上传、压制、字幕烧录、封面、Webhook、云同步都没有；按 77 的建议另立产品层。
7. **doc/80 的旧结论以本文为准。** 80 写于 P0–P2 之前，正文里的“缺重试/取消/队列/磁盘预检”“手动转封装仍是旧链路”已经被本文覆盖。

## 7. 一句话总结

后处理内核的“失败可恢复、批量可控、custom 可用”三件事已经闭环：243 个单测、真实整场转码、重试取消、仅删源、整场清源都过了；下一步不是继续加后处理模式，而是任务中心和 P3 生态。
