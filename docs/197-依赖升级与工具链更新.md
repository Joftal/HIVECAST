## 1. 目标与策略

本轮目标是把项目使用的组件、依赖和开发工具尽可能升到当前稳定最新版本，降低后续维护成本，同时保证录制、弹幕、登录、任务中心等既有功能不被升级破坏。

策略：

1. **按模块分组升级**：前端补丁/次版本、前端主版本、Rust Tauri 补丁、Rust 运行时主版本、密码学主版本、其余主版本、工具链，每组单独构建/测试。
2. **保持精确版本**：`package.json` 与 `src-tauri/Cargo.toml` 继续写精确版本，不使用 `^`/`~` 漂移。
3. **不跟随 alpha/beta**：Tauri 3 仍是 alpha，继续停在 2.x 最新稳定版。
4. **运行时对齐**：Node 保持 24 LTS，因此 `@types/node` 不升到 26；Rust 的 `rust-version` 按依赖实际 MSRV 调整。
5. **每组验证**：`cargo check` / `cargo test` / `pnpm build`，最后统一跑格式、Clippy、文档、i18n、release 构建和启动冒烟。

### 4.2 运行时主版本（`c513c28`）

| crate | 升级前 | 升级后 |
| --- | --- | --- |
| `reqwest` | 0.12.28 | 0.13.5 |
| `rusqlite` | 0.37.0 | 0.43.0 |
| `fs4` | 0.13.1 | 1.1.0 |
| `tokio-tungstenite` | 0.24.0 | 0.30.0 |

同时把 `src-tauri/Cargo.toml` 的 `rust-version` 从 `1.77` 提到 `1.89`：`rusqlite 0.43` 需要 Rust >= 1.89，`std::fs::File::try_lock` 也是 1.89 稳定。

**API 适配**：

1. `reqwest 0.13` 删除 `rustls-tls` feature，`form` 变为显式 feature。Cargo.toml 改为：
   `reqwest = { version = "=0.13.5", default-features = false, features = ["rustls", "json", "gzip", "form"] }`
2. `rusqlite 0.43` 不再为 `u64` / `Option<u64>` 实现 `ToSql`。`/Library/dshproject/HIVECAST/src-tauri/src/db.rs` 的 `info.online` 与 `item.online` 改为 `.map(|value| value as i64)`；`item.uid` 是 `String`，不需要转换。
3. `fs4 1.1` 删除 `fs4::fs_std::FileExt` 与 `FileExt::try_lock_exclusive`。改用标准库：
   `std::fs::File::try_lock()` + 匹配 `std::fs::TryLockError::WouldBlock`，删除 `fs4::FileExt` import。涉及 `/Library/dshproject/HIVECAST/src-tauri/src/instance.rs` 与 `/Library/dshproject/HIVECAST/src-tauri/src/recorder.rs:3934`。`fs4` 仍保留用于 `available_space`。
4. `tokio-tungstenite 0.30` 的 `Message::Binary` 改为接收 `Bytes`。在 `/Library/dshproject/HIVECAST/src-tauri/src/danmaku.rs` 增加：
   ```rust
   fn ws_binary(data: Vec<u8>) -> WsMessage {
       WsMessage::Binary(data.into())
   }
   ```
   斗鱼/虎牙所有发送与测试统一走 `ws_binary(...)`。

### 4.3 密码学主版本（`fbb3028`）

| crate | 升级前 | 升级后 |
| --- | --- | --- |
| `md5` | 0.7.0 | 0.8.1 |
| `base64` | 0.22.1 | 0.23.1 |
| `aes-gcm` | 0.10.3 | 0.11.1 |
| `rsa` | 0.9.10 | 0.10.0 |
| `sha2` | 0.10.9 | 0.11.1 |
| `rand` | 0.8.8 | 0.10.4 |

**API 适配**：

1. `rsa 0.10` 删除 `sha2` feature，Cargo.toml 改为 `rsa = "=0.10.0"`。类型 `RsaPublicKey` 改为 `rsa::PublicKey`；加密改用 `key.oaep_encrypt::<Sha256>(message.as_bytes())`（不再传 rng），测试解密改用 `private.oaep_decrypt::<Sha256>(&bytes)`。
2. `rand 0.10`：`thread_rng()` → `rand::rng()`，`gen_range` → `random_range`，trait 由 `rand::Rng` 改为 `rand::RngExt`。涉及 `/Library/dshproject/HIVECAST/src-tauri/src/account.rs`、`/Library/dshproject/HIVECAST/src-tauri/src/huya_auth.rs`。
3. `aes-gcm 0.11` 不再导出 `aead::OsRng` / `generate_nonce` / `generate_key`。`/Library/dshproject/HIVECAST/src-tauri/src/secret.rs` 改为：
   - `rand::random::<[u8; 12]>()` + `Nonce::from(bytes)`
   - `rand::random::<[u8; 32]>()` 生成密钥
   - 解密用 `Nonce::<aes_gcm::aead::consts::U12>::try_from(nonce)`，避免 deprecated `from_slice`。

凭据密封格式与平台登录流程没有变化，只替换了底层 API。

1. **构建脚本白名单位置变化**：删除 `package.json` 的 `pnpm.onlyBuiltDependencies`，新增 `/Library/dshproject/HIVECAST/pnpm-workspace.yaml`：

## 8. 已知限制

1. **没有逐项人工点击回归**。本轮验证覆盖编译、单测、构建、release 启动冒烟与真实凭据续期，但没有对全部页面做人工点击。
2. **Windows 未真机验证**。Windows 仍依赖 GitHub Actions 的 `windows-2022` runner；本机没有 `gh` CLI，未触发 Actions，NSIS 安装器需首次 CI 运行确认。
3. **macOS 仅 arm64、ad-hoc 签名**。与 195 一致，没有公证与 Intel 构建。
4. **Clippy 仍有 66 条既有 warning**。本轮只修复了 2 个阻断构建的 `erasing_op` error，没有扩大范围清理历史 warning。

## 9. 后续建议

1. 首次真实触发 GitHub Actions（`publish=false`），确认 Windows NSIS 与 macOS DMG 均能产出。

3. Clippy 的 66 条历史 warning 单独开清理提交，不和依赖升级混在一起。
