# 78 录制后处理实现与验收

> 状态：v1 已实现（2026-11-08）。依据 [77-录制后处理四方对比与设计](77-录制后处理四方对比与设计.md)，按用户 m29073 的拍板落地。
> 本文记录**实际实现**、验收证据与残余缺口；77 是设计评审稿，其中 §5.3 老用户迁移、§9 三个待拍板项属于历史方案，**不再执行**。

## 0. 与 77 的差异

用户明确：项目仍在迭代，没有外部用户，**不考虑老用户迁移**。因此：

- 不读取、不迁移 `post.auto_remux`，旧键直接忽略；默认 `post.mode=source`。
- 不做 `post.migrated_v1`、不做升级提示、不把老会话回填成 `legacy`。
- FLV + HEVC/AV1 的母带用 `.mkv`，不做 `.ts` 备选。
- 自定义后处理使用**完整 ffmpeg argv 模板**，必须同时包含 `{input}` 与 `{output}`，不经过 shell，源永不自动删。
- 77 §5.2 的多阶段状态机在 v1 简化为三个状态：`recording` / `done` / `failed`；细节由 DB 字段 + 清单 + 文件系统共同恢复。
- 77 §6 设想的独立 orchestrator 目录未落地，编排集中在 `recorder.rs` 的收尾/恢复路径与 `post.rs`。

## 1. 实际生命周期

### 1.1 开录

- `recorder.rs:832 start_inner` 在解析出实际线路后，从当前设置快照 `PostConfig`（`recorder.rs:930`），中途改设置只影响下一场。
- 母带扩展名由实际拿到的 `StreamFormat` + `Codec` 决定（`recorder.rs:962-979`，`post::source_extension`）。
- 文件名仍由 `filename::reserve_unique_path` 原子占位；录制期间 ffmpeg 仍写同 stem 的 `.partNNNN.ts`，但占位文件不再是固定 `.mp4`。
- `create_session` 同时写入 `source_path=占位路径`、`post_mode`、`post_state=recording`、`source_deleted=false`。

### 1.2 收尾

`recorder.rs:1814 finalize` 的顺序固定为：

1. 停 ffmpeg、按分片规划 clip；
2. 每段先 `finish_range` / `finish_file` 合并成**源封装母带**（`recorder.rs:3041/3083`）；合并失败退化为字节拼接的 `.ts`，不会凭空丢文件；
3. 对母带执行 `post::run`（`recorder.rs:1984`）：source 直接校验母带；convert/custom 写临时文件、校验、`fsync`、rename；
4. 首段用 `finish_session_with_post` 单条 UPDATE 提交路径与后处理结果（`db.rs:599`）；后续片段 `create_clip` 带上同样的后处理字段；
5. **数据库成功之后**才执行 `delete_source_after_commit`（`recorder.rs:3018`）：移入回收站成功再 `set_source_deleted(true)`；失败只 WARN，源保留；
6. 全部片段与 DB 成功后清单标 `completed` 并删除；任一步失败保留清单，启动恢复只补缺失的源/最终文件，**不自动重试已 `failed` 的后处理**。

### 1.3 三种模式

| 模式 | 行为 | 产物 | 删源 |
| --- | --- | --- | --- |
| `source`（默认） | 只封母带并校验 | 源封装文件 | 不动 |
| `convert` | `-map 0 -c copy` 转到目标封装，临时文件 + ffprobe + rename | 母带 + 派生文件 | 仅显式开启且转换成功、DB 提交后 |
| `custom` | 把模板分词成 argv，替换占位符后直接执行 ffmpeg | 母带 + 自定义输出 | **永不自动删** |

互斥规则：`custom` 不执行内置转换，`convert` 不执行自定义命令；切到非 `convert` 时设置页会把 `postDeleteSource` 置回 false。

## 2. 容器映射

实现位于 `post.rs:101 source_extension`：

| 源格式 | 编码 | 母带 |
| --- | --- | --- |
| FLV | H.264 / 未知 | `.flv` |
| FLV | H.265 / AV1 | `.mkv` |
| HLS / HTTP-TS | 任意 | `.ts` |
| DASH / fMP4 | 任意 | `.mp4` |
| AudioOnly | AAC | `.m4a` |
| AudioOnly | 非 AAC / 未知 | `.mka` |

补充：

- 这是**容器重封装**，不是 bit-exact 原始流；时间戳、FLV header、TS PAT/PMT 会重写。
- `segment::merge_range` 只在目标扩展名为 `mp4/mov/m4v` 时加 `-movflags +faststart`；FLV/TS/MKV/M4A 加该参数会被 ffmpeg 拒绝。
- 合并失败时 `finish_range/finish_file` 走字节拼接，目标变成 `.ts`，属于兜底而不是正常路径。

## 3. 自定义命令的安全边界

实现位于 `post.rs`：

- 模板必须同时含 `{input}` 与 `{output}`，保存设置时静态拒绝缺占位符的模板。
- 自写分词支持单/双引号与反斜杠；**不经过 shell**，管道、重定向、`&&`、`;` 作为独立 token 会被拒绝。
- 允许模板首 token 是 `ffmpeg` / `ffmpeg.exe`，其余参数原样传给应用解析出的 ffmpeg。
- 输出扩展名只保留 ASCII 字母数字、最多 8 位、自动小写；空值回落 `mp4`。
- 超时默认 600 秒，范围 10–86400 秒；超时/失败会删临时文件、保留母带，状态记 `failed` + `post_error`。
- 成功也必须通过 `validate_media`（优先 ffprobe，缺 ffprobe 时用 ffmpeg 读 1 秒）才 rename；退出码 0 不等于产物可用。
- 自定义模式不产生 `delete_source`，即使设置里误留 `true` 也不会删。

## 4. 数据与设置

### 4.1 设置

`settings.rs` 实际键与默认值：

| 键 | 默认 | 取值 / 夹取 |
| --- | --- | --- |
| `post.mode` | `source` | `source` / `convert` / `custom`；非法回落 source |
| `post.convert_format` | `mp4` | `mp4` / `mkv` / `ts` |
| `post.delete_source` | `false` | 布尔；仅 convert 生效 |
| `post.custom_command` | `-i {input} -c copy {output}` | 必须含两个占位符；custom 保存时校验 |
| `post.custom_output_ext` | `mp4` | 清洗为 1–8 位小写字母数字 |
| `post.custom_timeout_sec` | `600` | 夹在 10–86400 |

旧 `post.auto_remux` 不再读取或写入。

### 4.2 会话字段

`record_session` 新增 5 列（`db.rs:18` SCHEMA，`db.rs:1232` 迁移）：

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `source_path` | TEXT NULL | 母带路径 |
| `post_mode` | TEXT NOT NULL DEFAULT `source` | 本场模式快照 |
| `post_state` | TEXT NOT NULL DEFAULT `done` | `recording` / `done` / `failed` |
| `source_deleted` | INTEGER NOT NULL DEFAULT 0 | 源是否已移入回收站 |
| `post_error` | TEXT NULL | 给 UI 的失败原因 |

`file_path` 仍是“当前主播放文件”：source 等于母带；convert/custom 成功等于派生文件；后处理失败等于母带。`RecordSession` 与 `MediaItem` 均暴露这些字段，`MediaItem.has_source` 在列表查询时按“文件存在且未标记删除”计算。

### 4.3 恢复清单

`SplitManifest` 升到 `version: 2`（`recorder.rs:2696`）：

- 顶层 `post: PostConfig` 记录本场快照；
- 每个 clip 增加 `final_path`（最终播放文件），`path` 始终是源封装；`post_state` / `post_error` 记录该段后处理成败，旧清单缺这两个字段时按 `done`。
- `version: 1` 清单仍可反序列化，但 `remux` 字段被忽略，`post` 走 `Default`，即按 **source** 恢复。由于本项目明确不做老用户迁移，这是可接受的取舍；老清单不会自动转 MP4。
- `recover_split_manifest` 逐段优先复用 `final_path`，其次复用源封装，缺源才重新合并，缺 final 才跑 `manifest.post`；已有 final 时保留清单里的成败状态，不把失败误标成功。DB 提交后才删/标记源。已记录 `failed` 的段不会在下次启动被自动重跑，只补缺失的 final/源。
- 非清单的 `recover_parts` 用**当前设置**快照补后处理；已 `done` 且文件存在的会话只补大小，不重复转换。

## 5. 界面

- 设置 → 录制与媒体 → 录制后处理：模式、目标封装、删除源、自定义命令、输出扩展名、超时六行；搜索索引同步拆成 6 条。
- 设置保存仍走后端 `settings::save`，custom 模板错误会以“自定义后处理命令不可用：…”返回；扩展名与超时会被后端规范化后回填。
- 媒体库卡片：平台徽标下增加后处理徽标，失败显示红色“转换失败”并把 `postError` 放进 title；成功按模式显示“源封装 / 已转 MP4 / 自定义”，`sourceDeleted` 追加“源已删”。
- 媒体卡仍以 `file_path` 为主播放文件，后处理失败时自然回落到母带。

## 7. 残余缺口与风险

1. **没有真实平台端到端验收**：Rust 单测与合成 ffmpeg 管线覆盖了合并、校验、恢复，但未跑“真实房间录制 → 收尾 → convert/custom → 删源”的完整链路。
2. **媒体库只做徽标**：77 设想的“展开两行：母带 / 派生文件；分别播放、在文件夹中显示；失败重试；仅删源”未实现。`has_source` 已进接口，UI 还没有消费。
3. **没有 post_retry / post_cancel 命令**：已 `failed` 的后处理不会自动重试；只能手动改设置后重新录制，或在媒体库外手工转封装。没有任务队列与并发上限，多个房间同时收尾会同时跑 ffmpeg。
4. **手动转封装仍是旧链路**：`postprocess.rs` 的 `remux/merge` 与新的 `post.rs` 并存；手动操作保留源，但没有接统一的校验/回收站/状态机。
5. **恢复时删源不是严格两阶段**：DB 提交后、移入回收站前崩溃，重启会按“源不存在”补 `source_deleted=true`；若回收站移动失败，源会保留但状态仍是 `done`（设计如此，UI 可能显示“源未删”而不是错误）。
6. **目标复用按 mtime 判断**：`post::target_for` 优先复用同 stem 同扩展名的非空文件，但要求派生文件 mtime 不早于源，否则改名为 `stem.1.ext`；输出扩展名与源相同时也会跳过源，避免自定义命令覆盖母带。若用户手工放了同名且时间更新的文件，仍可能被当作本次产物复用（会先 ffprobe 校验）。
7. **Linux 回收站只移动文件**：没有写 `.trashinfo`，桌面回收站可能无法“还原”；macOS 固定移到 `~/.Trash`，跨卷时退化为复制 + 删除；Windows 走 PowerShell 回收站 API。
8. **source 模式也做 ffprobe 校验**：好处是母带不完整会显式失败；代价是极少数容器/时间戳异常的源可能被判 `failed`，此时母带仍在，媒体库仍可播放。
9. **v1 清单忽略 remux**：老清单恢复为 source，不会按老开关转 MP4；与“不迁老用户”的决策一致，但需要知道这个行为。
10. **分片仍是 MPEG-TS**：母带容器不是录制时的原始字节，不能承诺 bit-exact；直录源容器不在 v1 范围。
