# 204 · 上线前独立代码审查与 Windows 复验

2026-11-26 · Windows 11 专业版 x64 · 候选版本 `0.1.0` · 审查提交 `7e5f00f927185a75e2eb9694eba842823966f2b0`

本报告记录修复前的复现结果。修复后的 Windows 验收及 macOS 专机步骤见[205 号报告](205-修复验收与macOS专机测试点.md)。

**建议暂缓 Windows 和 macOS 的正式分发。** 本轮新增 7 项发现，其中 2 项 P1 会让启动恢复删除尚未正确登记的真实分片，已在 Windows 隔离夹具复现。203 号提到的 PID 标记缺失也已实测到“旧进程仍在写、数据库已关单且允许恢复”，本轮将其列为 P1。三项均位于两端共用的恢复逻辑。macOS 对外分发另有 203 号真机发现的签名问题。

202 号的 Windows 安装、托盘、账号和并录验收仍有参考价值。此前的放行判断没有覆盖下述故障组合，本报告更新该判断。当前提交相对 `d3108fad75e420ef21a1e53aa7bc89f48b90a710` 只新增 203 号文档，产品源码完全相同。开始审查时工作树干净。[202 号 Windows 验收](202-Windows上线前最终验收报告.md) · [203 号 macOS 真机报告](203-macOS独立审查与d3108fa真机验收.md)

## 一、本轮新增发现

| 编号 | 触发条件与实际影响 | 证据与修复验收条件 |
| --- | --- | --- |
| **N1 · P1** 分割恢复会认领不属于本场的 TS | 清单还没有记录最终产物时，恢复依次试清单路径、计划路径、把计划扩展名改成 `.ts` 的路径。最后一个只要非空就可能被登记，随后程序删除该片范围内的原始分片。旧录像或中断写入的半份 TS 都可能满足这个条件。 | **运行复现**：清单只指定 `live.flv`，同目录预放 14 字节的 `live.ts` 与 752 字节本场分片。恢复返回 1 份、14 字节，数据库指向旧 TS，原分片和清单均消失。应记录本次实际生成的产物及完成状态；来源或完整性无法确认时保留原分片。回归须同时断言旧文件内容、分片及索引。[产物选择](../src-tauri/src/recorder.rs#L4056) · [删除范围分片](../src-tauri/src/recorder.rs#L4136) |

| **N4 · P2** 普通恢复写库失败仍计为已恢复 | 后处理结果写库失败仅记日志，函数仍返回文件路径、大小。调用方照常增加恢复数量，后台可广播媒体刷新，库中仍是旧登记。 | **运行复现**：用有效的 479,024 字节 TS，在 SQLite 的后处理状态更新上注入失败。返回恢复数 1、恢复字节 479,024，但库中大小为 0、后处理状态仍为 `recording`。应将登记失败向上传播，保留成品与重试依据，撤销故障后只登记一次。[写库错误与返回值](../src-tauri/src/recorder.rs#L3810) · [汇总](../src-tauri/src/recorder.rs#L4362) |
| **N5 · P2** 超过最近 200 条后，遗留录像进不了普通恢复 | 关单先将旧的活动会话改为 `aborted`；普通恢复只查询按开录时间排序的前 200 条失败或中止记录。较早开录的长场次或此前一直待恢复的会话，都可能被较新的失败记录挤出。没有待处理游标推进到下一页。 | **运行复现**：给仍有分片的会话加入 200 条开录时间更晚的中止记录，关单后实际查询返回 200 条，目标会话缺席。应按待恢复状态持久化工作，或分批遍历到底；回归要求保留策略关闭时第 201 条也能收尾。[关单](../src-tauri/src/db.rs#L366) · [恢复查询](../src-tauri/src/db.rs#L1641) |
| **N6 · P2** 媒体卡片把后处理重试发给另一片 | 整场卡片用首片段的失败状态显示重试按钮，点击时却传入首个有主文件的片段。第一段主文件缺失、后处理失败，第二段完好时，后端收到第二段 ID 并以“只有失败或已取消的后处理才能重试”拒绝。 | **前端逻辑夹具**：执行当前 TSX 的分组、状态与目标选择表达式，失败项为 `c0`、按钮显示，实际目标为 `c1`。重试应绑定显示错误的同一会话。用首段源封装仍在、次段完好的两片场次验收，点击后只应重试首段。[按钮](../src/features/media/RoomRecordingsPage.tsx#L992) · [后端判据](../src-tauri/src/commands.rs#L1589) |

## 四、复测与放行条件

1. **先修两条分片丢失路径及缺 PID 标记的关单路径。** 用本报告 N1、N2 和 PID 三组夹具在 Windows 与 macOS 各跑两次恢复，同时核对原始分片、成品内容、媒体索引、清单和写入进程状态。三项关闭前，现有候选只宜作内部验证。
2. **随后验收文件归属、登记和用户可见结果。** N3 预置同名文件作哨兵；N4 注入并撤销 SQLite 写入失败；N5 布置超过 200 条记录；N6、N7 在媒体页点重试并翻页。203 号的弹幕恢复和整房合并按上表独立回归。
3. **对外发布 Mac 版时验证最终要分发的 DMG。** 对内含 app 运行严格签名与系统评估，核对公证、stapling，另在具备下载隔离标记的干净用户环境执行首开、覆盖升级并核对旧库。记录通过验收的最终包哈希。
