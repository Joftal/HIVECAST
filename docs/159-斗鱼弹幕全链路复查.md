# 159 斗鱼弹幕全链路复查与修复

> 复查日期：2026-11-14
> 测试直播间：https://www.douyu.com/138243 （洞主丨歌神洞庭湖）
> 结论：主链路可用；本轮修复 5 个真实缺陷（颜色索引、刷屏 flush 饥饿、无 idle 检测、ASS 字体硬编码、合并缺段错位），补齐 spbc / 酬勤 / ssd / 礼物无名兜底。Cookie 不参与弹幕鉴权，匿名与登录拿到的是同一条公开流。

## 1. 结论先行

| 问题 | 结论 |
| --- | --- |
| 有 Cookie 是否优先用 Cookie 拿弹幕 | 协议上没有登录入口。带完整 Cookie 与不带 Cookie 同时各连 60 秒，均 807 条、11 种类型、`loginres.userid=0`，差异只有 sid。应用保持匿名是正确行为，不是漏用 Cookie |
| 匿名与登录弹幕数量是否不同 | 实测完全相同；Cookie 不影响弹幕流 |
| 弹幕是否完整落盘 | 397 秒整场 1688 条、0 坏行；分段 5 段合计 852 条与母带一致；6 源合并 2540 = 1688 + 852 |
| 颜色是否正确 | 修复前把调色板索引当 RGB，`col=2` 变 `#000002`；现按斗鱼网页 computed style 映射 |
| 字体 | ASS 不再硬编码 PingFang SC，按平台选字体 |
| 刷屏会不会不落盘 | 修复前 200ms flush 每来一条消息就重置，持续刷屏可能长期不 flush；现固定 interval |
| 连接假死 | 新增 90 秒无数据主动重连 |
| 分段 | 每个片段独立 `.jsonl` + `.ass`，时间轴归零，条数与 DB `danmaku_count` 一致 |
| 合并 | 合并弹幕按各段时长累加偏移；缺视频的片段不再推进偏移 |

## 2. Cookie / 匿名

### 2.1 探测方法

同一时刻、同一房间，用 Node 24 + ws 建两条 `wss://danmuproxy.douyu.com:8501/`：

- A：不带 Cookie，发匿名 `loginreq/roomid@=138243/` + `joingroup/rid@=138243/gid@=-9999/`；
- B：握手带数据库里完整斗鱼 Cookie（1767 字符，`acf_uid`、`acf_auth`、`acf_ltkid` 等），登录包与 A 完全相同。

结果：

| 指标 | 匿名 | 带 Cookie |
| --- | --- | --- |
| 60 秒消息总数 | 807 | 807 |
| 类型数 | 11 | 11 |
| `loginres.userid` | 0 | 0 |
| `loginres.username` | 空 | 空 |
| sid | 70424 | 70421 |

类型计数：`uenter 563`、`chatmsg 173`、`dgb 40`、`oni 12`、`actFishing 5`、`spbc 2`、`dream_bus_session 2`、`defense_tower_session 2`、`star_route_session 2`、`anchor_rank2505_change 1`、`ranklist 1`、`upgrade 1`、`loginres/pingreq/mrkl` 各 1。

### 2.2 判断

斗鱼弹幕 WS 是公开房间流，鉴权只到“能进这个房间”，没有用户级登录包；服务端忽略握手 Cookie。因此：

- 不需要为了弹幕额外注入 Cookie；
- 也不存在“登录能多拿一些弹幕”的隐藏通道；
- 录制/观看的画质仍需要 Cookie，这与弹幕是两条独立链路。

## 3. 获取与解析

入口：`danmaku.rs` 的 `run_douyu_room` → `douyu_once` → `douyu_connect`（8501..8507，native-tls）。

- 帧格式：`[len u32 LE][len u32 LE][0x02B1 u16 LE][0,0][payload][0]`；`douyu_drain` 仅接受完整帧，帧头非法直接清空缓冲。
- 字段：`@S` → `/`，`@A` → `@`，再按 `/` 与 `@=` 拆分。

### 3.1 事件映射

| type | 处理 | kind | user | content | 颜色 |
| --- | --- | --- | --- | --- | --- |
| `chatmsg` | 是 | chat | `nn` | `txt` | `col` 调色板 |
| `dgb` | 是 | gift | `nn` | `gfn x gfcnt` | `0xFFC85C` |
| `spbc` | 本轮新增 | gift | `sn` | `gn x gc` | `0xFFC85C` |
| `bc_buy_deserve` | 本轮新增 | gift | `sui.nn` | `酬勤 Lv{lev} x{cnt}` | `0xFFC85C` |
| `ssd` | 本轮新增 | super_chat | `sn` | `content` | `0xFF8A00` |
| `uenter` / `oni` / `ranklist` / `upgrade` / 活动 session | 忽略 | — | — | — | — |

说明：

- `uenter` 是进房提示，不是聊天弹幕；忽略是产品语义，不是丢数据。录制统计会把它计入 `ignored`。
- `dgb` 缺 `gfn` 时回退「礼物 {gfid}」，再缺回退「礼物」，不再整条丢弃。
- 斗鱼连击礼物会下发多条 `dgb`，当前逐条记录，不按 `hits` 合并；这与平台下发条数一致。
- `spbc` 是大礼物广播，部分场景可能与 `dgb` 描述同一次赠送；当前两条都保留，存在重复计数可能，尚未做跨事件去重。

### 3.2 颜色

`col` 是调色板索引，不是 24 位 RGB。用斗鱼网页真实 DOM 的 `getComputedStyle` 取值：

| col | 颜色 |
| --- | --- |
| 0 | `#FF314E` |
| 1 | `#4A94EF` |
| 2 | `#70C150` |
| 3 | `#D4A113` |
| 4 | `#8A5BE9` |
| 5 | `#E04AC0` |
| 6 / 缺省 | `#333333` |
| 7..15 | 白色 |

修复前 `col=2` → `#000002`，`col=5` → `#000005`，在深色画面上几乎不可见。现在 397 秒样本的颜色分布全部落在上表与礼物金色、白色内。

## 4. 写入与落盘

- 每行：`{"t":offset_ms,"k":kind,"u":user,"c":content,"col":color}`。
- `accept` 先 `fan_out` 写盘，再做 UI 每秒 200 条限流；录制文件不受 UI 限流丢弃。
- `RecordWriter` 每 50 条或 1 秒 flush；写失败计数并 WARN；0 条结束时删除空文件。
- 落盘路径与视频同名 `.jsonl`；只有 writer 创建成功才写 DB `danmaku_path`。

### 4.1 刷屏 flush 饥饿（已修）

旧实现：

```rust
_ = tokio::time::sleep(BATCH_WINDOW) => flush(...)
```

每来一条消息都会取消并重建 200ms sleep，持续刷屏时 flush 可能长期不执行。现改为固定 `interval(200ms)`，与 B 站分支一致。

### 4.2 连接假死（已修）

新增 `idle_check` 每 15 秒检查，90 秒没有任何 Binary/Text 就返回错误，外层按 1s→30s 退避重连。此前 TCP 半开会让录制一直“有弹幕连接但没数据”。

### 4.3 连接统计（新增）

每 60 秒 INFO：

```
斗鱼弹幕连接统计 room=138243 frames=687 parsed=139 ignored=548 batches=... dropped=0
```

真机样：`frames=687 parsed=139 ignored=548`，下一分钟 `frames=1417 parsed=324 ignored=1093`，可直接判断“连上了但没弹幕”是平台没发还是解析失败。

## 5. 分段

- 整场只写一条母带 JSONL；停录切片时，按每个 clip 的 `[start,end)` 调 `postprocess::slice_danmaku`。
- 每个片段生成同名 `.jsonl`，`t` 减去片段起点归零；第一段原地覆盖母带，最后删除母带与临时文件。
- 每段独立导出 `.ass`。

真机（`split_max_duration_sec=60`，总 293 秒）：

| 片段 | 时长 | DB 条数 | JSONL 最大 t | ASS 行数 |
| --- | --- | --- | --- | --- |
| 首段 | 60000 | 188 | 59005 | 188 |
| clip01 | 60000 | 166 | 57691 | 166 |
| clip02 | 60000 | 106 | 59810 | 106 |
| clip03 | 60000 | 244 | 59380 | 244 |
| clip04 | 53000 | 148 | 54289 | 148 |
| 合计 | 293000 | 852 | — | 852 |

母带 JSONL 也是 852 行，说明切片前后总数一致。

## 6. 合并

- 素材：`commands.rs` 的 `MergePlan` 先排序，再过滤掉 `file_path` 不存在的片段，然后用同一批文件生成 `files`、`danmaku`、`total_ms`、`room_id`。
- 弹幕：`postprocess::merge_danmaku` 逐段读 JSONL，`t + offset` 写入合并视频同名 JSONL；每段结束 `offset += duration_ms`。
- 登记：`register_merged_session` 写 `reason=merge`、`danmaku_path`、`danmaku_count`，媒体库可直接当弹幕轨播放。

修复前：`danmaku_sources` 包含没有视频文件的 session，而 `merge_files_in_order` 会过滤缺失视频，导致后续弹幕整体偏移。现在两者都来自 `MergePlan`。

真机：6 个 session → `合并-20261114-233925.mp4` 427,963,512 B、690 秒；合并弹幕 2540 条，`min t=949`、`max t=691289`，kinds `{gift:519,chat:2021}`；ASS 2540 行。

## 7. 渲染与字体

- 媒体库详情 → 内置播放器：`media_danmaku` 逐行解析，按 `t` 排序；`DanmakuCanvas` 用 lowerBound + 单调游标回放，seek 或前跳 >2.5s 清队列。
- 聊天横向滚动；`gift` / `super_chat` 固定顶部 5 秒；非 chat 显示「user：content」。
- 渲染层每帧最多 perFrame 条，轨道满回队首，队列超上限丢最旧；这是显示层丢弃，不影响 JSONL。
- 字体：Canvas 用 PingFang SC / Microsoft YaHei / system-ui；ASS 用 `danmaku_font()`（Windows 分支为静态选择，本轮未在 Windows 真机验证）：
  - macOS `PingFang SC`
  - Windows `Microsoft YaHei`
  - 其他 `Noto Sans CJK SC`

## 8. 会不会丢 / 漏 / 跳过

### 8.1 已覆盖

- 分片边界：`slice_danmaku` 左闭右开，片段总条数等于母带条数。
- 合并缺段：`MergePlan` 过滤无视频片段，不再错位。
- 坏行：读 JSONL 时跳过，不阻塞整场。
- 写失败：计数 + WARN，不静默。
- 空场：0 条删除空文件，DB 不写空轨。

### 8.2 仍可能丢的窗口

1. **断线重连间隙**：斗鱼没有历史回补，退避 1s→30s 期间平台下发的弹幕会永久缺失。当前靠 90 秒 idle 尽快发现半开连接，但无法补齐。
2. **进程崩溃**：内存里最多 200ms 的 batch 未 flush 会丢；正常停录会 flush。
3. **未知 type**：平台新增事件类型会被忽略；本轮已补 `spbc`、`bc_buy_deserve`、`ssd`。
4. **连击礼物**：逐条记录，不做 `hits` 合并；如果期望“一条连击只算一次”，需要在产品层再聚合。
5. **礼物重复**：`spbc` 与 `dgb` 可能同时出现，当前不去重，统计礼物数量时可能偏高。
6. **关注/贵族等非弹幕事件**：按设计不写入弹幕轨。

### 8.3 与平台是否“完全一样”

不是逐字节镜像。应用做了语义归一：

- `chatmsg` 只保留文本、昵称、颜色、相对时间；
- 礼物把 `gfn/gfcnt` 拼成可读文本；
- 非弹幕事件不落盘；
- 相对时间以连接建立为 0 点。

在“聊天 + 礼物 + SC/酬勤”这个产品口径下，条数与平台下发一致；原始字段未全量保留。
