# 抖音与斗鱼弹幕/礼物全链路复查

- 日期：2026-11-16
- 范围：抖音、斗鱼弹幕连接与鉴权、帧解析、JSONL 落盘、ASS/Canvas 渲染、分段与合并、重复/遗漏、Cookie 与匿名差异；同时回归 B 站。
- 结论：三个平台的「连接 → 解析 → 落盘 → 渲染 → 分段/合并」主链路均可用；本轮修复 6 个会直接影响数据正确性的缺陷，另有 1 个斗鱼礼物去重加固在收尾构建中。

## 1. 链路与鉴权结论

| 平台 | 连接 | Cookie 是否参与弹幕 | 结论 |
| --- | --- | --- | --- |
| 哔哩哔哩 | WSS + token | 是，登录态优先取 token | 登录态事件量显著高于匿名；本轮回归正常 |
| 斗鱼 | WSS + loginreq/joingroup | 否，Cookie 只进握手 | 带 Cookie 与匿名同流同量，服务端 `loginres.userid="0"` |
| 抖音 | WSS + protobuf PushFrame | 是，登录态带完整 Cookie | 登录态 `authed=true`、77 个 Cookie 名；匿名用 ttwid 也能收 |

斗鱼双 WS 探针（25 秒、同一房间、一条带 DB Cookie、一条匿名）：

- 统计完全一致：`loginres 1 / pingreq 1 / uenter 61 / chatmsg 45 / oni 5 / oun 5 / actFishing 2 / dgb 2 / spbc 3`；
- 聊天 45 条对 45 条、礼物 5 条对 5 条，前三条聊天内容逐字一致；
- 结论：**斗鱼弹幕协议不接受 Cookie 登录**，Cookie 不影响弹幕内容或数量；客户端仍优先带 Cookie 握手，连接失败自动回退匿名。

B 站则相反：登录态 `使用登录态获取弹幕 token` → `弹幕认证回复 code=0`；匿名路径只作为兜底。此前实测登录 285 事件/67 弹幕，匿名 24–55 事件/2–10 弹幕（docs/147 §17）。

抖音：登录态 `抖音弹幕连接建立 ... authed=true`，Cookie 名包含 `sessionid/sessionid_ss/ttwid`；匿名态只用 `ttwid`，`authed=false`，同样能收到聊天与礼物。

## 2. 本轮修复

### 2.1 抖音昵称/礼物字段解析错误

`/Library/dshproject/HIVECAST/src-tauri/src/douyin_ws.rs`

- `decode_chat`：User 字段改为 1=user_id、2=short_id、3=nickname；昵称空时依次回退 short_id、user_id、`未知用户`。
- `decode_gift`：User 同样取 1/2/3；GiftMessage 顶层 2=giftId、5=repeatCount、7=User、15=Gift；Gift 内 5=id、16=name；礼物名空时回退 `礼物 #{gift_id}`、`礼物`，不再丢弃整条。
- 新增 4 个单测，覆盖昵称/礼物名缺失。

修复前抖音礼物显示为数字 shortId；修复后真机 JSONL 为：

```json
{"c":"赠送 点亮粉丝团 × 1","col":16756775,"k":"gift","t":89839,"u":"②柒"}
```

### 2.2 斗鱼/抖音 batch 在退出路径丢失

`/Library/dshproject/HIVECAST/src-tauri/src/danmaku.rs`

- `run_douyu_room`、`run_douyin_room` 的 `batch` 从 `douyu_once/douyin_session` 内部提到循环外；
- 任何读取循环退出（重连、断流、关播）都先 `flush`，再进入退避；
- 修复前，最后不足 200ms 的一批消息会在重连时被丢掉。

### 2.3 斗鱼颜色/礼物/上舰字段兜底

- `douyu_color`：调色板索引 6 原映射为深灰（在黑底不可见），改为白色；
- `spbc` 礼物名：`gn` → `gfn` → `礼物 {gfid}` → `礼物`；
- `ssd` 发送者：`sn` → `nn`；
- 修复后斗鱼礼物在 JSONL、ASS、实时 Canvas 都能看到名称与发送者。

### 2.4 ASS 礼物/SC/上舰补发送者

`/Library/dshproject/HIVECAST/src-tauri/src/postprocess.rs` 的 `danmaku_to_ass`：

- chat 保持纯正文；
- gift/super_chat/guard 若 `u` 非空，文本前加 `{user}：`；
- 与实时 Canvas 的 `user：content` 展示一致。

真机 ASS 示例：

```text
Dialogue: ...{\an8\pos(640,20)\c&H005CC8FF&}熏黄指尖：粉丝荧光棒 x120
```

### 2.5 分割最后一段弹幕越界

`/Library/dshproject/HIVECAST/src-tauri/src/recorder.rs` 约 :2621：

- 最后一段不再 `end=None`，统一用 `clip.ended_at*1000 - recording_started_ms - writer_shift` 封口；
- 此前最后一段会把停止后仍到达的弹幕全写进去，出现 `t=87314 / 视频 46s`、`t=12331 / 视频 12s`；
- 修复后真机最后段：斗鱼 12s 视频 t≤11489ms，B 站 25s 视频 t≤21072ms，均在时长内。

单场不分割的尾部越界已在 2.7 单独修复；此前只有分割路径会在收尾时按结束时刻裁剪。

### 2.6 抖音控制帧被误当 gzip

`/Library/dshproject/HIVECAST/src-tauri/src/douyin_ws.rs` 的 `decode_push_frame`：

- 解析 PushFrame 字段 7 `payload_type`；
- payload 为空直接忽略；
- `payload_type` 为 `hb/ack/close/closeRoom` 直接忽略；
- 只有 `payload.starts_with([0x1f,0x8b])` 才走 GzDecoder，其余按明文 Response 解析；
- 新增 `ignores_uncompressed_control_frame_without_gzip_error` 单测。

修复前日志会出现 `gzip 解压失败：invalid gzip header`；新 bundle 连续连接抖音 12 分钟、950 帧，`gzip 解压失败` 计数为 0。

### 2.7 单场不分割收尾尾部越界

`/Library/dshproject/HIVECAST/src-tauri/src/recorder.rs:2322` 起，弹幕 writer 改为在 **ffmpeg 退出后、`finish_range` 合并分片之前** 摘掉；此前它在合并完成后才 `detach_record`。

问题链路：

1. 收到停止请求，ffmpeg 退出，视频时长到此为止；
2. `finish_range` 把 `.partNNNN.ts` 合成母带，2GB / 77 片实测耗时 **12,056 ms**；
3. 旧代码在合并完成后才摘 writer，合并期间到达的弹幕继续以超过视频时长的 `t` 写入 JSONL；
4. 单场不分割不走 `rendered.len() > 1` 的切片分支，尾部直接入库；媒体库计数、ASS 和合并偏移都会带上这些事件。

修复后 writer 在合并前已 `finish`，晚到事件被丢弃；新增 `finished_writer_drops_events_that_arrive_after_stop` 单测锁定 `finish` 后 `push` 不再写入。

剩余边界：ffmpeg 自身优雅退出前、最后几帧到进程结束之间的窗口仍可能有极少量事件，量级已从「合并耗时（十几秒）」降到「进程退出窗口（通常亚秒级）」。

### 2.8 斗鱼重复礼物去重加固（收尾）

原实现只记「上一条礼物」，两条重复帧中间夹了别人的礼物就会漏掉。改为 `HashMap<key, offset_ms>`：

- key = `发送者长度:发送者:内容`；
- 同 key 1 秒内直接丢弃；
- 每次保留 5 秒内的键，避免 map 无限增长；
- 单测新增「中间夹了别人的礼物仍去重」。

此前 97 个斗鱼片段里有 1656 条片段内重复（绝大多数是 `粉丝荧光棒 x1/x10` 等连发礼物），属于该缺陷。

新 bundle 真机复验：斗鱼 yyfyyf 连续录制 12 分钟、12 个弹幕文件（主文件 + 11 个分段）、743 条事件，逐片段与跨片段「同发送者 + 同内容 + 同秒」组合均为 **0**，`dup1s=0`；说明 1 秒窗口去重生效。

## 4. 读取、渲染与字体

- JSONL：`{t,k,u,c,col}`，t 为 writer 启动后毫秒；每 50 条或 1 秒 flush；写失败 warn 并计数。
- **读取口径**：媒体库回放不读 ASS；`media_danmaku` 逐行读 JSONL，跳过空行/坏行/空内容，按 `t` 升序返回 `offsetMs/kind/user/content/color`，前端按视频进度用 `lowerBound` 取窗口。ASS 只用于导出给外部播放器。
- ASS：`PlayResX 1280 / PlayResY 720`，字体 macOS `PingFang SC`、Windows `Microsoft YaHei`、Linux `Noto Sans CJK SC`；chat 用 `\move` 滚动，gift/SC/guard 用 `\an8\pos(640,y)` 顶部公告停留 5 秒；`{`/`}`/`\` 会转全角，避免文本注入 ASS 指令。
- ASS 颜色：`0` 与 `0xFFFFFF` 都按白色处理，其余转 BGR；单测覆盖 `0xFF0000 → &H000000FF&`。
- Canvas：chat 只显示正文，非 chat 显示 `user：content`；字体族 sans/serif/kai 带 macOS/Windows 回退，颜色 `0` 显式按白色，避免黑字消失；有 160 条上限与超长文本丢弃，只影响实时浮层，不影响 JSONL/ASS。
- 单测证据：`writes_ass_for_sample_danmaku` 断言起始时间、颜色、注入转义、礼物 `an8` 与发送者、SC/舰长不丢，并断言 ASS 声明当前平台字体；`merges_danmaku_with_cumulative_offsets` 断言缺段仍推进 1000ms（第三段 50ms → 2050ms）；`merged_session_registers_danmaku_and_media_track` 断言合并登记后媒体库能拿到弹幕轨、计数 3。

## 5. 已知边界

1. 斗鱼礼物去重的 1 秒窗口是启发式：用户真的在 1 秒内连点两次同礼物会被合并；超过 1 秒的重复帧仍保留。
2. 单场不分割录像的尾部已在 2.7 修复：writer 在分片合并前摘掉；仅剩 ffmpeg 自身退出前的亚秒级窗口。
3. 抖音只把 `WebcastChatMessage` 与 `WebcastGiftMessage` 转事件，成员进出、点赞、榜单等按设计忽略；房间没人说话时 JSONL 为 0 行是正常的。
4. 跨片段逐字相同的聊天可能是用户真实重发（B 站实测 2 条），不能一律当重复删除。
5. 合并录像的弹幕偏移按各段视频时长累加；缺 JSONL 的段仍推进偏移，不会把后段弹幕提前。
