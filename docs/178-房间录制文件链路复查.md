# 178 房间录制文件链路复查

> 日期：2026-11-19  
> 范围：下线媒体库后的房间「录制文件」页、监控入口、已移除直播间、分页/筛选/删除与缩略图  
> 结论：信息架构方向成立；本轮修掉 7 个会让页面“看起来不对”的具体问题，其中缩略图被 CSP 全量拦截是影响最大的一个。后端数据结构未改。

## 1. 复查方法

- 逐行读 `src/App.tsx`、`src/features/media/RoomRecordingsPage.tsx`、`src/features/monitor/MonitorPage.tsx`、`src-tauri/src/db.rs`、`src-tauri/src/commands.rs`。
- 用 release bundle 真机走：进入/返回、切 tab、搜索、时间筛选、空态、无匹配、分页、回放、录制中点击、已移除入口。
- 分页用临时 61 条 session 验证，验证后删除，不污染最终数据。

## 2. 页面结构结论

`RoomRecordingsPage` 只做三件事：

1. 按 `roomId` 查当前房间的 `record_session`，支持标题/主播搜索、时间范围、仅看弹幕、排序。
2. 按 `group_id || id` 把同一场的分段聚成一张卡片；卡片时长、大小、弹幕数取整组之和，播放取第一个仍有文件的片段。
3. 打开回放抽屉：本地 HLS、弹幕轨、主文件/源封装切换、转 MP4、导出 ASS、定位、删除。

入口仍有三处：监控行尾 `...`、直播间详情「录制文件」、已移除弹窗「录制文件」。顶栏没有媒体库 Tab。

## 3. 本轮修复

### 3.1 进入录制文件后，点顶栏「监控」没有反应

- 现象：已在房间录制文件页时，点顶栏「监控」不会回到监控列表；从观看页切回监控还会停在旧录像页。
- 原因：`requestTab` 在 `next === tab` 时直接 return，且 `tab === "monitor"` 时没有清 `roomFiles`。
- 修复：`src/App.tsx:103-127` 先处理：

```
if (next === tab) {
  if (next === "monitor" && roomFiles) setRoomFiles(null);
  return;
}
if (tab === "monitor" && roomFiles) setRoomFiles(null);
```

依赖数组补 `roomFiles`。现在顶栏「监控」始终回到列表根级。

### 3.2 切换房间时可能沿用上一房间的列表和回放

- 现象：路由只保存一个 `roomFiles`，正常路径下不会同时开两个房间；但从已移除弹窗连续切换房间时，React 会复用同一组件实例。
- 修复：`src/App.tsx:496-500` 给页面加 `key={roomFiles.id}`，房间变化强制重挂，items / playing / 筛选状态全部重置。

### 3.3 分页 offset 错位，可能跳过或重复片段

- 现象：分页按片段返回，一场直播可能第一页只出现一部分。点卡片「+N」会把后续片段补进 items；原实现用 `items.length` 当下一页 offset，补进来的片段会被重复计数，导致跳过真实数据或重复行。
- 修复：`RoomRecordingsPage.tsx:187` 增加独立的 `loadedRows`，只记录后端实际返回过的行数：

```
setLoadedRows((prev) => (offset > 0 ? prev + page.items.length : page.items.length));
```

`loadFiles(offset > 0)` 的追加改为按 id 的 Map 去重，再不依赖 `items.length`。加载更多按钮条件改为 `loadedRows < total`（`RoomRecordingsPage.tsx:1001-1003`）。

### 3.4 快速切筛选时，旧请求覆盖新结果

- 现象：搜索/时间/仅看弹幕/排序每次变化都会发请求；慢的旧请求晚返回时会把新结果覆盖。
- 修复：`loadSeq` 请求序号（`RoomRecordingsPage.tsx:223/288/301`），旧请求返回直接丢弃；`finally` 也只在最新序号时清 loading。

### 3.5 整场删除部分失败后，列表残留已删除片段

- 现象：`media_delete_group` 逐片段删文件；某个片段失败会保留该行，但前面的片段已经删掉了。失败时只弹错误、不刷新，页面会继续显示过期卡片。
- 修复：`removeOne` 的 catch 里 `await refreshAll()`，失败也重新拉列表；成功路径原本就刷新。

### 3.6 缩略图被 CSP 全量拦截（影响最大）

- 现象：缓存目录里明明有 `59dfd276-....jpg`，卡片仍显示灰色「缩略图生成中」。
- 根因：缩略图不是 asset 协议，而是回环服务：

```
http://127.0.0.1:{port}/s/{token}/thumbs/{session}.jpg
```

`src-tauri/src/stream/server.rs:75-83` 明确用 127.0.0.1。但 `src-tauri/tauri.conf.json:28` 的 `img-src` 只有 `'self' data: blob: https:`，没有 loopback；`media-src` 反而允许 127.0.0.1。浏览器按 CSP 直接拒绝图片。
- 修复：`img-src` 增加 `http://127.0.0.1:* http://localhost:*`，与 `media-src` 对齐。
- 真机对比：修复前 Asaki 卡片灰底；修复后同一张卡片显示 3×3 九宫格封面（生成器本来就是九宫格，不是单帧）。

### 3.7 文案与后端能力不一致

- 搜索框原写「搜索标题或文件名」，但 `db.rs media_where` 只查 `r.title` / `r.host_name`，不查文件名。改为「搜索标题或主播」。
- 空态原写「媒体库还是空的 / 在主播监控里添加直播间」，此页是单房间，改为「这个直播间还没有录像 / 开播并录制后，录像会出现在这里」。
- 无匹配原提示切平台筛选，但此页没有平台筛选；改为「换个关键词，或把时间范围切回『全部时间』」。
- 刷新成功/toast/加载失败同步改为「录制文件」口径。

## 7. 边界与已知限制

- 已移除弹窗的场次/体积来自 `record_session` 记录，不是磁盘扫描；文件被手动删掉但 DB 行还在时，仍会计入历史，卡片进页后显示「文件已缺失」。
- 恢复已移除房间时若 `auto_record=1` 且正在直播，会立刻自动开录；这是沿用原设置，不是本次改造引入。
- 从已移除弹窗进入录制文件再返回监控，弹窗不会自动重开；底部「已移除 N」仍可再进。属可接受路径，未改。
- `delete_file=false` 只删 DB 行，不删弹幕/伴随文件；按场次删文件才会清这些。
- 多片段场次的封面现在取「第一个有缩略图的片段」；如果所有片段都还没生成，仍显示占位，生成事件到达后会逐张替换。
- 分页 61 条验证数据已从 DB 删除；测试房间与录像在收尾时清空。
