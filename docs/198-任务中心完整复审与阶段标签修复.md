# 198 任务中心完整复审与阶段标签修复

## 结论

任务中心四段链路（录制 → 收尾 → 后处理 → 入库）本轮完成代码复审、真机录制、详情时间线、跨 Run 检索和周边入口验收。任务中心主流程可用。复审分两阶段：第一阶段修复 4 类确认问题；第二阶段把复审报告里列出的 5 项任务中心残留全部修掉。

1. **阶段事件被保留策略误删**：收尾时写入的 `phase:*` 事件没有对应的 `task_history` 行，被孤儿事件清理当成垃圾删除，详情时间线只剩收尾阶段。现在清理 SQL 明确排除 `phase:%`。
2. **跨 Run 检索无法按界面中文阶段名命中**：数据库存 `record`/`running`，界面显示「录制」/「运行中」，检索却只匹配内部值。现在用共享标签映射生成 SQL `IN (...)`，内部值、中文标签和英文标签都能命中。
3. **部分阶段显示「未知阶段」**：后处理实际会发出 `preparing`/`converting`/`validating`/`committing`，前端和检索映射都缺这几项。现已补齐中英文文案。
4. **B 站过期凭据仍尝试登录态弹幕**：过期 Cookie 能换到弹幕 token，但 WS 认证后被服务端重置，形成每 30 秒重连循环。现在凭据状态不是 ok 时直接走匿名。

第二阶段修掉的 5 项残留：英文界面检索/CSV 仍是中文、平台筛选隐藏无房间独立 Run、检索全表 `LIKE`、历史行只能 Enter 不能空格、时间线只保留 200 条窗口。具体见「第二阶段修复」一节。

任务中心本身可以进入验收；**应用整体仍不建议正式上线**。仓库中未提交的 `docs/196-上线前代码审查报告.md` 列出 7 项 P1（Windows 后处理产物被删、分片误匹配、百分号标题漏录、清理失败仍删索引、同名产物误认领、整场合并只提交当前页、扫码参数进日志），这些问题不属于任务中心本轮改动，但属于发布阻塞项，详见该报告。

## 第一阶段修复（阶段事件与标签）

### 1. 阶段事件不再被当成孤儿删除

`db::prune_task_data` 原逻辑删除所有 `task_id NOT IN (SELECT id FROM task_history)` 的事件。任务中心用 `jobs::emit_session` 写录制/缩略图阶段事件时，`task_id` 是 `phase:<kind>:<session>`，按设计只挂 `run_id`、不写 `task_history`；收尾一执行保留策略，刚写入的事件就被删掉。

修复位置：`src-tauri/src/db.rs:1966`，删除条件增加 `AND task_id NOT LIKE 'phase:%'`（`db.rs:2015`）。新增单测 `keeps_phase_events_while_pruning_orphan_events`，同时验证普通孤儿事件仍会被清理。

真机复验：B 站 545068 于 04:15–04:22 录制 423 秒，生成 18 条 `task_event`，收尾后 `phase:record`、`phase:thumbnail` 的 running/done 均保留；详情抽屉显示「录制中 运行中」「录制中 完成」「合并 5%」等 15 条，不再是只有收尾事件。

### 2. 跨 Run 检索支持界面中英文标签

新增 `src-tauri/src/labels.rs`，集中维护 `STAGE_LABELS`/`STAGE_LABELS_EN` 与 `STATE_LABELS`/`STATE_LABELS_EN`，提供：

- `stage_label_for`/`state_label_for`：按语言返回展示名，未知内部值原样返回；
- `matching_stages`/`matching_states`：把用户输入（内部值、中文标签、英文标签，大小写不敏感）映射回内部枚举，供 SQL `IN (...)` 走索引。

`db::task_event_search`（`db.rs:1869`）不再对阶段/状态做 `CASE ... LIKE`，而是先用 `matching_*` 得到内部值，再生成常量 `e.stage IN (...)`/`e.state IN (...)`。输入「录制」「后处理」「运行中」「准备中」以及英文 `Cover`/`Post-processing`/`Running` 都能命中；原始值 `record`/`running` 也仍然可搜。`commands::csv_stage`/`csv_state`（`commands.rs:3172`）改为调用同一套映射，避免 CSV 和检索各维护一份文案。

单测 `labels_cover_both_languages`、`matching_maps_chinese_english_and_raw_values` 与 `task_event_search_matches_english_labels_and_short_chinese` 覆盖中英文标签、短中文查询、LIKE 通配符转义、平台筛选和房间关联。

### 3. 补齐未知阶段文案

`post.rs:296` 会发出 `preparing`，`postprocess.rs:155` 会发出 `converting`，`post.rs:664` 会发出 `validating`；旧前端 `STAGE_KEYS` 没有这些键，界面显示「未知阶段」。

现在 `src/features/tasks/TasksPage.tsx:60` 增加 `preparing`/`converting`/`validating`/`committing`，`src/i18n/zh-CN.json` 与 `en-US.json` 同步增加「准备中 / 转换中 / 校验中 / 入库中」及英文文案。`labels.rs` 也加入相同映射，检索中文可以命中。

真机复验：跨 Run 检索输入「准备中」返回 9 条，覆盖 B 站、抖音、虎牙；条目显示「准备中 · 运行中 2%」，不再出现「未知阶段」。

### 4. B 站过期凭据回退匿名

`danmaku::fetch_session` 原来只判断是否存在 Cookie，不看凭据状态。过期 Cookie 仍能通过 `getDanmuInfo` 换 token，但 WS 认证后服务端立即 reset，日志每 30 秒重复「弹幕 WS 已连接 → 连接中断」，且永不回退匿名。

现在先判断 `credential::is_ok("bilibili")`，过期时记录「B 站登录态已过期，弹幕使用匿名连接」并走匿名主接口。真机日志确认匿名连接后 `弹幕认证回复 code=0`，无重连循环，44 条弹幕正常写入 JSONL/ASS。顺带修复 `account.rs` 的 `rsa::RsaPrivateKey` 弃用告警。

## 第二阶段修复（5 项残留）

### 1. 英文界面检索与 CSV

- 检索：`matching_stages`/`matching_states` 同时匹配内部值、中文标签、英文标签；英文界面输入 `Cover`、`Post-processing`、`Running` 会先映射成 `thumbnail`/`postprocessing`/`running`，再走 `IN` 索引。
- CSV：`task_events_export` 新增 `lang: Option<String>`，前端 `EventSearchDialog` 传 `i18n.language`；阶段/状态用 `stage_label_for`/`state_label_for`，表头由 `csv_header` 按语言输出（英文 `Time,Platform,Room,Streamer,Title,Stage,State,Progress,Message,Task,Run`）。
- 单测：`labels_cover_both_languages`、`matching_maps_chinese_english_and_raw_values`、`csv_export_uses_readable_labels_and_blocks_formulas`、`task_event_search_matches_english_labels_and_short_chinese`。

### 2. 平台筛选不再隐藏无房间 Run

事件检索的平台条件从 `r.platform = ?` 改为 `(?4 = '' OR r.platform = ?4 OR r.platform IS NULL)`。合并、弹幕导出等独立 Run 没有房间，选择任一平台时仍然可见；有房间的事件仍按平台过滤。测试把原断言 2 条改为 3 条，并确认 `merge:x` 仍在结果里。

### 3. 检索从全表 LIKE 改为 FTS5 trigram

- 新表 `task_event_fts(body)`，`tokenize = 'trigram'`，`rowid` 复用 `task_event.id`；`task_event_fts_ai/ad/au` 三个触发器保证增删改同步。
- 老库首次启动由 `ensure_task_event_fts` 回填，`app_setting.db.task_event_fts_v1` 标记避免重复扫表；回填失败只告警，`Db.fts_ready` 置 false，检索退回 `message LIKE`，不会出现索引缺失导致 0 条结果。
- 查询长度 ≥3 且含字母/数字时用 FTS 短语匹配；1–2 字符仍用 `message LIKE`，但阶段/状态已由 `IN` 命中，房间名改走 `record_session`/`task_history` 小表子查询，避免 JOIN 后对 20 万事件全表 `LIKE`。
- 单测 `task_event_fts_backfills_old_events_once` 覆盖回填、标记幂等和 FTS 不可用时的 LIKE 回退；`task_event_search_joins_rooms_and_escapes_like_wildcards` 覆盖 `100%` 字面量与空查询。

### 4. 历史行键盘可打开

历史行原本已有 `tabIndex={0}` 和 Enter 处理；本轮补上空格键，并保持 `event.target === event.currentTarget`，避免在行内「详情」按钮上按空格时重复触发。Enter 和 Space 都会打开详情抽屉。

### 5. 时间线不再只保留 200 条窗口

- 删除 `TIMELINE_WINDOW`、`timelinePage`、`olderLoaded` 和「更早/较新」翻页按钮；首屏仍取最近 200 条，点「加载更早的事件」后把已取到的全部事件按时间正序展示。
- 加载更早前记录最上方事件的 `id`、`scrollTop`、`offsetTop`，插入后用 `useLayoutEffect` 恢复同一事件的视口位置；运行中 Run 同时从底部追加新事件也不会把视口带偏。
- 事件行加 `content-visibility: auto` 和 `contain-intrinsic-size: auto 44px`，只布局视口附近的行；底部显示「已加载 N 条」，不再显示「第 x–y 条」。
- 仍保留 `(at, id)` 游标分页和「加载更早」，事件不会一次性全部读入内存。

## 当前实现与逻辑

### 后端聚合

- `task_center::build` 先读房间、进行中的 `record_session`、任务历史与阶段事件，再按 `session:<id>` 或 `task:<id>` 聚合成 Run。
- 同一场直播的分片按 `group_id` 合成一个 Run，字节数、时长、结束时间取所有片段汇总；`clip_index` 最大的片段决定片段数。
- 四段链路由 `build_stages`（`task_center.rs:813`）生成：录制、收尾、后处理、入库。录制中断/失败、收尾失败、后处理失败分别落到对应阶段，不会因为后续阶段成功而掩盖前面的失败。
- 平台健康、异常、排队、历史四段由同一个快照返回；前端每 2 秒轮询一次。

### 异常与重试

- `incident_task`（`task_center.rs:1094`）的选择顺序是：post/remux 失败或中断 → merge 失败 → finalize 失败或中断。后处理失败优先给 `retry_post`，避免收尾失败遮蔽更可操作的后处理失败。
- 历史窗口先满足录像场次，再由 `cap_history_runs`（`task_center.rs:1065`）把剩余名额给合并、导出等独立任务。
- 排队中的 post/remux/merge 可以在 QueuedRow 或详情抽屉取消；取消标记由 `post::acquire` 在等槽位时检查，未拿到槽位也会退出。

### 历史与事件

- 历史首次 100 条，最多加载到 1000 条；表格使用虚拟列表，行高 56px；行支持 Enter/Space 打开详情。
- 详情时间线首次取最近 200 条，向上按 `(at, id)` 游标分页，每页 200 条；终态 Run 停止轮询，运行中 Run 只追加新事件。已加载的事件全部渲染，不再做 200 条滑动窗口；行使用 `content-visibility`，插入更早页时按最上方事件锚定滚动位置。
- 事件只在阶段/状态转换和 25% 里程节点写入，不按秒膨胀。`phase:*` 事件保留在 `task_event`，不写 `task_history`。
- 跨 Run 检索最多返回 50000 条，界面默认显示最近 200 条；阶段/状态先用中英文标签映射到内部枚举，消息等自由文本走 FTS5 trigram，短查询回退 `LIKE`。CSV 导出上限 50000 条，阶段/状态和表头跟随界面语言，并对 `= + - @` 开头的内容加前导单引号防公式注入。

### 保留策略

`retention.rs` 保留 180 天、最近 500 场、历史 20000 条、事件 200000 条；`prune_task_data` 清历史与事件时保留运行中的任务和 `phase:%` 事件。

## 仍需完善/未做

### 任务中心相关

- **1–2 字符查询仍走 LIKE**：FTS5 trigram 要求至少 3 个字符，输入「录」「合」「5」时只在 `message` 上 `LIKE`；阶段/状态/房间名仍有 `IN` 与索引子查询。短词在 20 万事件上限内可接受。
- **FTS 不覆盖房间名**：`task_event_fts` 只索引消息、阶段、状态、类型、任务号；主播/标题搜索改走 `record_session`/`task_history` 子查询，依赖这两张小表的索引，不参与 trigram 排序。
- **时间线全量渲染依赖已加载页数**：点多次「加载更早」后 DOM 会持续增长，`content-visibility` 只降低布局/绘制成本，未设硬上限；正常复盘几十页没有问题，但极端情况下仍需虚拟列表。
- **英文检索只映射标签，不翻译历史数据**：英文界面能搜 `Cover`/`Post-processing` 等阶段词，但历史消息里的中文主播名、标题仍按原文匹配；这是数据本身的限制，不做机器翻译。
- 事件检索一次最多 50000 条、CSV 导出 50000 条、历史最多 1000 条，均未做分页导出；超过上限会截断。
