## 2. 统一结构：一条连接、多个消费者

三个平台共用同一套骨架，新增平台只写「怎么连」和「怎么解」，不要碰落盘与广播。

- `run_room` 按 `conn.room.platform` 分派到 `run_bilibili_room` / `run_douyu_room` / `run_huya_room`。
- `supports(room)` 是唯一门控：`matches!(room.platform.as_str(), "bilibili" | "douyu" | "huya")`。监控循环与录制挂载都读它，未支持平台不建连接、不打 warn。
- `accept(conn, &mut window_start, &mut count, &mut batch, message)`：补 `offset_ms`，1 秒窗口内最多 `MAX_PER_SECOND = 200` 条，超了计数丢弃；够一批就塞进 `batch`。
- `flush(app, conn, &mut batch)`：`app.emit(EVENT_DANMAKU_BATCH, payload)`，事件名 `danmaku://batch`，同时 `writer.write` 落 JSONL。
- 每个连接循环里 `sleep(BATCH_WINDOW)`（200ms）触发 flush，避免一条一条 emit 把前端打爆。
- 断线重连统一退避：1s 起翻倍，上限 `RETRY_MAX = 30s`；被 `closed` 标志命中时退出并 `finish` 所有 writer。

## 3. 斗鱼弹幕

### 3.1 连接

- 地址：`wss://danmuproxy.douyu.com:8501` … `8506`（`DOUYU_PORTS = 8501..8507`），逐个端口尝试。
- 登录：`type@=loginreq/roomid@={房间号}/`，紧接 `type@=joingroup/rid@={房间号}/gid@=-9999/`。
- 心跳：每 45 秒发 `type@=mrkl/`，否则服务端会踢。

### 3.2 帧格式

```text
[len u32 LE][len u32 LE][0x02B1 u16 LE][0x00][0x00][payload][0x00]
len = 8 + payload.len() + 1
```

解析时 payload 切片是 `&buffer[12..len + 3]`。**这里踩过 off-by-N**：先写成 `[12..len - 1]`，尾部被截断，靠单测 `frame_round_trips_through_buffer` 才抓出来。
`len < 9` 或 `> 1MB` 视为流错位，直接清空读缓冲重新同步。

### 3.3 STT 解析

- payload 按 `/` 拆字段，每段 `split_once("@=")`；`douyu_unescape` 把 `@S` 还原成 `/`、`@A` 还原成 `@`（顺序不能反）。
- `chatmsg` → `kind: chat`，`nn` 是昵称，`txt` 是内容，`col` 解析成颜色（0 或解析失败给白色 `0xFFFFFF`）。
- `dgb` → `kind: gift`，内容拼成 `{gfn} x{gfcnt}`，颜色固定 `0xFFC85C`。
- 其它类型（`uenter` / `rss` / `ssd` 等）先忽略。

### 3.4 必须用 native-tls（最容易卡住的一步）

rustls 连斗鱼网关直接失败：

```text
wss://danmuproxy.douyu.com:8506/ → IO error: received fatal alert: HandshakeFailure
```

但 `openssl s_client` 与 `curl` 都能握手成功（TLSv1.2 / AES256-GCM-SHA384 / HTTP 101）。结论不是网络问题，是对方要求的密码套件 rustls 不提供。
解法：`tokio-tungstenite` 开 `native-tls` feature，连接时用 `Connector::NativeTls` + `connect_async_tls_with_config`（macOS 走 Security.framework，Windows 走 SChannel）；B 站仍用默认 rustls。

## 4. 虎牙弹幕

### 4.1 为什么需要 JCE

虎牙的 WS 不是文本协议，每条消息都是 TARS/JCE 编码的结构体。所以先写了 `jce.rs`。

字段头规则：

- 首字节 = `(tag << 4) | type`；`tag >= 15` 时首字节是 `0xF0 | type`，第二字节才是 tag。
- 类型：0 int8 / 1 int16 / 2 int32 / 3 int64 / 4 float / 5 double / 6 string(len u8) / 7 string(len u32) / 8 map / 9 list / 10 struct begin / 11 struct end / 12 zero（零值只写一个头字节）/ 13 simple list（bytes）。
- 整数按值域收窄：0 → zero，±127 → int8，±32767 → int16，i32 域 → int32，否则 int64。
- `bytes` = 头(13) + 元素类型头(0, int8) + 长度 + 原始字节；长度本身也是收窄整数，**解码端必须读头字节再按类型读**，不能假定 4 字节（这里踩过，见 §8）。

### 4.2 房间三元组

`https://m.huya.com/{room}` 用移动 UA 抓，抠 `lUid` / `lChannelId` / `lSubChannelId`。实测多数房间页面只有 `lUid`，缺失或 <=0 时一律回退成 `lUid`（和参考实现一致）。

### 4.3 注册与心跳

- `ws://ws.api.huya.com`（明文，不带 TLS）。
- 注册：`WebSocketCommand{iCmdType = 1, vData = WSUserInfo{lUid, bAnonymous = uid == 0, sGuid, sToken, lTid, lSid, lGroupId = uid, lGroupType = 3}}`。
- 心跳：每 60 秒一次，`WebSocketCommand{iCmdType = 3, vData = Wup 信封}`，信封里 `sServant = "onlineui"`、`sFuncName = "OnUserHeartBeat"`，`tReq` 是 `UserHeartBeatReq`。`UserId.sHuYaUA` 必须写 `webh5&1.0.0&websocket`。
- Wup 信封前缀 4 字节是**整个信封（前缀 + header）的总长度**，不是 header 长度。写成 header 长度会少 4，服务端照样回注册成功，但心跳不被认，表现是「连上了但一条弹幕都没有」。

上面两个包（注册、心跳）在单测里断言逐字节 hex，参考值由直接跑参考实现的 `lib.js` 生成，所以等价于「与官方实现逐字节一致」。

### 4.4 消息解析

命令 7（`EWSCmdS2C_MsgPushReq`）里再套一层 `WSPushMessage{iUri, sMsg}`，按 `iUri` 分派：

| iUri | 结构体 | 取什么 |
| --- | --- | --- |
| 1400 | `MessageNotice` | `tUserInfo.sNickName` + `sContent`，颜色取 `tBulletFormat.iFontColor` |
| 6501 | `SendItemSubBroadcastPacket` | `sSenderNick` + `sSendContent` + `iItemCount`，内容拼成「荧光棒 x3」 |
| 其它 | — | 7101–7114、8006 等是榜单/在线人数推送，先忽略（参考实现也只映射了 1400 与 6501） |

颜色是 `0xBBGGRR`，要转成前端用的 `0xRRGGBB`；`<= 0` 视为默认白色。

`sContent` trim 后为空直接丢弃——虎牙会推大量空内容的心跳型消息。

## 5. 落盘与前端

- JSONL 与录像同名，每行一条：`{"c":"内容","col":16777215,"k":"chat","t":703,"u":"昵称"}`；`t` 是相对开播的毫秒偏移。
- 前端订阅 `danmaku://batch`，按槽位开关渲染；斗鱼/虎牙与 B 站走同一条通路，没有平台分支。
- 契约没变：`DanmakuMessage { offset_ms, kind, user, content, color }`，新增平台只负责把协议翻译成它。

## 7. 已知缺口：抖音（当时记录，已由 [32](32-M7.3b-抖音弹幕.md) 补齐）

抖音弹幕没做，原因是签名链路比前两家重：

- 连接前要先拿 `wss://webcast*.douyin.com/webcast/im/push/v2/...` 的带签名地址，签名由 `webmssdk.js` 的 `get_sign` 生成（先用参数拼串 md5 成 `X-MS-STUB`，再喂进混淆过的 JS）。
- 消息体是 protobuf：`PushFrame` → gzip 解压 → `Response` → `Message` 列表，聊天是 `WebcastChatMessage`，礼物是 `WebcastGiftMessage`。需要手写最小 wire 解析或引入 `prost`。

两条可行路线（按代价排序）：

1. **内嵌 JS 运行时**（推荐）：引入 `rquickjs` 或 `boa`，把 `webmssdk.js` 原样打包进去只调 `get_sign`，签名与官方永远同步；protobuf 用 `prost` 生成结构体。代价：二进制体积 +5–8MB。
2. **换 HTTP 拉取接口**：`/webcast/im/fetch/` 复用项目里已有的 `abogus`（`src-tauri/src/platform/abogus.rs`）签名，长轮询拿 protobuf；代价：延迟比 WS 高，且 `abogus` 是否被该接口接受需要试。

其它小缺口：

- 礼物颜色目前是固定色（斗鱼 `0xFFC85C`、虎牙 `0xFFC85C`），没有按礼物等级分色。
- 虎牙只解析 1400 与 6501，榜单/贵族进场等未消费。
- 斗鱼匿名连接可能被限流，重连退避已做但没有做「换个端口重试」的显式记录。

## 8. 踩坑

1. **斗鱼 rustls 握手失败**：换 native-tls，别在端口和 DNS 上浪费时间。
2. **斗鱼帧切片 off-by-N**：`[12..len-1]` 截掉尾字节，靠单测抓出来。
3. **JCE 计数不能按 int32 读**：编码端会收窄，解码端必须先读头字节，否则 `simple list` 长度错位，表现为「解出来一堆垃圾字段」。
4. **Wup 前缀是总长度**：写成 header 长度会静默失败——注册成功、心跳无效、没有弹幕。
5. **虎牙 `tId` 是完整结构体**：`writeStruct` 会写 `0x0A` 开头和 `0x0B` 结尾，少写一个头字节整包就不匹配。
6. **`String.raw` 塞整段 Rust 会触发 TS 解析错误**：把代码拆成多段 `appendFileSync` 写临时文件再拼接，稳定得多。
