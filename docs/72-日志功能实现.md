# 72-日志功能实现

> 版本：v1.5（2026-11-07，移除单日上限，加固脱敏、字段转义与退出收尾）
> 对应评审：`70-日志设置与日志体系评审.md`
> 范围：日志目录、保留天数、文件滚动、全链路日志补齐与前端错误落盘。本文记录已落地实现，不再重复评审阶段的候选方案。

## 1. 落地结论

评审阶段的三个关键判断全部按原方案执行：

1. 默认目录使用平台标准日志目录，不写安装目录；开发构建写工程根目录 `logs/`。
2. 保留天数按自然日清理，只删自家文件名；默认 7 天（含今天），0 表示不按天清理。
3. 不使用 tracing-appender 的 `Rotation::DAILY`，自写按本地日期切分的 writer，同时解决运行中换目录、同日重启追加、无限续段与写入失败缓冲。

设置入口仍在「设置 → 存储」，没有新增一级分类；日志目录与媒体目录、媒体保留策略放在同一页。

## 2. 目录与文件

| 场景 | 目录 |
| --- | --- |
| macOS 安装态 | `~/Library/Logs/com.hivecast.desktop` |
| Windows 安装态 | `%LOCALAPPDATA%/com.hivecast.desktop/logs` |
| Linux | `~/.local/share/com.hivecast.desktop/logs` |
| 开发构建 | 工程根目录 `HIVECAST/logs` |
| 环境变量 | `HIVECAST_LOG_DIR` 优先于以上全部 |

- 文件名：`hivecast-YYYY-MM-DD.log`，同一天超过 16 MiB 后追加序号 `.1.log`、`.2.log`……不设段数上限，一直续写到跨天；空间回收交给保留天数清理。
- 时间戳：控制台与文件都使用本地时区，格式 `%Y-%m-%d %H:%M:%S%.3f %:z`。
- 控制台不显示 target；文件保留 target，便于按模块过滤。
- 文件字段值统一转义：`\n`→`\\n`、`\r`→`\\r`、`\t`→`\\t`，其他控制字符转 `\\u{...}`，避免日志字段伪造换行；控制台保持原样。
- 日志线程名 `hivecast-log`；panic 走 `hivecast_lib::panic` target，带 panic 信息落盘。
- 文件写入通过 4096 深度 channel 与独立线程串行化，避免业务线程被磁盘 I/O 阻塞；channel 满时该条直接丢弃并计入 `dropped`（按写入批次计，不是行数）。另有 512 KiB `pending` 仅用于「writer 尚未拿到目录」的启动早期，按先进先出排水，溢出同样计入 `dropped`。

## 3. 设置与状态

- `Settings.log_dir`：空串表示平台默认目录；用户选择后保存绝对路径。
- `Settings.log_retention_days`：0–3650，默认 7；0 表示不按天清理。日志不设单日总量上限，磁盘空间由保留天数回收。
- 保存时校验：拒绝相对路径、文件系统根目录、macOS `.app/Contents`；目录必须可创建、可写。校验失败返回错误，不写入设置。
- 运行中切换目录：先尝试创建目标目录并切换 writer；成功后新日志立即写入新目录，旧文件保留原处。启动早期积压的 `pending` 会逐条搬运；若新目录写入失败，未写出的块留在队首，由 `apply_settings` 回落默认目录时继续写，不会静默丢掉启动日志。
- 运行中目标目录失效：记录 `last_error`，自动回落到平台默认目录；回落仍失败时该条丢弃并计 `dropped`；丢弃每 60 秒最多 WARN 一次，避免日志系统自我刷屏。默认目录自身被删时会尝试原地重建一次。设置里仍保留用户填写的原路径，下一次启动会再次尝试。
- `LogStatus` 暴露：生效目录、默认目录、配置值、保留天数、当前文件、文件数、总字节、丢弃片段数、最后错误、回落原因。设置页每 5 秒刷新一次。
- 「打开日志目录」只打开当前生效目录，不打开用户填写但尚未生效的路径。

## 4. 清理与滚动

- 清理在启动、保存设置、每日巡检时执行；清理任务每 30 分钟检查一次日期是否翻篇。
- 保留窗口为「含今天在内的 N 个自然日」；删除前严格匹配 `hivecast-\d{4}-\d{2}-\d{2}(\.\d+)?\.log`，只删普通文件。
- 跳过当前正在写的文件；单个文件删除失败不会中断其余清理，首个错误写入 `last_error`，不影响应用运行。
- 单日写满 16 MiB 切下一段，段号可一直递增，不设单日段数上限；跨天或重启后从第一个未写满的分段继续写。
- 没有日额度：日志不再因为当天写满 64 MiB 而被丢弃。代价是磁盘占用由日志量和保留天数决定，新增高频日志前仍应评估保留窗口内的总量。
- 单条日志超过 16 MiB 时写入一个空分段，不因单条过大而丢弃；下一次写入再切新段。
- 弹幕批量下发每 200ms 一批，但 DEBUG 不逐批打印：每个房间每 60 秒汇总一条「弹幕批量下发汇总（60 秒）」，字段为 `batches`、`messages`、`dropped_total`。4 路同时观看约 0.6 MiB/天，不再出现“看几小时就把当天日志写满”的情况。
- 应用退出时 flush 并关闭 writer；`SIGTERM`/正常退出路径由 `logging::shutdown` 收尾。`shutdown` 最多等写线程 2 秒，超时后打印错误并分离线程，避免网络盘或卡死 I/O 拖住退出。

## 8. 已知边界

- 单日段数不设上限，日志不会因为容量被丢弃；磁盘占用随日志量增长，需要保留天数兜底。
- `dropped` 只在 channel 满、pending 溢出或写失败时增加，单位是写入批次；出现后每 60 秒最多一条 WARN。
- 自定义目录失效时回落到默认目录重试；默认目录也写失败时该条丢弃并计 `dropped`（控制台仍输出）。默认目录自身被删会尝试原地重建一次。
- 前端错误上报依赖 Tauri IPC；纯浏览器预览（非 Tauri）只写 console，不落盘。
- Windows 的路径与文件占用行为已按平台分支实现，但本轮真机验收只在 macOS 完成，Windows 仍需在打包机复验。
