## §2 统一音量

之前每个卡片自己存一份音量（`volumes[id]`），默认 0（静音）。
同时放几条录像时，调好一条再放第二条又回到静音，很容易以为是播放器坏了。

改法：音量提到 `MediaPage` 的组件状态，所有 `<Player>` 共用：

```
const VOLUME_KEY = "hivecast.mediaVolume";
function loadVolume(): number { ...钳到 0..1，解析失败回 0... }
const [volume, setVolume] = useState(loadVolume);
```

- 任意一格的音量滑杆改动，会同步到所有正在回放的卡片（本来就是一个「媒体库音量」）。
- 写入 `localStorage`，重启应用还是上次的音量；`try/catch` 包住，隐私模式写不进去只影响默认值。
- 默认仍是 0（静音），与 D3「默认全静音」一致：点开录像不会突然出声。
- 观看页（D3 / O1）保持每槽位独立音量，两条链路互不影响；媒体库是「看完就关」的场景，统一更顺手。

## §3 后处理进度

### 3.1 后端

```
pub struct Progress<'a> { app: &'a AppHandle, task: &'a str, total_ms: i64 }
pub const EVENT_POST_PROGRESS: &str = "post://progress";
```

- 跑 ffmpeg 时在输出参数前追加 `-progress pipe:1 -stats_period 0.2 -nostats`，
  读 stdout 的 `out_time_us=` 行（微秒），`percent_for()` 换算成 0..99 并封顶 99；
- 百分比只增不减（`if percent > last`），避免 ffmpeg 抖动导致数字来回跳；
- 100% 不靠事件表达，任务成功由返回值 `PostResult` 表示，前端在 finally 里清空百分比；
- **只有知道总时长才发进度**：`total_ms > 0` 才走带 progress 的分支，否则退回原来的 `run_ffmpeg`
  （没有分母算百分比没有意义，例如源文件缺时长信息）；
- `stderr` 用独立 task 读干净再 `wait`，避免管道写满互相卡死（`-loglevel error` 输出很少，但合并大量文件时仍可能很长）；
- 合并任务的 `task` 固定为 `"merge"`，与录像 id 不冲突（录像 id 是 uuid）。

### 3.2 前端

- `onPostProgress` 订阅后只更新一个数字；
- 按钮文案从 `…` 换成 `42%`：转封装按钮显示自己那条任务的百分比，合并按钮显示 `"merge"` 的进度；
- 任务结束（成功或失败）在 `finally` 里把百分比置空，按钮恢复成「转 mp4 / 合并选中」；
- 失败仍然走原来的 `error` 条，不额外弹通知。

## §4 实测

真机步骤（macOS，`pnpm tauri dev`）：

1. 先起一次应用创建数据库，然后用 `sqlite3@@ 直接插一条 `room@@ + 一条 `record_session@@
   （`/tmp/seed60.flv`，60 秒 1.4MB，status=finished），模拟媒体库里已有录像；
2. 临时给 `MediaPage` 加一行「进入页面就点第一张卡的转 mp4」并在页面上渲染收到的最大百分比；
3. 刷新后：页面显示 `TEMP-VERIFY max=99`，同时 `/tmp/seed60.mp4` 生成（1.48MB），
   说明 `post://progress` 事件从 Rust 一路到了 React；
4. 验证完删掉临时补丁、删掉种子数据与产物。

| 检查 | 结果 |
| --- | --- |
| 事件到达前端 | ✅ max=99 |
| 产物生成 | ✅ seed60.mp4 1.48MB |
| ffmpeg 参数生效 | ✅ 单独跑同一串参数，stdout 有 `out_time_us=3000000` |
| cargo test --lib | 95 passed / 14 ignored |
| cargo check --all-targets | 0 warning |
| tsc -b / pnpm build | 通过 |
| check-i18n / check-docs | 233 keys / 35 files |

60 秒素材的转封装不到 1 秒，百分比会从 0 直接跳到 99；真实 4 小时录像的 remux 与多段合并才会看到连续爬升。

## §5 为什么不做成全局任务队列

后处理仍是一次只跑一个（`posting !== null` 时按钮禁用），理由是 ffmpeg 抢磁盘 IO 会把正在录制的分片写坏。
进度只是让用户知道「它在动」，不是并发调度的前提。真正的任务队列留给 M11（如果要）。

## §6 已知缺口

1. 截图与 ASS 不显示进度（本身 100ms 级完成）。
2. 没有取消按钮：ffmpeg 一旦跑起来只能等它结束或杀掉进程。
3. 极快任务上百分比会跳变（0 → 99），因为 ffmpeg 的 `-stats_period` 是固定间隔。
4. 媒体库音量统一后无法「这张卡单独静音」，需要的话再给卡片加本地覆盖。
5. 进度事件是全局广播，多窗口（如果将来开第二个窗口）会互相看到对方的百分比。
