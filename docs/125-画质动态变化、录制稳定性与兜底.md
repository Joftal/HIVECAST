# 125-画质动态变化、录制稳定性与兜底

> 状态：v1 已实施（2026-11-09）；补充自动画质录制钉档、能力清单刷新与空清单兜底。
> 范围：录制自动画质、观看能力清单刷新、画质解析失败兜底。

## 0. 结论速览

- 用户的判断基本正确：**录制应保持开场时的实际画质**，观看界面应能发现后来出现的更高档位。
- 录制自动画质（qn=0）开场落到实际档位后，本场会钉住这个档位；直播中途出现 4K 不会让同一场录像跳档。
- 显式档位（如原画/蓝光）仍保留请求值，续录时可恢复到用户选的档位。
- 观看的自动画质不会在播放稳定时主动跳档；菜单打开会重新请求能力清单，缓存的 60 秒 TTL 过期后即可看到新出现的 4K，手动选择后该路重启。
- B 站能力清单现在合并 `g_qn_desc` 与 `accept_qn`，避免平台只把新档位放进其中一份导致漏档。
- 能力清单为空或解析失败时，前端回退到通用档位列表（最高可用/原画/蓝光/超清/高清/流畅），不会把画质入口变成空菜单。

## 1. 录制自动画质

### 开场

`record_qn = 0` 时，`pick_candidate` 使用 `quality_rank(qn, 0)`，在平台返回的候选里选最高档。实际拿到的 qn 会写进文件名与 `Recording.quality`。

### 本场钉档

`Active.qn` 不再直接存请求值，而是：

```rust
fn pinned_qn(requested: u32, actual: u32) -> u32 {
    if requested == 0 && actual > 0 {
        actual
    } else {
        requested
    }
}
```

- 自动画质 → 钉住开场实际 qn（例如 250）。
- 后续断流续录仍用 250 重新解析；即使平台此时已经提供 4K，也不会切到 4K。
- 显式档位 → 保留请求值（例如 400），续录允许恢复到 400。

### 降级

- 开场实际档位低于请求档位时，仍会记录 `quality_fallback` 提示，但不会拒绝录制。
- 续录时如果钉住的档位消失，`quality_rank` 会选不高于目标的最高可用档；没有再取更高档，避免无提示跳档。

## 2. 观看看法

### 自动画质

- 起播或重连时按当时的能力取最高档。
- 播放稳定期间不会因为平台后来上架 4K 而自动重启升级。
- 打开画质菜单会重新请求 `room_stream_options`；broker 的 `StreamPlan` 缓存 TTL 为 60 秒，过期后会重新解析并显示 4K。
- 手动选择 4K 后只重启当前观看槽位，不影响录制。

### 是否需要自动升级

暂不自动升级：观看中切换画质会重建转封装管线，造成短暂中断。更稳妥的做法是让菜单保持最新，由用户决定何时切换。

## 3. 漏档与解析兜底

### B 站

- 合并 `g_qn_desc`（平台名称）与所有 codec 的 `accept_qn`（实际可用档位）。
- 只出现在 `accept_qn` 的新档位也会补进清单，标签暂为 `qn<数字>`，至少不会丢档。
- `accept_qn` 内但 `g_qn_desc` 没有的档位标记可用。
- 例外（[138](138-B站三态Cookie与取流审计.md)）：匿名（任意探测档）或最高档探测时 `current_qn` 才是当前实际上限；`accept_qn` 里高于它的档位（如匿名下的 4K/原画）不能标可用。

### 斗鱼 / 虎牙 / 抖音

- 分别以 `multirates`、`vMultiStreamInfo`、`collect_qualities()` 为准。
- 清单为空时返回空数组，前端进入兜底。

### 前端兜底顺序

1. 平台能力清单（正常路径）。
2. 清单为空 → 通用档位：最高可用、原画、蓝光、超清、高清、流畅。
3. 当前请求 qn 不在清单 → 补一个同值兜底项，保证入口有标签。
4. 自动项始终存在。

监控详情的画质选择器同样使用通用档位兜底。

## 4. 缓存与刷新

- `StreamBroker::plan` 缓存 60 秒。
- 观看页打开菜单会请求一次；60 秒内命中缓存，不额外触网。
- 超过 60 秒后菜单打开会重新解析，能看到平台新增/下架的档位。
- 监控详情的画质/线路选择器每次打开强制走前端刷新；后端仍受 60 秒缓存和限速保护。
- 线路刷新按钮绕过前端缓存，后端缓存过期后重新拉取。

## 5. 仍然存在的边界

- 平台完全不返回某档位时，应用无法凭空知道它存在；此时只能靠通用兜底让用户手动选择。
- 自动画质录制不会在中途升级画质；这是刻意的稳定性选择。
- 观看自动画质不会在稳定播放时自动升级；需要用户在菜单里选择。
- B 站访客权限、斗鱼原画权限仍可能导致实际档位低于清单标注。
- 虎牙 HEVC 4K/2K 已在 [126](126-全平台画质可用性改造.md) 开放选择；匿名 4K/HDR 可能被平台 403，需要账号权限。
- B 站杜比已开放；音频解码取决于系统/WebView。
