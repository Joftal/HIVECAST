# 194 任务中心保留策略与导出加固

## 结论

上一轮复审遗留的 4 项问题本轮全部处理：

1. **任务历史/事件无限增长**：新增固定保留策略，180 天前的已结束任务会被淘汰，并保留最近 500 条；任务历史封顶 20,000 条，阶段事件封顶 200,000 条。运行中、排队中的任务永不被删。
2. **CSV 导出仍是内部值且可被 Excel 当公式执行**：阶段/状态映射为中文，单元格统一做 RFC 4180 转义，并对 `= + - @`、制表、回车、换行开头的值加前导单引号。
3. **任务历史缺失时 Run 可能显示完成**：`finish_run` 直接把 `record_session.post_state=failed` 纳入失败判定；若找不到可重试的 post/remux 任务，会按场次补一条合成失败任务，异常卡仍有 `retry_post` 入口。
4. **历史表行不支持 Enter**：行本身可聚焦，Enter 打开详情；行内「详情」按钮保留，事件目标判断避免按钮上的 Enter 重复触发。

## 当前实现与逻辑

### 保留策略

- 策略常量集中在 `src-tauri/src/retention.rs`：`TASK_HISTORY_DAYS = 180`、`TASK_HISTORY_KEEP_RECENT = 500`、`TASK_HISTORY_MAX = 20_000`、`TASK_EVENT_MAX = 200_000`。
- `Db::prune_task_data` 在一个事务里按顺序执行：
  1. 删除 `finished_at/started_at < cutoff` 的已结束任务，但用子查询保留最近 `keep_recent` 条；
  2. 把已结束任务压到 `max_history`；
  3. 删除 `task_history` 中已不存在的任务事件；
  4. 删除 `at < cutoff` 的事件；
  5. 把事件压到 `max_events`。
- `state IN ('running','queued')` 在每一道任务删除条件里都排除，正在跑或排队的任务不会被保留策略误删。
- 没有新增后台定时器：跟随应用启动、录制收尾、保存设置三个既有清理时机执行，避免再引入一套生命周期。清理失败只记 warn，不影响主流程。

### CSV 导出

- `csv_stage` / `csv_state` 覆盖任务中心使用的内部阶段与状态；未知值原样输出，避免以后新增枚举被静默吞掉。
- `csv_cell` 先检查去掉前导空格/制表后的首字符，命中公式前缀就加 `'`，再按 RFC 4180 用双引号包裹并转义内部引号。
- 导出仍是 UTF-8 CSV，不改变列顺序和上方表头。

### Run 失败聚合

- `post_failed` 直接来自本 Run 所有 `record_session.post_state`，不再只依赖 `task_history` 的任务状态。
- 对 `post_state=failed` 且没有 failed/interrupted post/remux 任务的片段，补一条 id 为 `post:<session_id>` 的失败任务，字段包含 room/session、`post_error`、结束时间；分组录制会带上片段序号。这样 `build_incidents` 仍能给出 `retry_post`，而不是一个没有入口的失败标记。
- 已有任务状态仍优先参与聚合；合成任务只在任务历史缺失时补位，不覆盖真实任务的重试状态。

### 键盘打开历史

- 历史 `<tr>` 增加 `tabIndex={0}` 与 `focus-visible` 样式。
- `onKeyDown` 只在 `event.target === event.currentTarget` 且按下 Enter 时打开详情，避免行内按钮的 Enter 冒泡导致重复打开。

## 验证

- `cargo test`：450 passed，0 failed，20 ignored。
- 新增单测：
  - `prunes_old_tasks_but_never_running_ones`：旧任务被删、running 保留、孤儿/过期事件被删。
  - `prunes_task_history_and_events_to_hard_caps`：任务历史与事件同时压到硬上限。
  - `csv_export_uses_readable_labels_and_blocks_formulas`：中文映射、公式前缀、空格前缀、引号转义。
  - `failed_session_post_state_is_not_reported_as_done_without_task_history`：没有任务历史也不会把失败 Run 报成完成，并生成可重试任务。
  - `grouped_missing_post_history_still_reports_failure`：分组录制缺历史时仍报失败，合成任务带正确片段序号。
- `npm run build`：tsc + vite 构建通过。
- `npm run check:docs`、`npm run check:i18n` 见本轮收尾结果。

## 仍需完善/未做

- 保留策略是固定阈值，没有暴露到设置页；如果用户希望永久保留任务审计数据，目前无法关闭。
- 事件清理按全局条数封顶，不按单个任务封顶；极端情况下一个超长任务仍可能挤掉其它任务较旧的事件。
- 磁盘上的录像/媒体文件与任务历史是两套保留策略：删文件不会立即删任务历史，只会等 180 天/条数上限自然淘汰。
- 未做桌面端逐项人工点击回归；本轮以单测与构建验证为主。
