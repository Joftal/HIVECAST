## 二、发布问题表逐项复核

### 15 · Windows 构建门

原问题是 Cargo 1.100 对没有显式测试目标的包拒绝 `cargo:rustc-link-arg-tests`，报 `invalid instruction` / `does not have a test target`。现在包内存在 `src-tauri/tests/windows_manifest.rs`，测试目标成立，链接指令有接收方。同一修复还处理了严格 Clippy 在 Windows 条件分支上的两处报错：

- `src-tauri/src/tray.rs` 的托盘 builder 改为 shadowing，macOS 下重新绑定 template icon。
- `src-tauri/src/post.rs` 的 `trash_dir` 只在 Unix 编译，Windows 的回收站打开走 explorer 的 `shell:RecycleBinFolder`。

macOS 上已通过 `cargo test --lib`、`cargo clippy -D warnings` 与 release 构建。Windows 原树和 NSIS 安装仍未在本轮执行。

### 04 · 卷暂时不可见时保留索引

清理逻辑现在对每个产物先 `metadata`，遇到 NotFound 时调用 `parent_missing`。父目录不存在意味着外置盘未挂载或目录被整体移走，此时把本次清理标为失败，保留会话行与媒体登记；只有父目录仍在、文件确实被删掉时才按成功处理。读取录像文件清单失败也直接保留，不再把母带当孤儿。

单测 `enforce_keeps_the_session_when_the_parent_directory_is_gone` 先登记临时录像，再重命名父目录，断言会话仍在、原文件未被删除。

### 05 · 提交阶段不覆盖他人文件

后处理不再先删目标再改名。`finish_command` 成功后调用 `commit_output`：

1. `next_available_target` 找当前不存在的候选；
2. 同目录 `hard_link(temp, candidate)`，这是原子且零拷贝的「仅当不存在时创建」；
3. 返回 AlreadyExists 就顺延 `.1`、`.2`；
4. 文件系统不支持硬链接时回退 `copy_no_clobber`，用 `create_new` 占位并复制；
5. 临时文件删除失败不再把已落盘的产物判成失败。

单测 `commit_output_does_not_overwrite_a_file_created_during_encoding` 在编码期间放入同名文件，断言成品落到 `live.1.mp4`，原文件内容保持不变。

### 07 · 错误日志不携带查询参数

`platform/http.rs` 的请求错误统一经过：

```rust
fn request_error(url: &str, err: reqwest::Error) -> String {
    format!("{} → {}", redact_url(url), err.without_url())
}
```

`without_url` 去掉 reqwest 错误内部携带的原始 URL，`redact_url` 再把查询值替换为 `***`。9 处 `map_err` 都走这个函数。测试用 `127.0.0.1:1` 和带 `qrcode_key`、`token` 的 URL，断言完整错误文本里没有密钥、查询键被脱敏。

### 10 · 崩溃恢复不误杀

`process_matches` 的返回值从 bool 改成 `Option<bool>`：

- `Some(true)`：PID 存活，命令行确实是这条录像的 FFmpeg，终止；
- `Some(false)`：进程已退出，或 PID 被别的进程复用，删除 PID 文件；
- `None`：查不到命令行、tasklist/ps 失败，保留 PID 文件，下次再判断。

命令行匹配先统一反斜杠为斜杠、转小写，再匹配完整路径；分片模板要求「完整父目录 + stem.part」，最后才回退完整文件名。这样 `D:\second\a.part%04d.ts` 不会被认成 `C:\media\a.flv`。Windows 侧优先 PowerShell CIM，失败才回退 wmic；两条都拿不到命令行时返回 `None`。

### 06 · 整组合并缺段必须失败

`MergePlan` 新增 `missing`。`merge_plan` 不再 `retain` 掉不存在文件，而是把缺文件路径和无路径片段记进 `missing`；`room_merge_sessions` 与 `sessions_merge` 在拿到计划后立即检查，非空就返回 `AppError::User`，提示最多 5 个路径和总数。排序改为 `(started_at, clip_index)`，同一秒内的分片按序号排列。

单测覆盖乱序输入、缺文件中段、同秒不同 `clip_index`。真机验证见第四节。

### 18 · 失败合并清掉占位成品

`MergeArtifacts` 保存成品、concat 清单和 `keep` 标志。`merge` 在 `reserve_merge_output` 之后立即创建守卫；FFmpeg 失败、输出为空或提前返回时，`Drop` 删除本次占位文件与清单。成功且大小大于 0 才删清单并置 `keep=true`，避免把上次崩溃留下的同名清单误删。

单测 `failed_merge_cleanup_removes_output_and_list` 同时验证失败清理与成功保留。真机用两段不可解码 FLV 复现，失败后目录没有 0 字节 MP4，也没有 concat 清单。

### 20 · 长录像弹幕回放

后端新增 `read_danmaku_range(path, from_ms, to_ms)`：用 `BufReader::lines()` 逐行读，跳过空行与坏 JSON，只解析落在窗口内的消息，并只对窗口排序。`media_danmaku` 增加 `fromMs`、`toMs` 两个可选参数。

前端每次加载播放位置前后各 120 秒：

- `DANMAKU_WINDOW_MS = 120_000`，`DANMAKU_MARGIN_MS = 30_000`；
- `loadDanmakuWindow` 用序号丢弃过期应答；
- 窗口前沿为 0 时不再用 `from + margin` 判断，否则开场前 30 秒每一帧都会重载同一段；
- 用 `danmakuLoadingRef` 做在途互斥，失败也推进窗口，避免失败后每个播放事件重复请求；
- 播放位置进出窗口边缘时才换窗。

真机发现并修复了两个窗口缺陷：播放器上报毫秒浮点数，直接传给 Tauri 的 i64 参数会被拒绝；以及开场阶段窗口边界判断错误导致每帧重复加载。两者修复后，300 秒、6000 条弹幕的夹具在 0–90 秒只发 1 次请求，90 秒后按窗口推进。

### 19 / 21 · 设置快照与默认目录

`Db::all_settings` 用一条 `SELECT key,value FROM app_setting` 返回全量快照，`settings::load` 用闭包从快照取值，避免逐键加锁读到跨事务的混合状态。

`defaults` 只用于安装后首次生成默认值；`load` 从 `base_defaults` 开始，媒体根为空时才调用 `default_media_root`。已有自定义目录时，监控每两秒重载设置不会再创建、删除探针目录。

### 16 · 相对路径

`absolute_media_root` 对绝对路径做 `canonicalize`（失败保留绝对形式），对相对路径以默认媒体根父目录为基准拼接后再规范。手动合并的 concat 清单对每个源调用 `std::path::absolute`，避免清单按自身目录解析导致目录拼两次。

### 22 · Windows 时区

jiff 特性从仅 `std` 改为 `["std", "tz-system", "tzdb-bundle-platform"]`，系统时区查不到时使用打包的时区库。macOS 上日期筛选与 CSV 正常；Windows 仍需按 UTC+8 和采用夏令时的时区实测。

### 09 · 自动录制开关竞态

房间开关的开启分支改走 `start_checked`，在房间级开录锁内重读 `auto_record`。`start_inner` 在会话挂进活动表后再次读取取消标记和数据库开关：

- 用户点停录留下 `start_cancelled`，立即按 `stopped` 收尾；
- 最后一次检查后用户关闭自动录制，`auto_off` 为真，同样立即收尾；
- 否则才消费原有的 `pending_stop`。

日志新增 `cancelled`、`auto_off` 字段。该窗口无法用桌面点击稳定复现，本轮以代码路径和编译测试确认，未做并发实录。

## 四、真机验收

环境为 macOS 27.2.1 arm64，应用是 `src-tauri/target/release/bundle/macos/HIVECAST.app`（35.10 MiB）。测试数据库为应用真实库，夹具写入后启动应用；测试结束后已退出应用并清理，避免污染用户数据。

夹具：

- `fixture-200` 房间，B 站，`room_key=99990001`，监控暂停、自动录制关闭；
- `/tmp/hivecast-200/bad` 两段 13 字节文本，模拟不可解码 FLV；
- `/tmp/hivecast-200/good` 三段约 3 秒 FLV；
- `/tmp/hivecast-200/long` 300 秒 20 MB 合成视频与 6000 条 JSONL 弹幕。

结果：

1. **18 失败合并清理**：点 bad 组「合并本场 2 段」，FFmpeg 报 `Invalid data`；目录只剩两段源文件，没有 0 字节 MP4，也没有 concat 清单。
2. **06 缺段阻断**：把 good 组第二段改名后点「合并本场 3 段」，界面顶部红色通知「合并失败 / 有 1 段录像文件不存在，已停止合并：/tmp/hivecast-200/good/clip2.flv」，目录没有产生成品。
3. **20 长弹幕回放**：打开 long 卡片，首窗读取 `from_ms=0 to_ms=120000`、返回 2401 条；播放推进到约 90 秒后换到 `0–210212`，再依次换到 `105000–345000`、`195143–435143`。窗口按 120 秒步进，界面总数显示 6000 条。
4. **20 浮点参数回归**：修复前日志出现 `invalid type: floating point 120500.353126, expected i64`，且每个播放事件重试一次；修复后同场播放不再出现该错误，首窗只发一次请求。
5. **缩略图**：bad 两段按预期失败，good 与 long 成功；失败只影响缩略图，不影响录像卡片与播放。

本轮没有重新录制四平台直播，也没有在 Windows 上安装 NSIS 包；这两类验收沿用 196/198 的既有记录，不能替代本次 Windows 结论。

## 五、当前实现与逻辑摘要

### 录像与后处理

- 录制按 `partNNNN.ts` 分片，停止后按 `started_at + clip_index` 合并为源封装或转封装产物。
- 后处理输出先写临时文件，成功后才提交最终名；提交不覆盖已有文件，冲突顺延序号。
- 失败合并会撤销本次占位的成品与清单；成功合并登记失败时保留成品并提示路径。
- 合并前校验每个片段的文件存在性，缺段直接阻断，不生成少一段的成品。

### 保留与删除

- 保留策略按天数与容量淘汰，删除前读取完整产物清单。
- 文件不存在且父目录也不存在时视为卷离线，保留会话；清单读取失败同样保留。
- 用户手动删除时，主文件、旁挂、母带分别处理；部分失败返回残留路径并保留可重试的记录。

### 任务中心与导出

- 任务事件支持游标分页、跨 Run 检索、FTS5 与中文标签映射。
- 历史录像按 100 条分页，上限 1000；事件时间线每次 200 条，可继续加载。
- CSV 导出上限 50,000 条，返回实际写入数与匹配总数，前端提示截断。
- 阶段事件（`phase:*`）不写 `task_history`，保留策略按时间窗口清理，不再按孤儿事件删除。

### 弹幕

- 直播弹幕按平台适配器连接；B 站凭据过期时回退匿名，不再形成 30 秒重连循环。
- 录像回放按播放位置前后 120 秒流式读取 JSONL，前端只持有当前窗口。
- 合并录像的弹幕偏移按每个片段时长累加，ASS 导出与 JSONL 使用同一组偏移。

### 设置与平台

- 设置加载走单条快照，保存走单事务；媒体根统一规范为绝对路径。
- 扫码登录的 HTTP 错误统一脱敏，日志不输出查询参数值。
- 崩溃恢复只终止命令行能确认属于本场录像的 FFmpeg；无法确认时保留 PID 线索。
