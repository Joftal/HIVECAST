# 任务中心收尾重试与历史回填

> 状态：实现并真机验收（2026-11-21）。承接 [182-任务中心分组与收尾状态复查](182-任务中心分组与收尾状态复查.md) 第 5 节列出的未完成项；设计见 [179-任务中心全链路追踪设计](179-任务中心全链路追踪设计.md)。
> 后续：同日的全链路复查修正了本文三处描述——收尾任务只保留最新一条、重试锁按 manifest 而非 session、历史分页必须多读一组，详见 [184-任务中心全链路复查](184-任务中心全链路复查.md)。
> 本轮范围：补齐收尾任务展示与手动重试、异常中断的「部分入库」、历史场次分组回填、任务中心历史分页；不改数据库表结构。

## 1. 结论

docs/182 第 5 节列出的 5 个缺口已经补齐，第 6 条「不改 schema」保持不变：

| 缺口 | 本轮处理 |
| --- | --- |
| 旧分割录像首片段 `group_id` 为空 | `Db::open` 启动时回填，只处理「已有片段明确指向它」的首片段 |
| 收尾失败没有任务行、没有重试入口 | `finalize` 任务进入 Run 任务列表；需要处理与详情新增「重试收尾」 |
| aborted 有部分产物仍显示「入库完成」 | 入库阶段新增 `partial`，有产物显示「部分完成」，无产物显示失败 |
| 历史读取固定 `history*4` 上限 | 改为按已结束分组数分页读取，硬上限 5000 行并告警 |
| 收尾失败只能人工处理 | `recorder::retry_finalize` 复用分割清单恢复，单场次加锁 |

## 2. 收尾任务展示与重试

### 2.1 任务列表

`/Library/dshproject/HIVECAST/src-tauri/src/task_center.rs:406` 的 `RunDraft` 新增 `finalize_tasks`，收尾任务不再被直接 `continue` 掉，而是收集起来；`finish_run` 在 :451 只认**最新一条**收尾任务：

```rust
draft.finalize_tasks.sort_by(|a, b| {
    a.started_at.cmp(&b.started_at)
        .then_with(|| a.finished_at.cmp(&b.finished_at))
});
if let Some(task) = draft.finalize_tasks.last() {
    draft.finalizing = task.state == "running" || task.state == "queued";
    draft.finalize_finished = task.state == "done";
    draft.finalize_failed = matches!(task.state.as_str(), "failed" | "interrupted");
    draft.finalize_message = if draft.finalize_failed { task.message.clone() } else { None };
}
```

旧实现用「或」合并，重试成功后旧的 `failed` 会永远把收尾阶段钉在失败。现在任务列表按「录制 → 收尾 → 后处理」排列（:648），详情里能直接看到收尾任务的类型、状态、耗时和消息；184 起只保留最新一条收尾尝试，避免重试成功后旧的 failed 仍占一行。

### 2.2 需要处理与详情按钮

- `task_center.rs:993` 对 `kind == "finalize"` 且带 `session_id` 的失败任务返回 `retry_finalize` 动作。
- `TasksPage.tsx:532` 把该动作渲染为「重试收尾」；详情抽屉 :808 也会出现按钮。
- `TasksPage.tsx:1011` 的 `onRetry` 按 `task.kind` 分流：`finalize` 调 `finalizeRetry`，其余仍调 `postRetry`。
- `src/lib/ipc.ts:293` 新增 `finalizeRetry(sessionId)` → `invoke("finalize_retry")`。

### 2.3 后端执行

`/Library/dshproject/HIVECAST/src-tauri/src/commands.rs:1509` 新增 `finalize_retry` 命令：先取 session/房间标题，建一条 `finalize` job，进度写「重新合并分片并执行后处理」，再调 `recorder::retry_finalize`，成功 `job.finish("done", "收尾完成")` 并发出 `EVENT_ROOMS_CHANGED`。

`/Library/dshproject/HIVECAST/src-tauri/src/recorder.rs:3897`：

- 拒绝不存在的场次、仍在录制的场次；
- 通过 `db.split_manifest_for(session_id)` 找清单（见 3.2）；没有清单提示「可能已经收尾完成」；
- 清单文件不存在则提示「收尾清单文件已不存在」；
- `FINALIZE_RETRYING: OnceLock<Mutex<HashSet<String>>>` + `FinalizeRetryLease` 保证同一份清单只跑一个重试（184 起锁键由 session 改为 manifest），重复点击返回「这一场正在重试收尾，请稍候」；
- 复用 `recover_split_manifest`：已完成的片段沿用，缺失的分片按清单重跑；清单删除后返回成功，未删除则返回「收尾仍未完成，缺失的分片或源文件可能已被清理」。

## 3. 部分入库与历史回填

### 3.1 aborted 的入库阶段

`task_center.rs:798` 新增 `normal_commit`：

```rust
let normal_commit = if abnormal_abort {
    if members.iter().any(|session| {
        session.file_size > 0
            || session.file_path.as_deref().is_some_and(|path| Path::new(path).is_file())
    }) { "partial" } else { "failed" }
} else { "done" };
```

并把它用于 `member_post_done`、`post_state == "skipped" && all_ended`，以及 `abnormal_abort && all_ended` 三个分支。这样磁盘满等异常中断不会显示「入库完成」：有文件显示 `partial`（详情圆点/文案用 warn），完全没有产物才是 `failed`。

前端：

- `TasksPage.tsx:257`、:676 为 `partial` 增加 warn 圆点与颜色；
- StageRail / 详情图标显示 `~`；
- 文案沿用 `STATE_KEYS.partial`，当前中文显示「部分失败」——语义偏向「没有完整成功」，本轮未改文案。

### 3.2 旧数据分组回填

`/Library/dshproject/HIVECAST/src-tauri/src/db.rs:1927` 新增 `backfill_session_groups()`：

```sql
UPDATE record_session
   SET group_id = id
 WHERE group_id IS NULL
   AND EXISTS (
       SELECT 1 FROM record_session AS clip
        WHERE clip.group_id = record_session.id
          AND clip.id <> record_session.id
   )
```

`Db::open`（:274）在迁移阶段调用，只有真的补了行才打 INFO「数据库迁移：补全旧录制场次分组」。它只处理「已有片段明确指向它」的首片段；没有片段指向的旧单场不会猜分组，符合 docs/182 的边界。再执行一次返回 0，幂等。

`split_manifest_for`（:1944）按 `id` 或同组任意片段的 `split_manifest` 查找，按 `started_at` 取最早一个，保证从组内任意片段都能重试整组收尾。

### 3.3 历史分页

`task_center.rs:1190` 的 `load_sessions(db, history)`：

- `PAGE = 200`、`MAX_ROWS = 5_000`、`target = history + 8`；
- 每页累计已结束分组（`session_group_key`），必须多读一个分组才停；未达上限时丢弃末尾不完整组；
- 达到 5000 行仍不够时打 WARN「任务中心历史分页达到上限，较早场次可能未纳入」，避免异常数据拖慢 2 秒轮询。

## 6. 边界

1. **重试依赖清单和源分片**：清单丢失、分片被清理、源文件不可读都会返回用户态错误并保留清单，不会把 session 标成完成。
2. **单进程锁**：`FINALIZE_RETRYING` 只防同进程并发；多实例同时重试同一场次不在本轮范围。
3. **partial 只针对异常中断**：正常结束仍走 `done`；`app_exit` 的「中断」语义由 docs/182 处理，不因本轮改成 partial。
4. **回填不猜分组**：没有后续片段指向的旧单场保持 `group_id NULL`，任务中心继续用 `COALESCE(group_id, id)`。
5. **分页上限**：超过 5000 行会告警并截断，属异常数据保护；正常几百场不受影响。
6. **未改数据库 schema**：只写既有 `group_id` / `split_manifest`，没有新增列或表。
