# 120-播放器丢帧统计改为增量与比例

> 状态：v1 已实施（2026-11-09）；开发预览用注入的 `getVideoPlaybackQuality()` 数据复看。
> 范围：观看页播放器统计里的丢帧展示。

## 0. 结论速览

- `getVideoPlaybackQuality().droppedVideoFrames` 是累计值，直接显示只增不减，不能反映当前播放是否卡顿。
- 统计仍每秒采样一次，但改为保存上一秒的丢帧数与总帧数，换算成：每秒新增丢帧数、最近一秒的丢帧占比。
- 展示格式：`丢帧 3/s · 10%`；当前窗口没有新丢帧时显示 `丢帧 0/s · 0%`，用来确认已恢复。
- 从未出现过丢帧时仍不显示这一段。
- 换源或重新加载导致计数器归零时只重建基线，不产生负增量。

## 1. 采样与计算

`src/features/watch/Player.tsx` 的统计定时器每秒执行：

```ts
const dropped = quality?.droppedVideoFrames ?? 0;
const total = quality?.totalVideoFrames ?? 0;

const droppedDelta = dropped - prev.dropped;
const totalDelta = total - prev.total;

dropRate = droppedDelta / 实际间隔秒数;
dropRatio = totalDelta > 0 ? (droppedDelta / totalDelta) * 100 : 0;
```

- `dropRate`：最近一个采样窗口内每秒新增的丢帧数，保留一位小数（≥10 时取整）。
- `dropRatio`：最近一个采样窗口内丢帧数占新增总帧数的百分比，保留一位小数（≥10 时取整）。
- `dropped`：累计丢帧数，仅用于判断是否曾经出现过丢帧。

## 2. 展示

`formatDroppedFrames(stats)`（`src/features/watch/playerStats.ts`）统一供两处使用：

- 观看格标题栏：`分辨率 · kbps · 丢帧 3/s · 10%`
- 播放器自带统计浮层（开发预览 / `showStats`）：同样的后缀。

规则：

| 情况 | 显示 |
| --- | --- |
| 从未丢帧 | 不显示丢帧段 |
| 本秒有新丢帧 | `丢帧 3/s · 10%` |
| 曾经丢帧、本秒已恢复 | `丢帧 0/s · 0%` |
| 浏览器不支持 `getVideoPlaybackQuality` | 累计丢帧为 0，不显示 |

## 3. 语义与局限

- 增量与比例都是**当前采样窗口**（约 1 秒）的数据，不再是从播放开始累计的平均值。
- 短暂拖动进度、切换画质/线路造成的丢帧只会影响对应窗口，下一窗口可以回到 0。
- 不同浏览器对 `getVideoPlaybackQuality` 的实现不同；`0` 只能说明本次窗口没有统计到丢帧，不等于绝对没有卡顿。
- 网络卡顿通常先表现为缓冲，不一定增加丢帧数；该指标主要反映本机解码/渲染压力。
