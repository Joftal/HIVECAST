# 193 任务中心复审与历史名额修正

## 结论

任务中心四段链路（录制 → 收尾 → 后处理 → 入库）仍按 Run 聚合，前端 2 秒轮询任务快照、详情时间线按需分页。本轮完整复查后修复了 4 个确认问题：

1. **历史名额被独立任务挤占**：合并/弹幕导出等没有 session 的 Run 原先也参与 `truncate(history)`，可能挤掉真实录像场次，且 `history_has_more` 只比较录像组数，导致被挤掉的场次没有「加载更多」入口。
2. **异常引用已被截断的 Run**：`build_incidents` 在截断前生成，异常可能找不到对应 Run，重试/打开详情动作丢失。
3. **收尾失败遮蔽后处理失败**：同一 Run 同时有失败收尾和失败后处理时，原先按任务顺序先命中收尾，只给「查看详情」，看不到可立即重试的后处理。
4. **详情「加载更早」失败后误翻页**：运行中的 Run 仍会轮询追加新事件，旧逻辑把「事件变多」误判为加载成功，时间线页码被多加一页。

同时补齐排队任务取消入口，并让跨 Run 检索通过 `task_history.room_id` 关联没有 session 的合并/导出事件。

## 当前实现与逻辑

- 后端 `task_center::build` 先按 session/group 聚合，再把 running、history 任务挂到对应 Run；没有 session 的任务各自成 standalone Run。
- 历史先按结束时间倒序，再由 `cap_history_runs` 分配名额：录像场次优先占满 `history`，剩余名额才给独立任务；`history_has_more` 只比较已展示的录像场次与已结束组数。
- 截断后再生成异常，并按保留的 session group 过滤历史 session，异常不会再引用列表里不存在的 Run。
- `incident_task` 的选择顺序为：post/remux 失败或中断 → merge 失败 → finalize 失败或中断；后处理失败优先给 `retry_post`。
- 排队任务与运行中任务共用 `post_cancel`：后端置会话取消标记，`post::acquire` 每 120ms 检查一次，未拿到槽位也会立即退出；前端 QueuedRow 与详情抽屉都提供取消。
- 详情时间线首次取最近 200 条，向上加载更早一页；只有 `onLoadEarlier` 返回成功且拿到事件时才前进页码，失败不再污染后续轮询。

- 新增单测覆盖：历史名额优先录像场次、独立任务使用剩余名额、收尾+后处理同时失败时选择后处理并给 `retry_post`。
- 既有任务中心 27 项单测全部通过。

## 仍需完善/未做

- `task_event` 与 `task_history` 仍无保留/清理策略；删除录像或媒体保留策略清理 `record_session` 时不会同步清理事件，长期会增长。
- CSV 导出的阶段/状态仍是内部值（`merging`/`running`），且 `csv_cell` 未防 Excel 公式注入；属于导出格式与安全加固项。
- `finish_run` 的状态主要由任务状态聚合；若历史任务缺失但 `record_session.post_state=failed`，极端情况下 Run 可能显示完成而阶段显示失败，本轮未改聚合规则。
- 历史表行本身仍不支持键盘 Enter 打开，但行内「详情」按钮可键盘操作。
