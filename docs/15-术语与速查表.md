# 15 · 术语与速查表

## 1. 术语表

| 术语 | 英文/别名 | 含义 |
| --- | --- | --- |
| 房间 | Room / LiveRoom | 一个直播间的配置与状态 |
| 场次 | Session | 一次"开播→下播"的完整录制，可含多个文件 |
| 分段 | Segment | 因时长/大小/改名而切出的单个文件 |
| 监听 | Listening | 周期性查询房间是否在播，不下载 |
| 录制 | Recording | 实际拉流写文件 |
| 仅通知 | Notify Only | 只提醒不录制 |
| 候选 | Candidate / StreamCandidate | 一路可选的流（清晰度+格式+编码） |
| 懒解析 | Deferred Resolve | 先给元信息，选中后才请求真实地址 |
| 占位流 | Placeholder | 元信息有但地址需二次请求的候选 |
| 退避 | Backoff | 失败后按指数拉长重试间隔 |
| 抖动 | Jitter | 在间隔上加随机量，避免同时请求 |
| 秒退 | Fast Fail | 取流成功但几秒内就断 |
| 看门狗 | Watchdog | 检测"进程活着但没数据" |
| 优雅停止 | Graceful Stop | 先 SIGTERM 等待，再强杀 |
| 后处理 | Post-processing / Pipeline | 录制结束后的修复/转码/截图/上传 |
| 阶段 | Stage | 流水线中的一步 |
| 可删标记 | Deletable | 全流程成功后才删的中间文件 |
| 烧录 | Burn-in | 把 ASS 字幕编码进视频画面 |
| 弹幕 | Danmaku | 直播评论，落成 ASS |
| 醒目留言 | Super Chat (SC) | 付费置顶留言 |
| 舰长 | Guard | B 站的付费会员等级（舰长/提督/总督） |
| 轮播 | Video Loop | 主播不在时播放录像，**不是直播** |
| 防盗链 | Anti-leech / AntiCode | 带签名的下载地址参数 |
| 设备号 | Device ID (did) | 斗鱼等平台用于识别客户端的固定 ID |
| Wbi | — | B 站的一套请求签名机制 |
| matcher | — | URL → 平台的正则匹配器 |
| 适配器 | Adapter | 某平台的具体实现 |
| 装饰器 | Decorator | 在适配器外包一层限流/缓存/退避 |
| sidecar | — | 随应用分发的独立可执行文件（如 ffmpeg） |

## 2. 三个项目的定位

| 项目 | 语言 | 定位 | 对 HIVECAST 的价值 |
| --- | --- | --- | --- |
| **bililive-go** | Go | 服务端录制器 + Web UI | 平台适配、录制引擎、后处理、数据模型 |
| **streamlink** | Python | CLI 流提取库 | 流抽象、HLS/DASH 分段、缓冲、权重模型 |
| **HIVECAST** | Rust + React | 桌面应用 | 融合两者，做成本地优先的产品 |

## 6. 常见错误与排查

| 现象 | 可能原因 | 排查 |
| --- | --- | --- |
| 一直"准备中" | 取流接口卡住/工具未就绪 | 看日志是否有 `ToolMissing` |
| 录制几秒就断 | 地址失效/风控 | 看是否触发秒退退避 |
| 文件 0 字节 | ffmpeg 启动失败 | 手动跑一遍 ffmpeg 命令 |
| 文件无法 seek | 未修复 FLV | 开启 `fix_flv_at_first` |
| 转 mp4 失败 | 时间戳不连续 | 先 fix_flv |
| 弹幕与画面不同步 | 时间基准错了 | 检查 `t0` 取值时机 |
| ASS 不显示 | 与视频不同名 | 检查文件名 |
| 上传失败 | OpenList 未登录/token 过期 | 检查 `/api/auth/login` |
| 内存持续增长 | 事件/日志无上限 | 检查环形缓冲 |
| 房间显示在播但没录 | 监听器替换竞态 | 参考 `replaceListener` 同步派发 |

## 8. 决策速查（ADR）

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| ADR-01 | 借鉴设计，重写实现 | Go→Rust 迁移成本高于重写 |
| ADR-02 | Tauri 而非 Electron | 体积/内存/后端同进程 |
| ADR-03 | SQLite + WAL | 读不阻塞写 |
| ADR-04 | 三级配置覆盖 | 多房间差异化 |
| ADR-05 | 流水线而非串行 if | 可重试、可观测、可并行 |
| ADR-06 | 默认 ffmpeg sidecar | 兼容性 + 开箱即用 |
| ADR-07 | 事件 + 全量兜底 | 防事件丢失导致状态漂移 |
| ADR-08 | 平台层只返回"描述" | 解耦监听与录制 |
| ADR-09 | 懒解析优先 | 减少请求量，降风控风险 |
| ADR-10 | 抖音依赖外部工具 | 自研签名维护成本过高 |

## 9. 一页纸总结

```text
监听（30s 轮询）→ 事件 → 录制（ffmpeg）→ 文件 → 流水线（修复/转码/截图/上传）
                ↘ 弹幕（WS）→ ASS ↗
                       状态 → SQLite → IPC 事件 → React UI
```

三条铁律：

1. **监听与录制分离**，用事件解耦。
2. **配置三级覆盖**，"未设置"必须可表达。
3. **失败要退避，文件要保留，任务要持久化**。
