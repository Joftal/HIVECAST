> 状态：v1 已实施（2026-11-09）；前端编译、Rust 检查与开发库迁移 SQL 验证通过，真实窗口的轮询/系统打开/规则门禁待复看。
> 范围：在 `105` 的详情抽屉上继续补「录制结果与统计、实时占用、监控诊断、页面联动、单房间规则、体验细节」。
> 前置阅读：`103-监控页性能与加载优化.md`、`104-监控选择工具栏改用Arc-FloatingButtonGroup.md`、`105-录制详情抽屉重构与播放叠层.md`。

## 0. 结论速览

- 详情抽屉现在能回答：上次录得怎么样、总共录了多少、文件写到哪、监控下一次什么时候跑、为什么失败、录像/任务去哪找。
- 信息卡新增「已录体积 · 场次」「上次录制时长」「打开上次录像文件夹」；新增「录制统计」卡（总时长、平均单场、近 7 天、上次结果）。
- 当前录制卡新增实时写入大小、磁盘剩余，并按两次轮询的增长速度估算「预计可录」，打开抽屉时每 3 秒轮询。
- 监控区新增下次检查、失败计数/退避、最近结果与「复制诊断信息」。
- 主操作行增加「更多」菜单：复制房间号、在浏览器打开、打开媒体库录像、查看相关任务。
- 新增「房间规则」：备注、标签、标题包含/排除、分片覆盖、开播/错误通知覆盖。

## 1. 数据与迁移

`room` 表新增列：

```sql
last_session_status TEXT,
last_session_reason TEXT,
last_session_file_size INTEGER NOT NULL DEFAULT 0,
note TEXT NOT NULL DEFAULT '',
tags TEXT NOT NULL DEFAULT '',
title_include TEXT,
title_exclude TEXT,
split_max_duration_sec INTEGER,
split_max_size_mb INTEGER,
notify_live INTEGER,
notify_error INTEGER
```

- 新库/老库都由 `migrate()` 按 `PRAGMA table_info(room)` 补列。
- 上次录制摘要的批量回填同时填充状态、原因和文件大小。
- `refresh_room_last_session` 在会话创建、分割片段、收尾、删除、孤儿清理时刷新这些字段。
- `SessionSummary` 新增 `totalDurationMs`、`recentCount`、`recentDurationMs`、`recentBytes`（近 7 天）与 `failedCount`（失败/中断场次，用于成功率）。

## 2. 新命令

- `room_set_rules(id, note, tags, titleInclude, titleExclude, splitMaxDurationSec, splitMaxSizeMb, notifyLive, notifyError)`
- `recording_usage(sessionId) -> { bytes, diskFree }`：读取录制文件大小和所在磁盘剩余。
- `monitor_status(roomId) -> MonitorStatus | null`：读取监控排期快照。
- `open_url(url)`：只允许 `http/https`，Windows 走 `rundll32`，macOS `open`，Linux `xdg-open`。
- `MonitorStatus` 字段：`nextCheckInSecs`、`inflight`、`backoff`、`throttleStreak`、`errorCount`、`lastCheckedAt`、`lastOutcome`。
- 监控循环每秒把排期快照写进 `AppState.monitor_status`，命令层只读快照，不碰调度内部。

## 3. 单房间规则

### 自动录制门禁

`monitor::auto_record_allowed`：

- `title_include`：逗号分隔，标题必须命中任意关键词。
- `title_exclude`：命中任意关键词则不自动录制。
- 规则只影响自动录制；手动「开录」不受限制。

### 分片覆盖

`Recorder::start` 读全局设置后，用房间的 `split_max_duration_sec` / `split_max_size_mb` 覆盖：

- `None` = 跟随全局。
- `0` = 关闭该项。
- 覆盖只在开录时快照，不影响正在进行的会话。

### 通知覆盖

- 开录/结束/画质降档走 `notify_live`；失败/磁盘异常走 `notify_error`。
- `None` 跟随全局；`false` 时后端不发送 `AppNotice`。
- 通知开关同样在开录时快照。

## 4. UI

### 头部与身份

- 平台 · 房间号副标题；备注与标签在列表中各自单独列，标签以彩色徽章展示。
- 链接右侧复制按钮；主操作行「更多」菜单补复制房间号/浏览器/媒体库/任务入口。

### 监控列表

- 直播间备注与标签各自单独成列；备注点击进入内联输入，标签点击进入 Arc TagInput，不打开录制详情。
- 标签列展示最多两个彩色徽章，超出显示 `+N`；编辑时横向单行，回车/逗号添加标签，失焦保存。
- 搜索框同时匹配主播名、标题、房间号、备注和标签。
- 平台筛选旁新增「标签」chip，选项按标签出现次数排序，可一键只看某组标签；「全部」会同时重置平台、标签和录制筛选。

### 当前录制

- 悬停播放叠层、时长、画质/线路、文件名、打开文件夹保持。
- 新增「已写入」与「磁盘剩余」，3 秒轮询 `recording_usage`；用相邻两次增长量估算「预计可录」。
- 卡片 `sticky top-0`，长抽屉滚动时仍能看到当前录制状态。

### 监控诊断

- 最近检查（相对时间）。
- 下次检查：`MonitorStatus.nextCheckInSecs`，检查中显示「检查中…」。
- 失败计数；退避中额外标红「退避中」。
- 最近结果：正常 / 限流 / 重试 / 失败。
- 最近错误可复制；底部「复制诊断信息」拼出房间、状态、检查时间、错误。

### 统计与规则

- 「录制统计」卡：总时长、平均单场、成功率、近 7 天（场次 · 时长 · 体积）、上次结果（状态 · 原因 · 文件大小）。
- 「房间规则」可折叠：主播备注、标签、标题包含/排除、分片时长/大小、开播/错误通知，保存后统一写回。
- 快捷键：抽屉打开且焦点不在输入框时，`W` 观看、`R` 开录/停录、`F` 刷新。

### 页面联动

- 「打开媒体库录像」：App 把 `roomId` seed 传给 `MediaPage`，直接进入该房间录像列表。
- 「相关任务」：App 把 `roomId` seed 传给 `TasksPage`，客户端按 `TaskRecord.roomId` 过滤，并显示可清除的「仅看该房间」chip。
- 「在浏览器打开」：调用 `open_url`。

## 6. 已知限制

- **实时大小是轮询**：3 秒一次，刚开录文件尚未创建时显示「—」；「预计可录」依赖文件持续增长，暂停写入时不显示。
- **磁盘剩余走平台 FFI**：Windows `GetDiskFreeSpaceExW`、Unix `statvfs`；路径不可用时返回 0。
- **规则只门禁自动录制**：手动开录始终可用；标题规则不阻止观看。
- **通知覆盖在开录时快照**：录制中修改只影响下一场。
- **任务过滤是客户端最近 100 条**：`taskBoard(100)` 之后按 roomId 过滤，更早的任务需要扩大上限。
- **备注按直播间保存**：备注是直播间级自由文本，不限定主播 ID；同一主播多房间不会自动共享。
