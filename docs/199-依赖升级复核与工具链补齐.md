## 3. 安全审计

### 3.1 cookie 漏洞

升级前 `cargo audit` 命中：

```text
Crate:     cookie
Version:   0.18.2
ID:        RUSTSEC-2026-0594
Title:     Private cookie nonces repeat in forked processes
Severity:  medium (6.5)
Solution:  Upgrade to >=0.18.3
```

依赖链是 `tauri 2.12.7 → tauri-runtime → wry → cookie`。项目没有直接使用 `cookie` 的 `PrivateJar`，但升级成本很低，直接执行：

```bash
cd src-tauri
cargo update -p cookie --precise 0.18.3
```

`Cargo.lock` 中 `cookie` 已变为 0.18.3；没有改 `Cargo.toml`，因为它是传递依赖。

### 3.2 剩余 6 条 warning

复跑命令：

```bash
cd src-tauri
cargo audit --no-fetch --target-os macos
cargo audit --no-fetch --target-os windows
```

两个目标都是 **0 vulnerabilities / 6 allowed warnings**。逐条归属：

| crate | 版本 | 类型 | advisory | 依赖链 | 是否进入发布产物 | 处理 |
| --- | --- | --- | --- | --- | --- | --- |
| `chrono` | 0.4.45 | unmaintained | RUSTSEC-2026-0543 | 项目直接依赖 | 是 | 无修复版本；当前无已知漏洞，暂留并跟踪 |
| `proc-macro-error` | 1.0.4 | unmaintained | RUSTSEC-2024-0370 | Linux GTK / libappindicator / muda / tao | 否（macOS/Windows 不编译） | 等 Tauri Linux 栈升级 |
| `zbus_names` | 4.3.5 | unmaintained | RUSTSEC-2026-0371 | `tauri-plugin-notification` 的 Linux 后端 | 否 | 等 zbus 5 / 插件升级 |
| `zvariant` | 5.15.1 | unmaintained | RUSTSEC-2026-0370 | 同上 | 否 | 同上 |
| `zvariant_derive` | 5.15.1 | unmaintained | RUSTSEC-2026-0372 | 同上 | 否 | 同上 |
| `glib` | 0.18.5 | unsound | RUSTSEC-2024-0429 | Linux GTK | 否 | 修复要求 `glib >=0.20`，当前 Tauri Linux 栈仍锁 0.18；不在 macOS/Windows 产物中 |

说明：

- `cargo audit` 会扫描整个 `Cargo.lock`，即使目标平台不编译这些 crate，也会报告；因此 `--target-os macos/windows` 仍有 Linux 依赖的 warning。
- `chrono` 是唯一进入发布产物的 warning。它是 unmaintained 而不是「有漏洞」；在没有明确替代方案前不为了清零而迁移到 `time`，迁移会改动时间解析、序列化和时区行为，风险大于收益。
- 其余 5 条都来自 Linux 桌面集成，macOS 与 Windows 安装包不包含这些 crate。要彻底清除，需要等 Tauri 的 Linux 依赖链升级，或单独为 Linux 目标维护分支。

## 6. 固化的升级检查流程

新增 `scripts/check-deps.sh`，并在 `package.json` 增加 `check:deps`。

默认检查（不更新依赖、不改仓库源码）：

```bash
pnpm check:deps
```

等价于：

```text
node/pnpm/rustc/cargo 版本
pnpm install --frozen-lockfile
pnpm check:i18n
pnpm check:docs
pnpm build
cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --locked
cargo test --manifest-path src-tauri/Cargo.toml --locked
```

可选：

```bash
bash scripts/check-deps.sh --audit      # pnpm audit + cargo audit(macos/windows)
bash scripts/check-deps.sh --outdated   # pnpm outdated + cargo upgrade --dry-run
bash scripts/check-deps.sh --release    # 追加 .app 与 DMG
```

升级时的推荐顺序：

1. **盘点**：`pnpm outdated`、`cargo upgrade --dry-run --ignore-rust-version -vv`，记录「当前 / 最新 / 为什么不升」。
2. **分组**：前端补丁、前端 major、Rust 补丁、Rust 运行时 major、密码学 major、其余 major、工具链；每组单独提交。
3. **精确版本**：`package.json` 与 `Cargo.toml` 保持精确版本，不用 `^`/`~` 漂移；传递依赖只通过 lockfile 更新。
4. **API 适配**：按编译错误改代码，不顺手重构；每个 major 单独跑 `cargo test` / `pnpm build`。
5. **本地基线**：`pnpm check:deps`。
6. **安全与过期**：`bash scripts/check-deps.sh --audit --outdated`，把 warning 按「是否进入发布产物」分类。
7. **发布验证**：`bash scripts/check-deps.sh --release`，启动冒烟；有 Windows 条件时再触发 Actions 的 `workflow_dispatch`（`publish=false`）。
8. **文档**：更新 195/197/199，写清版本、命令、结果、未验证项，不只写「已升级」。

## 8. 仍未完成与风险

1. **Windows 真机构建未验证**。本机没有 `gh` CLI，也没有在 GitHub Actions 页面手动触发 `workflow_dispatch`。仓库里的 Windows job 仍是 `windows-2022` + `cargo build` + NSIS；静态配置已把 Rust 改成 1.100.0，但安装器没有实际产出。这是发布前最需要补的一项。
2. **没有逐页人工点击回归**。本轮只做了启动冒烟；任务中心、录制、四平台登录、设置页等页面的上一轮真机结果来自旧 release 二进制。编译器升级不改业务代码，但发布前仍应按页面矩阵点一遍。
3. **66 条 Clippy warning 仍在**。都是历史 warning（`assertions_on_constants`、`items_after_test_module` 等），不影响构建；建议单独开清理提交，不和依赖升级混在一起。
4. **6 条 RustSec warning 未清零**。其中 5 条只影响 Linux，1 条 `chrono` 进入发布产物但无已知漏洞。清零需要等上游或迁移时间库。
5. **GitHub Actions 本身没有真实跑过**。Node/pnpm/Rust 版本、lockfile、DMG/NSIS 脚本都只在本地验证；CI 缓存、runner 镜像、macOS 签名与 Windows 安装器仍需首次运行确认。
6. **发布产物仍是 ad-hoc 签名、macOS 仅 arm64**。与 195 一致，没有公证与 Intel 构建。
