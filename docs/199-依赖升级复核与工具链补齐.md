## 3. 安全审计

### 3.1 cookie 漏洞

升级前 `cargo audit` 命中：

```text
Crate:     cookie
Version:   0.18.2
ID:        RUSTSEC-2026-0594
Title:     Private cookie nonces repeat in forked processes
Severity:  medium (6.5)
Solution:  Upgrade to >=0.18.3
```

依赖链是 `tauri 2.12.7 → tauri-runtime → wry → cookie`。项目没有直接使用 `cookie` 的 `PrivateJar`，但升级成本很低，直接执行：

```bash
cd src-tauri
cargo update -p cookie --precise 0.18.3
```

`Cargo.lock` 中 `cookie` 已变为 0.18.3；没有改 `Cargo.toml`，因为它是传递依赖。

### 3.2 6 条上游 advisory 的显式豁免

上一轮把 6 条上游 warning 留在输出里，作为「未清零」的尾巴。这一轮先把能迁掉的迁掉，再把不能迁的逐条写进配置：

- 项目直接依赖从 `chrono 0.4.45` 换成 `jiff 1.0.2`（见 5.2）。业务代码不再调用 chrono。
- `Cargo.lock` 里仍会出现 `chrono 0.4.45`：`serde_with 3.24.0` 的 optional `chrono_0_4` 依赖会把它写进 lock，但没有任何 feature 启用它，`cargo tree -i chrono --locked` 输出 “nothing to print”，实际不编译，也不会进入产物。
- 新增 `src-tauri/.cargo/audit.toml`，在 `[advisories] ignore` 中列出 6 条 advisory，每条都写明为什么当前不能由本项目修复。

验证命令与结果：

```bash
cd src-tauri
cargo audit --no-fetch --target-os macos
# 输出：0 条 advisory，exit 0
```

逐条归属：

| crate | 版本 | 类型 | advisory | 依赖链 | 是否进入发布产物 | 处理 |
| --- | --- | --- | --- | --- | --- | --- |
| `chrono` | 0.4.45 | unmaintained | RUSTSEC-2026-0543 | `serde_with` 的 optional `chrono_0_4`，无 feature 启用 | 否（实际不编译） | 已把直接依赖迁到 `jiff`；lock 条目待上游移除 |
| `proc-macro-error` | 1.0.4 | unmaintained | RUSTSEC-2024-0370 | Linux GTK / libappindicator / muda / tao | 否（macOS/Windows 不编译） | 等 Tauri Linux 栈升级 |
| `zbus_names` | 4.3.5 | unmaintained | RUSTSEC-2026-0371 | `tauri-plugin-notification` 的 Linux 后端 | 否 | zbus_names 已并入 zbus，等插件升级 |
| `zvariant` | 5.15.1 | unmaintained | RUSTSEC-2026-0370 | 同上 | 否 | 同上 |
| `zvariant_derive` | 5.15.1 | unmaintained | RUSTSEC-2026-0372 | 同上 | 否 | 同上 |
| `glib` | 0.18.5 | unsound | RUSTSEC-2024-0429 | Linux GTK | 否 | 修复要求 `glib >=0.20`，Tauri 2.12.7 仍锁 gtk 0.18；不在 macOS/Windows 产物中 |

说明：

- 这些是 **显式豁免**，不是把告警隐藏掉：配置在仓库里，原因逐条可查。新增豁免必须同时写清为什么不能升级或迁移。
- `cargo audit` 会扫描整个 `Cargo.lock`，即使目标平台不编译这些 crate 也会报告；因此不能靠 `--target-os` 自动消掉 Linux 依赖。
- 5 条来自 Linux 桌面集成，macOS 与 Windows 安装包不包含这些 crate。要彻底清除，需要等 Tauri 的 Linux 依赖链升级，或单独为 Linux 目标维护分支。
- 后续若 Tauri / zbus / glib 升级，应先删除对应 ignore 并复跑 `cargo audit`，确认真的不再命中。

### 5.1 Clippy 66 → 0

先跑自动修复：

```bash
cargo clippy --manifest-path src-tauri/Cargo.toml --fix --all-targets --locked
cargo fmt --manifest-path src-tauri/Cargo.toml --all
```

自动修掉 48 项，剩余手工处理。主要类别与改法：

- `needless_range_loop` / `explicit_iter_loop`：改迭代器或 `by_ref()`，例如 `filename.rs` 的模板解析。
- `too_many_arguments`：IPC 命令和聚合入口保持扁平参数，加 `#[allow]` 并注释为什么拆结构体不合适（`room_set_rules`、`media_list`、`build_incidents`、`ViewManager::start_once`）。
- `unnecessary_cast` / `unnecessary_min_or_max`：去掉无意义转换；`MediaFilter.offset` 是 `usize`，不再 `.max(0)`。
- `manual_div_ceil`、`manual_is_multiple_of`、`manual_range_contains`、`needless_lifetimes`、`redundant_closure` 等按建议改写。
- `items_after_test_module`：把 `platform/mod.rs` 的测试模块移到文件末尾，测试内容不变。
- 排序统一改 `sort_by_key(|x| Reverse(...))`；`recorder.rs` 的 `ended` 用 `type EndedRecord = (Instant, Option<i64>, bool)` 降低类型噪声，逻辑不变。
- `task_center.rs` 把两个 `all_ended` 分支合并为 `all_ended && (post_state == "skipped" || abnormal_abort || interrupted_abort)`，条件等价。

最终：

```bash
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --locked
# Finished `dev` profile ...；0 warning
```

### 5.2 chrono → jiff

`chrono 0.4.45` 进入产物带来的唯一问题是 RUSTSEC-2026-0543（unmaintained），不是已知漏洞。上一轮判断「迁移风险大于收益」，这一轮把迁移范围压到最小：

- `Cargo.toml` 删除 `chrono`，新增 `jiff = { version = "=1.0.2", default-features = false, features = ["std", "tz-system"] }`。
- 新增 `src-tauri/src/clock.rs`，只暴露业务需要的 7 个函数：`now_secs`、`now_ms`、`local_now`、`local_at`、`format_local_opt`、`format_now_local`、`parse_cn_naive`。页面、平台、后处理不再各自处理时区。
- `logging.rs` 的本地日期分片、跨天滚动、保留清理改用 `jiff::civil::Date` 与 `Span`；日志时间格式仍为 `%Y-%m-%d %H:%M:%S%.3f %:z`，真机输出 `2026-11-24 21:10:04.029 +08:00`。
- `platform/bilibili.rs` 的 `LiveTime::Text` 走 `parse_cn_naive`（按 UTC+8 解析不带时区的北京时间）；`platform/http.rs` 的 RFC 2822 解析改用 jiff；CSV 导出、文件名模板、回收站 `.trashinfo`、合并文件名全部走 `clock`。
- 验证：`cargo test --locked` 455 passed；真机录制生成的文件名时间、任务时间线、CSV 时间均为本地时间。

`Cargo.lock` 中仍保留 `chrono 0.4.45` 条目，原因见 3.2：它是 `serde_with` 的可选依赖，没有 feature 启用，`cargo tree -i chrono --locked` 无依赖边。不要把「lock 里有」误判为「产物里有」。

## 6. 固化的升级检查流程

新增 `scripts/check-deps.sh`，并在 `package.json` 增加 `check:deps`。

默认检查（不更新依赖、不改仓库源码）：

```bash
pnpm check:deps
```

等价于：

```text
node/pnpm/rustc/cargo 版本
pnpm install --frozen-lockfile
pnpm check:i18n
pnpm check:docs
pnpm build
cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --locked
cargo test --manifest-path src-tauri/Cargo.toml --locked
```

可选：

```bash
bash scripts/check-deps.sh --audit      # pnpm audit + cargo audit(macos/windows)
bash scripts/check-deps.sh --outdated   # pnpm outdated + cargo upgrade --dry-run
bash scripts/check-deps.sh --release    # 追加 .app 与 DMG
```

升级时的推荐顺序：

1. **盘点**：`pnpm outdated`、`cargo upgrade --dry-run --ignore-rust-version -vv`，记录「当前 / 最新 / 为什么不升」。
2. **分组**：前端补丁、前端 major、Rust 补丁、Rust 运行时 major、密码学 major、其余 major、工具链；每组单独提交。
3. **精确版本**：`package.json` 与 `Cargo.toml` 保持精确版本，不用 `^`/`~` 漂移；传递依赖只通过 lockfile 更新。
4. **API 适配**：按编译错误改代码，不顺手重构；每个 major 单独跑 `cargo test` / `pnpm build`。
5. **本地基线**：`pnpm check:deps`。
6. **安全与过期**：`bash scripts/check-deps.sh --audit --outdated`，把 warning 按「是否进入发布产物」分类。
7. **发布验证**：`bash scripts/check-deps.sh --release`，启动冒烟；有 Windows 条件时再触发 Actions 的 `workflow_dispatch`（`publish=false`）。
8. **文档**：更新 195/197/199，写清版本、命令、结果、未验证项，不只写「已升级」。
