## 3. 本轮修复

### 3.1 手选 HLS/TS 线路起播失败

**现象**：观看 2K 后把线路切到 `d1--cn-gotcha104.bilivideo.com`，日志连续 `观看起播超时（12 秒内没有输出分片）`，UI 显示 `ffmpeg failed：起播超时`。

**定位**：同一 Cookie 拉该线路 m3u8，ffmpeg 直接解码 3 秒成功，排除 CDN 死链。问题在 `/Users/joftal/Library/Caches/com.hivecast.desktop/view/ffmpeg.log`：

```
[mp4] Malformed AAC bitstream detected: use the audio bitstream filter 'aac_adtstoasc' to fix it
[out#0/hls] Error muxing a packet
```

B 站 TS 线路音频是 AAC-ADTS，回环封装为 fMP4 时必须转 ASC；FLV 源本身是 ASC，加同一 bsf 无害。

**修复**：`src-tauri/src/view.rs:755` 在 `-c copy` 后加 `-bsf:a aac_adtstoasc`。

**复验**：同一条 104 线路日志出现 `观看起播 ... quality=2K · TS · H.264 line=d1--cn-gotcha104...`，截图分辨率 2560×1440。

### 3.2 不存在的房间被报成「响应解析失败」

**现象**：输入 `999999999`，toast 显示「操作失败 / 响应解析失败」，并带出内部 API URL。

**定位**：接口 HTTP 200 返回 `{"code":1,"msg":"未找到该房间","data":[]}`；原 `Envelope<RoomInfoData>` 的 `data: Option<T>` 无法把数组反序列化成对象，先报 `error decoding response body`。

**修复**：`src-tauri/src/platform/bilibili.rs:73` 新增宽松 `RoomInfoEnvelope { code, message, data: Option<serde_json::Value> }`；`:79` 新增 `parse_room_info`：

- code ≠ 0 且（-400/-404 或 message 含「未找到」「不存在」）→ `PlatformError::RoomNotFound`；
- code = 0 但 data 为 null/空数组 → `RoomNotFound`；
- 其他 code → `PlatformError::Upstream`；
- 对象 payload 再 `serde_json::from_value`，失败才报格式异常。

`room_info` 改用该 envelope + `parse_room_info`。单测 `:912` 与 `:926` 覆盖数组错误与正常对象。

**复验**：toast「操作失败 / 房间不存在：999999999」，日志同类文案，不再出现「响应解析失败」或 URL。

### 3.3 录制中「已写入 —」

**现象**：录制 1:16:03 的 LPL 房间，抽屉「已写入」为「—」，实际磁盘已有 77 个 `.partNNNN.ts` 共 2,112,608,264 B。

**根因**：ffmpeg 录制固定写 segment/mpegts，主 `.flv` 要停止后才合并；`recording_usage` 只 `metadata(session.file_path)`，录制中主文件不存在。

**修复**：`src-tauri/src/commands.rs:890` 改为 `master.max(crate::segment::parts_total(path))`，主文件与分片不重复计算；`src-tauri/src/segment.rs` 新增 `parts_total_sums_every_remaining_part`。

**复验**：抽屉实时 121.6 MB → 236.8 MB；停止后 77 片合并成功。

### 3.4 文件名预览固定 `.mp4`

**现象**：后处理为「保留源封装」时，存储页预览仍以 `.mp4` 结尾，实际落盘 FLV/TS。

**修复**：

- `src-tauri/src/commands.rs:1666` `filename_preview` 新增 `ext: Option<String>`，清洗扩展名（去点、仅 ASCII 字母数字、空则 flv）；
- `src/lib/ipc.ts:345` 传 `ext`；
- `src/features/settings/SettingsView.tsx:520` 按 `postMode` 计算：convert → 目标封装，custom → 自定义输出扩展名，否则 flv；
- 中英文提示追加「预览扩展名按当前后处理设置生成；保留源封装时以实际源流为准」。

**复验**：预览以 `.flv` 结尾，英文提示完整。

### 3.5 托盘提示错位

**现象**：「关闭窗口不会退出，应用会留在托盘继续录制」出现在外观与语言页。

**修复**：从 `SettingsView.tsx` 的 appearance 分支移到 system 分支「关闭主窗口时」行之后。

### 3.6 英文界面表格截断

**现象**：1166 宽窗口下，Note 列「Add a note f...」、Quality「Follow glo...」、搜索占位被截断，录制状态列显示「Recordi...」。

**修复**：

- `src/i18n/en-US.json`：`monitor.qn.0` → `Global`；`searchPlaceholder` → `Search host, title, or note`；`addNote` → `Add note`；
- `src/features/monitor/MonitorPage.tsx:60` COLUMNS 改为 `120px 58px 80px 58px minmax(0,1fr) 104px 104px 74px 120px 140px`，录制状态列 60→80。

**复验**：英文下 Add note / Global / Search 占位 / Recording 均完整；主播名与标题仍按设计省略号截断。

### 3.7 英文存储页混入中文

**现象**：英文界面回收站卡片出现「删除后可在「访达→废纸篓」中还原…」。

**根因**：后端 `src-tauri/src/post.rs:1167` 返回硬编码中文 note，前端直接渲染。

**修复**：`SettingsView.tsx:1365` Windows 用 `t("settings.trashLocationWindows")`；`:1370` 改渲染 `t("settings.trashNote")`；中英文新增两键。

**复验**：英文显示 `~/.Trash` 与 `Files can be restored directly from the system recycle bin...`，无中文。

### 3.8 防休眠在空闲时仍阻止休眠

**现象**：开启「阻止系统休眠」并保存后，即使没有录制/观看，`pmset -g assertions` 仍出现 `PreventUserIdleSystemSleep named: "HIVECAST is recording or watching"`。

**根因**：`src-tauri/src/settings.rs:483` 只按设置值直接 `power::apply`，未结合录制/观看活动。

**修复**：

- `src-tauri/src/power.rs:180` 增加 `HELD AtomicBool`，`apply` 幂等，状态不变不碰系统 API；
- `settings.rs` 删除直接 apply，改由后台任务计算；
- `src-tauri/src/lib.rs:152` 新增 2 秒轮询 supervisor：读 `KEY_PREVENT_SLEEP`，`busy = recorder.active_count() > 0 || recorder.starting_count() > 0 || !view.snapshot().is_empty()`，再 `power::apply(wanted && busy)`；
- `recorder.rs:402` `starting_count` 改 `pub(crate)`。

**复验**：开关开启 + 空闲 → `NO_ASSERTION`；自动开录后出现；停止后 2 秒内消失；观看起播后再次出现。
