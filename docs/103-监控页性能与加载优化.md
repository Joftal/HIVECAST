# 103-监控页性能与加载优化

> 状态：v1 已实施（2026-11-09）；前端编译、Rust 检查与开发库 SQL 验证通过，真实窗口的大数据量表现待继续观察。
> 范围：监控页六项性能与加载优化：行渲染、单飞加载、搜索防抖、详情分页、首次加载重试、最近录制反范式化。
> 前置阅读：`101-监控列表细节优化.md`、`102-搜索清除与添加房间反馈.md`。

## 0. 结论速览

- **离屏行跳过渲染**：`.monitor-row` 使用 `content-visibility: auto` + `contain-intrinsic-size: 76px`，100+ 房间时不再为所有行做完整布局/绘制，DOM 数量保持不变。
- **加载单飞**：`rooms://changed` 仍做 200ms 合并；`load()` 内部保证同一时刻只有一条 `rooms_list`，期间的刷新请求合并成一次尾随刷新，不再递归重排定时器。
- **搜索/排序减负**：输入 120ms 防抖后再过滤，`Intl.Collator` 按语言缓存；连续输入不会每键全量 sort。
- **详情按页拉取**：打开抽屉先取 `SessionSummary` + 第一页 50 场；「加载更多」按 offset 追加。合计与可合并数来自汇总，不受分页影响。
- **加载失败可重试**：首次加载失败显示持久错误态 + 重试按钮，后台刷新失败仍只弹一次 toast。
- **最近录制已反范式化**：`room` 表直接保存最近一场的 id/开始时间/时长，监控列表不再单独查 sessions；`latest_sessions` 命令已删除。

## 1. 行渲染

- 列表行加 `.monitor-row`：`content-visibility: auto`、`contain-intrinsic-size: 76px`（行高固定 76px）。
- 这不是虚拟列表：`shown.map(renderRow)` 仍会挂载全部行，但离屏行会跳过内容布局与绘制，滚动到附近时才恢复。
- 保留共享 1s tick + `LiveDuration`，录制时钟只重渲染自己，页面不会每秒全量 render。
- 选择「不引入虚拟列表」的原因：现有行内有多选、菜单、缩略图和预览交互，`content-visibility` 改动面小、视觉零变化，先覆盖主要收益。

## 2. 事件合并与单飞加载

- `requestReload`：每次 `rooms://changed` 重置 200ms 定时器，窗口内只触发一次 `load()`。
- `load()` 用 `loadInFlight` / `loadQueued` 两个 ref 实现单飞：
  - 已有请求在途时，新请求只置 `loadQueued = true` 并立即返回。
  - 当前请求结束后检查 `loadQueued`，有则再跑一轮（`do…while`），不会并发、也不会丢刷新。
- 初次进入页面直接 `load()`；添加/删除/开关等操作后的 `await load()` 仍即时刷新。
- 后台加载失败仍走 `loadErrorShown` 去重，只提示一次。

## 3. 搜索防抖与排序缓存

- `queryInput` 是输入框的即时值，`query` 是 120ms 防抖后的过滤值；清空输入立即同步清空过滤条件，不等防抖。
- `Intl.Collator(locale, { numeric: true })` 用 `useMemo` 按语言缓存，排序不再每次按键新建 collator。
- 过滤/排序仍是客户端全量计算，只是降低了触发频率与单次成本。

## 4. 详情抽屉分页

- 打开详情时并行请求：
  - `session_summary(roomId)` → `SessionSummary { total, totalBytes, mergeable }`。
  - `sessions_list(roomId, 50, 0)` → 第一页录制。
- 抽屉底部「加载更多」按 `offset = 已加载数量` 追加，每页 50 场，按钮只在 `已加载 < total` 时显示。
- 合计录制体积、可合并数直接读汇总，不再依赖当前已加载的页面。
- `session_summary.mergeable` 统计 `status != 'recording'` 且 `file_path` 非空的场次，与合并可用条件一致。
- 房间合并命令 `room_merge_sessions` 改为分页读完该房间全部历史（单页 500），避免超过单页上限时漏掉旧片段。

## 5. 首次加载失败重试

- `loaded` 控制首次加载指示；`loadFailed` 记录最近一次加载是否失败。
- 首次加载失败且没有任何房间数据时，内容区显示 `PageEmpty`（标题/说明 + 「重试」按钮），而不是只闪一次 toast 后落入空态。
- 重试会清空 `loadFailed`、重置 `loaded` 并重新调用 `load()`；已有数据时的后台失败继续只提示 toast，不清空表格。

## 6. 最近录制反范式化

`room` 表新增三列：

```sql
last_session_id TEXT,
last_session_started_at INTEGER,
last_session_duration_ms INTEGER NOT NULL DEFAULT 0
```

- 新库建表直接包含；老库由 `migrate()` 按 `PRAGMA table_info(room)` 缺列补齐，并在补列后批量回填一次，避免升级后「最近录制」全空直到房间再次产生 session。
- `refresh_room_last_session(conn, room_id)` 用 `ORDER BY started_at DESC, id DESC LIMIT 1` 重算摘要。
- 刷新时机：会话创建、分割片段创建、收尾/后处理更新、删除会话、启动时 orphan 会话清理。
- `RoomRecord` / `RoomRecord.ts` 暴露 `lastSessionId`、`lastSessionStartedAt`、`lastSessionDurationMs`；监控列表用 `lastByRoom` 直接从房间构建。
- 删除 `latest_sessions` 命令、IPC 与前端 `latestSessions()`；初始加载只剩一次 `rooms_list`。
- 依赖现有 `idx_record_session_room (room_id, started_at DESC)`，每次刷新是单房间索引查找。

## 8. 已知限制

- **仍是 content-visibility 而非虚拟列表**：极端数量（500+）时 DOM 节点与 React fiber 仍线性增长，如需进一步优化再做窗口化。
- **搜索/排序仍是客户端全量**：已做防抖和 collator 缓存，但每次过滤仍遍历全部房间。
- **详情分页只减少首屏**：加载更多会持续追加 DOM；单房间上千场时仍建议限制或虚拟化。
- **事件加载仍是全量房间列表**：`roomsList()` 没有分页，极端大量房间时 payload 与 JSON 解析仍会增长。
- **反范式化是冗余字段**：摘要依赖上述写入路径维护；若未来新增绕过 `Db` 的 session 写入口，需要同时调用 `refresh_room_last_session`。
