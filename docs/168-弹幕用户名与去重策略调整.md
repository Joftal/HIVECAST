# 弹幕用户名与去重策略调整

- 日期：2026-11-17
- 范围：哔哩哔哩、斗鱼、抖音三平台的弹幕落盘、实时浮层、ASS 导出与合并回放。
- 结论：三平台普通聊天不再记录、也不再显示用户名；礼物、SC、上舰保留发送者。三平台不再做弹幕去重，平台重复下发的帧原样保留。

## 1. 需求

用户要求：

1. 斗鱼、哔哩哔哩、抖音的弹幕不显示用户名；只有礼物、SC、上舰这类特殊事件需要记录和显示用户名，普通文本弹幕不需要记录、显示。
2. 这三个平台先不做弹幕去重，优先完整记录所有弹幕。

## 2. 调整前的实际行为

- 实时浮层 `/Library/dshproject/HIVECAST/src/features/watch/DanmakuCanvas.tsx:63` 的 `labelOf()` 已经只对非 chat 事件拼「用户名：」；普通聊天只显示正文。
- ASS 导出 `/Library/dshproject/HIVECAST/src-tauri/src/postprocess.rs:374` 也只在 `kind != "chat"` 时加发送者前缀。
- 缺口在数据层：JSONL 落盘和实时批次仍携带 chat 的 `u` 字段；旧数据回放虽然不显示，但文件里仍能读到发送者。
- 去重只存在于斗鱼礼物：`RoomConn.recent_gifts` + `duplicate_gift()`，同发送者、同内容、1 秒内的礼物帧会被丢弃；B 站与抖音没有去重。

## 3. 实现

### 3.1 普通聊天清空用户名

`/Library/dshproject/HIVECAST/src-tauri/src/danmaku.rs:849` 新增：

```rust
fn drop_chat_user(platform: &str, message: &mut DanmakuMessage) {
    if message.kind == "chat" && matches!(platform, "bilibili" | "douyu" | "douyin") {
        message.user = None;
    }
}
```

`accept()` 在写入时间戳后、`fan_out()` 之前调用它（同文件 :868）：

```rust
message.offset_ms = conn.started.elapsed().as_millis() as i64;
drop_chat_user(&conn.room.platform, &mut message);
conn.fan_out(&message);
```

因此实时批次与 JSONL 都不再带聊天用户名；礼物、SC、上舰保持原样。虎牙不在本次三平台范围内，行为不变。

### 3.2 JSONL 省略空用户名

`RecordWriter::push`（同文件 :395）先构造 `{"t","k","c","col"}`，只有 `message.user` 为非空 `Some` 时才插入 `"u"`：

```rust
let mut line = json!({
    "t": offset,
    "k": message.kind,
    "c": message.content,
    "col": message.color,
});
if let Some(user) = message.user.as_deref().filter(|user| !user.trim().is_empty()) {
    line["u"] = json!(user);
}
```

当前三平台聊天行形如：

```json
{"t":25585,"k":"chat","c":"你问我啊，我懂个蛋","col":16777215}
```

礼物行仍保留发送者：

```json
{"t":16636,"k":"gift","c":"粉丝荧光棒 x96","col":16762972,"u":"SKT丶飒布"}
```

### 3.3 移除斗鱼礼物去重

删除 `RoomConn.recent_gifts` 字段及初始化、`duplicate_gift()`、`accept()` 中的斗鱼礼物去重分支，以及对应单测。`accept()` 保留原有注释：

> 不去重：平台重复下发的帧也原样保留，先保证事件完整。

限流仍然存在，但落盘在限流之前（`fan_out()` 先写 writer，再判断 `MAX_PER_SECOND`），所以即使实时浮层限流，JSONL 仍尽量完整。磁盘写入失败与 0 字节清理逻辑未改。

## 4. 兼容性

- `u` 字段本来就是可选的：`media_danmaku` 用 `value["u"].as_str()` 读取，缺失时为 `None`；前端 `DanmakuMessage.user` 也是可选。
- 旧 JSONL 里 chat 仍带 `u`，回放时 `DanmakuCanvas` 与 ASS 导出仍按 `kind == "chat"` 忽略它，不会把用户名显示出来。
- 媒体库弹幕轨、合并弹幕、ASS 导出都不依赖 `u` 是否存在；合并只累加时间偏移，没有按内容去重。
- 数据库 schema 无变化，不需要迁移。

### 5.2 真机录制（斗鱼 138243，2026-11-17）

使用 release bundle，`record.split_on_title=false`，录制两段：

| 文件 | 事件 | chat | chat 带 `u` | gift | gift 带 `u` |
| --- | ---: | ---: | ---: | ---: | ---: |
| 01:25:38 场 | 19 | 15 | 0 | 4 | 4 |
| 01:29:40 场 | 7 | 2 | 0 | 5 | 5 |

实际行：

```json
{"c":"你问我啊，我懂个蛋","col":16777215,"k":"chat","t":25585}
{"c":"粉丝荧光棒 x96","col":16762972,"k":"gift","t":16636,"u":"SKT丶飒布"}
```

同一场 ASS 中，聊天行没有发送者前缀，礼物行有：

```
Dialogue: ...,{\move(1280,20,-378,20)\c&H00FFFFFF&}你问我啊，我懂个蛋
Dialogue: ...,{\an8\pos(640,20)\c&H005CC8FF&}SKT丶飒布：粉丝荧光棒 x96
```

第一段中「驴酱杯加油」连续出现 3 次，均保留在 JSONL 与 ASS 中，证明斗鱼礼物去重移除后不会再合并重复帧。B 站与抖音的清空逻辑由同一 `drop_chat_user()` 覆盖，并由三平台参数化单测锁定；本轮未再占用直播时长做重复真机录制。

## 6. 影响与边界

- 实时浮层、媒体库回放、ASS 导出均不会再显示普通聊天用户名；礼物/SC/上舰仍显示。
- 平台重复下发的聊天或礼物会重复落盘、重复显示，这是当前「先完整记录」策略的预期结果。
- 聊天用户名不再写入 JSONL 后，无法从录像文件反查某条普通弹幕的发送者；礼物/SC/上舰不受影响。
- 实时浮层仍有每房间每秒 `MAX_PER_SECOND` 条限流；它只影响浮层批次，JSONL 在限流前写入。
- 跨平台协议里若以后新增普通文本类型，需要同步扩展 `drop_chat_user()` 的判断，否则可能重新带回用户名。
