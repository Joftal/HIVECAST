# 斗鱼关注导入与批量状态轮询

> 2026-11-14，2026-11-16 修订。范围：斗鱼关注列表导入、监控批量状态发现、导入去重与界面呈现。数量门槛与登录态降级以 [166](166-斗鱼单房批量与三平台登录态降级.md) 为准。
> 目标：斗鱼和哔哩哔哩一样，能一次导入关注、按房间号去重，并在房间多时用一次关注列表请求刷新全部状态，而不是每 30 秒对每个房间打一次 `betard`。

## 1. 结论

斗鱼关注导入与批量状态轮询已落地，并完成 macOS 真机验证：

- 登录态一次拉取 177 位关注、2 页（120 + 57），导入时不再逐房请求。
- 关注列表直接带直播状态、标题、主播、分区、人气、头像、封面和 `videoLoop`，导入后监控表立即有数据。
- 监控侧在「斗鱼已登录」时，每个检测拍点只请求一次关注列表，批量刷新全部斗鱼房间；不再限制房间数量，1 个斗鱼房间也走批量。未登录仍逐房匿名 `betard`。
- 批量结果里缺失的房间不会被判离线，会回退单房检查；整批失败会全量降级单房；限流则整平台短冷却。
- 真机 3 个斗鱼房间：每 30 秒一次关注列表请求，`keys=3 returned=3 live=3`，耗时 206–271ms；监控表人气随批次更新。
- 顺带修复了全局 CSP：此前 `img-src` 不含 `https:`，所有平台的远程头像/封面都被 WebView 拦截，监控表和导入弹窗只显示空白圆环/灰块。现在 `https:` 图片可加载，斗鱼封面与头像在真机正常显示。

## 2. 斗鱼关注接口

文件：`/Library/dshproject/HIVECAST/src-tauri/src/platform/douyu_follow.rs`

```text
GET https://www.douyu.com/wgapi/livenc/liveweb/follow/list?sort=0&cid1=0&limit=120&page=1
Referer: https://www.douyu.com/directory/myFollow
```

- 每页硬上限 120 条，传更大也只返回 120；`pageCount` 与 `total` 都由响应给出。
- 模块最多读 20 页，防止异常账号把一次批量拖成几十页；超出部分由单房检查兜底。
- 未登录返回 `error=-1`，不能把任何房间判成离线。
- 直播判定是 `show_status == 1 && videoLoop == 0`。轮播录像的 `show_status` 也是 1，必须排除，否则会 7×24 一直录。
- `online` 可能是数字或 `"475.4万"` / `"1.2亿"` 字符串，统一解析成整数；解析失败只丢这一项，不阻断导入。
- 标题和主播名里的 `&amp;`、`&#20320;` 等 HTML 实体做常见实体解码。

关键函数：

- `douyu_follow.rs:75 FollowItem::into_status`：字段映射、轮播过滤、开播时间、人气解析。
- `douyu_follow.rs:112 fetch_follow_page`：单页拉取与 envelope 校验。
- `douyu_follow.rs:157 fetch_live_statuses`：按房间号集合跨页查找，只返回关注列表里找到的房间。

## 3. 导入链路

文件：`/Library/dshproject/HIVECAST/src-tauri/src/commands.rs`

- `commands.rs:305 douyu_follow_page`：IPC 命令，把平台错误映射成用户可读错误。
- `commands.rs:295 map_douyu_error`：`error=-1` 映射为「斗鱼登录已失效，请重新扫码登录」。
- `commands.rs:315 import_room_info`：斗鱼 extra 写 `roomId / liveStatus / videoLoop`，不伪造 `uid`。
- `commands.rs:352 rooms_import`：按平台泛化。

斗鱼的导入规则：

| 项目 | 规则 |
| --- | --- |
| 去重键 | `room_key`（斗鱼房间号）；斗鱼没有独立关注 UID，`platform_uid` 留空 |
| 规范化 URL | `https://www.douyu.com/{room_id}` |
| 已存在 | 只刷新标题、主播、头像、封面、分区、在线、直播状态，不覆盖用户的备注/标签/规则 |
| 软删除 | 导入时恢复，并重新挂监控 |
| 默认监控 | 开（弹窗「导入后监控」默认开） |
| 默认自动录制 | 关（弹窗「导入后自动录制」默认关；开启后只对正在直播的场次立即开录） |
| 轮播 | `videoLoop=1` 不算直播，不自动开录 |

B 站原有的短号归一、UID 合并、rekey 逻辑保留；只有 B 站走 `platform_uid` 合并，斗鱼不会被 B 站 UID 规则误伤。单测 `douyu_import_keeps_video_loop_without_a_uid` 覆盖「斗鱼导入不写 platform_uid 且保留 videoLoop」。

## 4. 批量状态轮询

文件：`/Library/dshproject/HIVECAST/src-tauri/src/monitor.rs`

- `monitor.rs:96 BatchState`：按平台保存 `at / interval / inflight / not_before`，B 站与斗鱼各自独立，不再共用一个全局批量变量。
- `monitor.rs:259 douyu_batch_ready`：只要求斗鱼登录态 `ok`，不再数房间；1 个房间也批量。
- 2026-11-16 起删除 `DOUYU_BATCH_MIN_ROOMS = 3`；旧的「1–2 个房间单查更准」结论作废，原因见 [166](166-斗鱼单房批量与三平台登录态降级.md)。
- `monitor.rs:716 run_batch_check`：
  - 斗鱼键是 `room_key`；B 站键仍是 `platform_uid`。
  - 一次 `fetch_live_statuses`；命中房间走 `batch_room_info` + `check_room_info_deferred`。
  - 未命中房间收集后并发单房 `run_check`，不会把「关注列表没返回」当成离线。
  - `Err(is_rate_limited)`：整平台冷却 `retry_after`，不放大请求。
  - `Err(is_auth_expired)`：登录态失效，本拍全量降级并发单房检查，不暂停平台。
  - `Err(is_risk_blocked)`：明确风控，整平台暂停 120 秒，不放大成 N 个单房请求。
  - 其他错误：全量降级单房检查。
- `monitor.rs:863 batch_room_info`：批量状态只覆盖平台能提供的字段，保留本地封面、头像、备注、标签、规则；开播时间优先用平台真实值，缺失才沿用旧值。

批量拍点与房间监控间隔共用同一个调度窗口，不会因为批量而额外增加拍点。真机日志：

```text
15:54:21 INFO 批量状态检查开始 platform="douyu" rooms=3 interval_sec=30
15:54:21 DEBUG GET /wgapi/livenc/liveweb/follow/list?...&page=1
15:54:21 INFO 批量状态检查完成 platform="douyu" rooms=3 keys=3 returned=3 live=3 missing=0 elapsed_ms=271

15:54:51 INFO 批量状态检查完成 ... elapsed_ms=206
15:55:21 INFO 批量状态检查完成 ... elapsed_ms=212
```

三个房间每 30 秒只有 1 个关注列表请求；此前是每 30 秒 3 个 `betard/{room_id}`。

## 6. CSP 修复：远程头像与封面

真机验证斗鱼导入时发现监控表和导入弹窗的头像、封面全是空白。数据库里的 URL 是正常的：

```text
https://apic.douyucdn.cn/upload/avatar_v3/202010/..._big.jpg
https://rpic.douyucdn.cn/live-cover/appCovers/2026/11/09/...jpg/dy1
```

用 `curl` 与 Safari 都能打开，但应用内不显示。根因是 `src-tauri/tauri.conf.json:28`：

```text
img-src 'self' data: blob:
```

WebView 的 CSP 直接拦截了所有远程图片。改为：

```text
img-src 'self' data: blob: https:
```

只放宽图片加载，`script-src`、`connect-src`、`media-src` 不变。重新构建后真机确认：监控表三行斗鱼封面、圆形头像都出来了；导入弹窗的 B 站与斗鱼头像也都正常。

影响范围是所有平台，不只斗鱼：此前 B 站关注导入、监控表头像同样被拦截，只是灰色占位不容易被注意到。

## 8. 边界与限制

- **只覆盖关注列表里的房间**。用户导入后取关、或关注数超过 20 页，批量结果会缺失；缺失房间会回退单房 `betard`，不会误判离线。
- **批量只做状态发现**。取流、画质、线路、Cookie、录制、弹幕仍走原有单房链路，本次没有改斗鱼播放/录制协议。
- **30 秒是状态新鲜度上限**。批量拍点受监控间隔与抖动控制，刚开播/刚下播最多滞后一个拍点。
- **封面 CDN 首次加载可能慢**。真机 Safari 首次打开同一张封面也用了数秒；应用会在图片到达后替换占位，不影响状态与操作。
- **未登录或关注列表接口失败**时不启用批量，按单房检查；不会用空列表覆盖在线状态。
- **完整扫码登录仍需手机确认**；本轮没有新增扫码逻辑，沿用 docs/154 的扫码与续期链路。
