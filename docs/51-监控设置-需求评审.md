# 51-监控设置-需求评审

> 状态：v0.1 评审稿（2026-11-06），**未实施**。确认口径后再进入开发。
> 范围：监控间隔与自动回退、录制目录、文件名模板、添加直播间默认开关。

## 0. 结论速览

- 四条需求都可行，没有需要推翻的设计；但有 4 个口径必须先定（见 §7），其中「间隔 0」和「默认目录」会直接影响实现。
- **不需要新增独立页面**。录制目录已经在「设置 → 存储」，添加房间已经有弹窗；再做一个「监控设置」页会出现第二套目录/画质入口，正好违反「不要有多余入口」。
- 建议落点：监控间隔与回退放「录制与观看」，文件名模板放「存储」（紧挨目录），两个开关放「添加直播间」弹窗。
- 三件最该先修的隐藏问题：① 监控是串行轮询，一个慢房间会拖住全部；② broker 的 15 秒房间信息缓存会吃掉小间隔；③ 同名文件会被 `-y` / `File::create` 静默覆盖，视频和弹幕一起没。

## 2. 参考项目怎么做（bililive-go）

| 机制 | 实现 | 取值 |
| --- | --- | --- |
| 检测间隔 | `config.Interval`，可被平台级、房间级覆盖 | 默认 30 秒；`Verify()` 要求大于 0，**不接受 0** |
| 连续失败退避 | `failureBackoffInterval`：每次失败翻倍，成功清零 | 上限 `max(5 分钟, 配置间隔)` |
| 平台访问最小间隔 | `min_access_interval_sec`，每平台一个闸门 | 默认 1 秒；但 `globalRateLimitEnabled=false`，代码保留未启用 |
| 文件名模板 | Go `text/template` + sprig；服务端用同一个模板渲染预览 | 默认 `平台/主播/[时间][主播][标题].flv` |
| 文件名清洗 | `filenameFilter` 只替换斜杠、反斜杠、冒号、星号、问号、引号、尖括号、竖线 | 不去 emoji，不处理保留名与长度 |

可以借的三条：退避放在监控层、成功即复位；预览必须和落盘共用同一个渲染函数；间隔不接受 0。
不要照搬的两条：Go 模板表达力过剩，桌面端用简单占位符更好校验；平台闸门默认关闭，我们可以做成可选项。

## 3. 逐条评审

### 3.1 监控间隔与自动回退

**结论：可行。** 建议 `monitor.interval_sec`，默认 30，范围 5–86400；0 的语义待定（Q1）。

为什么不能直接允许 0：monitor 循环是 3 秒一拍，0 会退化成「每 3 秒把 N 个房间全打一遍」，叠加每房间 1.5 秒闸门，一轮就要 1.5N 秒，等于自造请求风暴，而且必被平台风控。

隐藏缺陷：

1. **串行轮询**：`tick` 里是 `for room in rooms { broker.room_info(&room).await }`，一个房间超时或被闸门等待，会阻塞后面所有房间；房间越多，间隔越不准。
2. **缓存吃掉间隔**：broker 房间信息 TTL 是 15 秒，间隔设 5/10 秒时第二次仍拿缓存，用户会以为设置没生效。
3. **自动开录延迟等于一个间隔**：30 秒意味着开播后最多 30 秒才开录（现在直播中是 15 秒）。这是产品取舍，需要文案说明。
4. **没有抖动**：多房间会在同一时刻集中请求，30 个房间就是一波脉冲。

自动回退建议：

- 放监控层，每房间记 `consecutive_failures`；`next = min(interval × 2^failures, cap)`，`cap = max(300 秒, interval)`，成功清零，另加 ±10% 抖动。
- **不要和 broker 现有 5–60 秒退避各算一套**：两套叠加会变成「实际等待 = 间隔 + broker 退避」，用户无法预期。建议二选一：要么 broker 只管取流、房间信息退避全归监控层，要么把监控退避并入 broker 并暴露状态给 UI。
- 前提是**错误分类**：现在 `PlatformError` 只有 Unsupported / RoomNotFound / NotLive / Upstream / Network / Parse，429 和 -352 只能靠 `Upstream.code` 猜。建议新增 `RateLimited`（或 `is_rate_limited()`），退避只对「限流 / 网络 / 5xx」生效；`RoomNotFound`、`NotLive` 不该退避，否则房间恢复了还要等很久。
- 平台级最小访问间隔（bililive-go 有）建议放 P2，首版不做；broker 已有同房间 1.5 秒闸门。

待定：0 的语义；是否保留直播/离线双档（建议单档，行为可预期；双档等于两个设置项，用户更难理解）。

### 3.2 录制文件保存路径

**结论：功能已经存在**（设置 → 存储），不需要新入口；要定的是默认值。

冲突：「默认在应用程序的 Recording 目录」与现状 `~/Movies/HIVECAST` 不一致。macOS 打包后 `.app` 内部只读（公证、签名、更新都会覆盖），不能把录像写进应用目录；Windows 的 `Program Files` 同样需要管理员权限。

建议：默认 `<用户视频目录>/HIVECAST/Recording`（macOS `~/Movies/HIVECAST/Recording`，Windows `%USERPROFILE%\\Videos\\HIVECAST\\Recording`），保留「可自选目录」。

隐藏缺陷：

- 换目录只影响之后开的录制；正在录的会话继续写旧目录（合理，但要在 UI 说明）。
- 旧目录文件不迁移；媒体库按数据库里的绝对路径读，不受影响。
- 磁盘红线用新目录所在卷判断：换到小容量盘会立刻拦开录。
- 目录被删或外接盘未挂载时，保存会 `create_dir_all` 重建空目录，用户以为文件丢了（其实在未挂载的盘上）。建议开录前再校验一次卷可用性。

### 3.3 录制文件名模板

**结论：可行，建议做；但模板只控制文件名（stem），目录结构保持「平台/主播」。**

理由：模板允许斜杠就等于允许任意子目录和 `../`，既要防穿越又要处理目录不存在；而媒体库按平台/主播分组已经稳定。

默认模板：`{platform}-{host}-{title}-{date}_{time}`，示例 `哔哩哔哩-某某-标题-2026-11-06_16-27-30`。目录仍是 `哔哩哔哩/某某/`，默认名里带平台会重复一次——可接受（你点名要），也可以给「按平台/主播分目录」开关（默认开）。

建议首版变量：`platform`（平台中文名）、`platform_id`、`host`、`title`、`area`、`room_key`、`date`、`time`、`datetime`、`year`/`month`/`day`/`hour`/`min`/`sec`、`qn`（画质档位名）。

不要提供：时长、文件大小、最终路径——录制开始时未知。

**与弹幕的契约（必须写进文档并用测试锁住）**：视频 stem 决定一切；`.jsonl` 是视频路径换后缀；`.ass` 是 jsonl 换后缀。只要模板只改 stem，弹幕永远同名。任何「模板里带扩展名」的设计都会破坏它。

隐藏缺陷：

1. **同名覆盖（最严重）**：ffmpeg 带 `-y`，`RecordWriter` 用 `File::create`，模板不含时间时，同一天重开同一房间会直接覆盖视频和弹幕。建议落盘前查重，存在则加 `-2`/`-3`；或强制模板至少含 `{time}`（二选一，Q5）。
2. **Windows 保留名**：`CON`/`PRN`/`AUX`/`NUL`/`COM1`–`COM9`/`LPT1`–`LPT9`，以及结尾的点和空格；现有 sanitize 没处理。
3. **路径长度**：Windows 默认 260 字符（未开 longPathAware），当前主播 40 + 标题 60 已接近上限，模板再长会失败。建议按总路径预算截断（如 240 字符），优先截 title。
4. **emoji 清洗不完整**：只删「图形字符」不够，还要处理 ZWJ、变体选择符、肤色修饰、旗帜；建议用 Unicode 属性（Extended_Pictographic + Cf/Sk）剔除后做 NFC 归一。
5. **预览与落盘必须同源**：前端不要自己实现一遍替换，新增 preview 命令调用同一个渲染函数；否则改了后端忘了前端，预览就是假的。
6. **变量为空/未知**：兜底 `未知主播`/`未命名直播`，并压掉连续分隔符与首尾分隔符（否则出现 `---`）。
7. 切换模板不影响已有文件；媒体库不需要迁移，但用户可能找不到旧文件（保留旧名，不重命名）。

### 3.4 添加直播间的两个开关

**结论：可行，弹窗加两个 Switch，默认都开。**

后端：`room_add` 增加两个参数（monitor、auto_record），默认 true/true；已存在的房间仍直接返回（不覆盖用户设置）。

隐藏缺陷：

1. **语义**：`monitor_paused=true` 是「完全不轮询」，房间标题、封面、在线状态都不再更新，`auto_record` 也就永远不会触发。所以「关监控 + 开自动录制」是自相矛盾的组合，建议关监控时把自动录制一起关掉并置灰（Q6）。
2. 添加时房间已在播：现在会自动开录；用户关掉自动录制后就只加入列表。
3. 默认值不要记忆上次选择（一次关掉后以后都关，用户会困惑）。
4. 弹窗里两个开关要有说明文字，尤其「关闭监控后不会自动开录」。

## 5. 隐藏缺陷清单（按严重度）

| # | 缺陷 | 影响 | 建议 |
| --- | --- | --- | --- |
| 1 | 串行轮询阻塞 | 一个慢房间拖住全部，间隔失真 | 每房间独立任务或并发上限 |
| 2 | 缓存 15 秒 | 小间隔设置无效 | 监控走不带缓存的读取 |
| 3 | 同名覆盖 | 视频与弹幕被静默覆盖 | 落盘前查重加序号 |
| 4 | 无 RateLimited 分类 | 退避与提示都不准 | 新增错误变体或判定 |
| 5 | Windows 保留名与长度 | 录制直接失败 | sanitize 增强 + 总长度预算 |
| 6 | emoji 清洗不完整 | 仍有残留或误删 | Unicode 属性 + NFC |
| 7 | 预览与落盘两套逻辑 | 预览与实际不一致 | 后端 preview 命令 |
| 8 | 关监控 + 自动录制 | 永远不会录 | 联动置灰 |
| 9 | 间隔大导致开录延迟 | 用户以为坏了 | 文案说明，可选双档 |
| 10 | 换目录不迁移 | 找不到旧文件 | UI 说明，不迁移 |
| 11 | 弹幕同名契约被破坏 | 弹幕无法加载 | 单测锁住 |
| 12 | 0 间隔风暴 | 风控、封 IP | 最小 5 秒，或 0 = 关闭 |
