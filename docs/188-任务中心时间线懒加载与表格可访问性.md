# 任务中心时间线懒加载与表格可访问性

> 状态：实现、单测、release 构建与真机验收完成（2026-11-22）。承接 [187-任务中心逐片段重试与事件保留复查](187-任务中心逐片段重试与事件保留复查.md)。
> 后续更新（2026-11-22）：事件时间线已在 [189-任务中心事件分页与历史压力](189-任务中心事件分页与历史压力.md) 改为 200 条游标分页，且只有运行中的 Run 每 5 秒刷新。本文关于「2000 条上限」「所有 Run 固定 5 秒」的描述保留为当轮记录。
> 本轮范围：只处理 187 第 6 节确认的未完成项中不需要改数据库语义的部分——事件按 Run 懒加载、历史行恢复表格语义并保留键盘入口；同时补一次真实长录制回归。

## 1. 结论

任务中心的四段链路、状态机、异常和历史分页保持不变。本轮完成两项结构性收尾：

| 项目 | 本轮之前 | 本轮之后 |
| --- | --- | --- |
| 首屏事件 | 一次最多读 20000 条 `task_event`，分发给当前屏所有 Run | 首屏不读事件；点开详情只读该 Run，单次上限 2000 条 |
| 分组时间线 | 首屏靠一次全量查询 + alias 映射 | `task_run_events` 按 `session:<group>` 展开同组片段后查询 |
| 历史行语义 | `<tr role="button">`，表格行不再是 row | 外层恢复 `<tr>`，单元格内提供真实「详情」按钮 |
| 时间线刷新 | 跟随任务页轮询 | 抽屉打开时立即拉取，之后每 5 秒刷新，关闭即停 |

效果：1000 场历史不再把全部事件读进内存，一个超长任务也不会挤掉别的 Run 的时间线；历史表恢复标准表格语义，键盘用户通过单元格内的按钮进入详情。

## 2. 后端

### 2.1 首屏不再携带事件

`src-tauri/ipc-types/src/lib.rs` 的 `RunView` 删除 `events: Vec<TaskEvent>`；`src-tauri/src/task_center.rs:277` 删除原先「一次读 20000 条 + alias 分发」的整段，首屏只保留状态、四段链路、任务与上下文。

### 2.2 按 Run 读取

新增命令 `src-tauri/src/commands.rs:3113 task_run_events(run_id)`：

- 普通 Run 的 id 形如 `session:<session_id>`，直接查；
- 分组 Run 的 id 形如 `session:<group_id>`，先调 `db.session_group_ids` 展开成每个片段的 `session:<id>`，再一起查；
- 最终调用 `db.task_events(&ids, 2_000)`，单场上限 2000 条，仍按时间正序返回最新 2000 条；
- 任务 id 本身（`task:<id>`）不做展开，按原 run_id 查询。

`src-tauri/src/db.rs:1751 session_group_ids` 的逻辑：

```sql
SELECT COALESCE(group_id, id) FROM record_session WHERE id = ?1 LIMIT 1
SELECT id FROM record_session
 WHERE id = ?1 OR group_id = ?1
 ORDER BY started_at ASC, id ASC
```

传组 id 或组内任意片段 id 都能得到全组；未知 id 返回空数组。

## 3. 前端

### 3.1 懒加载与轮询

`src/features/tasks/TasksPage.tsx:977-1012`：

- `detailEvents/detailEventsLoading/detailEventsError` 三个状态；
- `selectedId` 变化时清空旧时间线并立即 `taskRunEvents(selectedId)`；
- 之后 `setInterval(..., 5_000)` 刷新，录制中的 Run 能看到阶段推进；
- `cancelled` 标记防止快速切换或关闭抽屉时写回过期结果；
- 关闭抽屉、非 Tauri 环境直接清空。

`src/lib/ipc.ts:647` 新增 `taskRunEvents(runId)`。时间线文案新增 `tasks.timelineLoading` 与 `tasks.timelineError`；空态仍用 `tasks.timelineEmpty`。

### 3.2 历史行可访问性

历史表外层 `<tr>` 删除 `role="button"`、`tabIndex`、`aria-label` 与 `onKeyDown`，只保留 `onClick`。状态单元格里新增真实按钮（`TasksPage.tsx:1425`）：

```tsx
<button
  type="button"
  aria-label={`${t("tasks.detailOpen")} ${run.room?.hostName || run.room?.title || run.id}`}
  onClick={(event) => {
    event.stopPropagation();
    setSelectedId(run.id);
  }}
>
  ›
</button>
```

这样表格行保持 `row` 语义，键盘与读屏用户仍能通过按钮打开详情，鼠标点击整行也保持原行为。

## 4. 真机验收

环境：macOS release bundle **33.05 MiB**，窗口 1166×749，测试前真实 DB 备份 `/tmp/hivecast-before-task-timeline.db`。

### 4.1 分组时间线

夹具：同组 `tc-lazy-g1` / `tc-lazy-g2`，g1 写 300 条事件（`批量事件 1..300`），g2 写 5 条（`第二段事件 1..5`）。

- 历史只出现一行「哔哩哔哩 LESSOSSSS 6:30 293 KB 完成」；
- 无障碍树里出现真实按钮「详情 LESSOSSSS」，点开后同时找到 `批量事件 300` 与 `第二段事件 5`；
- 说明 `session:<group>` 被正确展开到两个片段，且详情只加载当前 Run。

### 4.2 轮询刷新

详情打开时向该 Run 插入一条 `task_event`「轮询刷新测试事件」，7 秒内无障碍树即出现该文案；关闭抽屉后不再出现。测试事件随后删除。

### 4.3 事件隔离

点开另一条真实录制历史后，夹具的 `批量事件 300` 不再出现在无障碍树，证明详情没有沿用上一条 Run 的事件。

## 5. 未做与剩余风险

1. **单场上限 2000 条 → 已由 189 处理**：改为 200 条游标分页，真机验证 2100 条事件可从最新翻到第一条。
2. **历史 1000 场渲染 → 已由 189 处理**：真机验证 1000 行全量加载，RSS 30.9→46.1 MB、CPU 0.4%；仍未引入虚拟列表。
3. **并发收尾重试**：只有单测覆盖同清单互斥/不同清单并行，没有真机同时点两个片段。
4. **事件不可全局检索**：时间线只在详情内可见，没有跨 Run 搜索或导出。
5. **抽屉轮询频率 → 已由 189 处理**：只有 recording/running/finalizing/queued 每 5 秒刷新；已结束 Run 只取一次，真机验证 DB 改消息 8 秒后界面不变。
6. **WAL 清理提醒**：SQLite WAL 模式下退出后应立即删除 `-wal/-shm` 前先 `PRAGMA wal_checkpoint(TRUNCATE)`；本轮测试遵守该流程。
