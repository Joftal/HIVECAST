## 1. 已确认决策（D1–D7）

| ID | 决策 | 理由 | 影响面 |
| --- | --- | --- | --- |
| **D1** | 观看内核走 **Rust 转封装 → 本地 HTTP（127.0.0.1 随机端口 + token）→ hls.js** | 鉴权/Cookie/Referer/代理/线路测速全部收敛在 Rust；WebView 只负责解码播放，不受 CORS 与请求头限制；线路切换可做到秒级无缝 | 新增 3 个组件：ViewSession、LocalStreamServer、Remuxer；见 §3.4 |
| **D2** | 观看端 **v1 就显示弹幕**（B 站优先，其余平台随平台接入） | 弹幕是直播观看的核心体验；且录制端已有 WS 能力，复用度高 | 每格一个 DanmakuTap + Canvas 渲染层；见 §2.5 |
| **D3** | 4 路音频**默认全部静音，点开才响** | 4 路同时出声无法使用；默认静音避免首启噪音 | 每格独立音量状态；发声路数不限，由用户自行管理（O1=B） |
| **D4** | 首批平台 **B 站 + 斗鱼 + 虎牙 + 抖音** | 覆盖绝大多数中文直播场景 | 抖音需移植 ABogus 签名，独立里程碑 M5 |
| **D5** | 后处理 **仅本地**（合并/转 mp4/弹幕 ASS/截图） | 不依赖外部账号，闭环自洽；上传与同步留到 v2 | 队列并发 2，见 10 文档 |
| **D6** | 录制与观看互踢时：**提示 + 观看切到"录制流回环"** | 部分平台/账号限制同房间单路播放；回环牺牲画质换稳定 | 录制 ffmpeg 增加第二路 HLS 输出，按需启用；见 §3.6 |
| **D7** | 4 路同屏**默认 1080p**，带自动降级 | 画质优先；现代机器硬解可撑住 | 需解码能力探测 + 掉帧/CPU 触发的降级策略；见 §4.2 |

## 2. 产品蓝图

### 2.1 两个 Tab 的定位

| | Tab 1 · 监控 | Tab 2 · 观看 |
| --- | --- | --- |
| 生命周期 | 常驻后台，应用启动即工作 | 用户打开才存在，关闭即释放 |
| 核心对象 | Room 的**录制意图**与**录制会话** | Room 的**观看会话**（最多 4 个） |
| 状态特征 | 长跑、可恢复、要持久化 | 短跑、可丢弃、不持久化（布局除外） |
| 失败影响 | 丢一场录像（严重） | 卡一下（可接受） |
| 资源占用 | ffmpeg 进程 + 磁盘写 | 解码 + 网络读 + 少量磁盘（HLS 缓存） |

两个 Tab 共享：平台适配层、StreamBroker、CredentialStore、房间元数据、HTTP 客户端与代理、日志。
两个 Tab **不共享**：会话对象、画质选择、错误状态、资源配额、播放/录制进程。

### 2.2 实体关系

```text
Room（唯一业务实体）
 ├─ RecordIntent   0..1   是否监控、是否自动录、录制画质/线路/关键词
 ├─ RecordSession  0..1   一次录制会话（1 个 ffmpeg 进程 + 1 个弹幕连接）
 ├─ ViewSlot       0..1   观看 Tab 的某个格子（1 个 ViewSession）
 └─ DanmakuTap     0..N   录制一份 + 已打开的观看各一份，互相独立
```

三条硬规则：

1. **一个房间最多占一个观看槽位**。重复打开只做"聚焦跳到已有槽位"，绝不重复建会话。
2. **同一房间可同时录制与观看**，但这是两条独立会话、两份独立 StreamLease。
3. **删除房间 = 先停会话再删**（事务式），不允许留下孤儿进程或孤儿文件。

解析顺序（?? 表示"未设置才回退"）：

## 3. 边界与状态机

### 3.1 录制 × 观看 冲突矩阵（验收用例）

| # | 操作 | 正在录制 | 正在观看 | 依据 |
| --- | --- | --- | --- | --- |
| 1 | 观看切画质 | 不受影响 | 新 lease，黑屏 ≤1s 后恢复 | 两条 lease 独立；录制 URL 已交给 ffmpeg |
| 2 | 观看切线路 | 不受影响 | 换 remux 源，1–2s 恢复 | 同上 |
| 3 | 关闭观看/关槽位 | 继续 | — | 会话引用计数 |
| 4 | 手动停止录制 | — | 继续 | 两端独立 supervisor |
| 5 | 录制自动重连（换 URL） | 重启 ffmpeg，续写同一文件 | 不受影响 | 录制侧只操作自己的进程 |
| 6 | 平台单路限制（互踢） | 断流 → 重连 | 断流 → 重连 | 检测到双方同时 403/踢流 → 提示 + 回环降级 |
| 7 | 修改房间录制画质 | 默认下一场生效（可勾选立即重启） | 不受影响 | 配置只影响下次 resolve |
| 8 | 删除房间 | 先停并提示 | 先关槽位并提示 | 事务式操作 |
| 9 | Cookie 失效 | 失败，错误码 NeedAuth | 失败，独立展示 | 共享账号状态，不共享错误 UI |
| 10 | 磁盘满 | 停录 + 通知 | 继续 | 资源守卫只管录制 |
| 11 | 网络切换（Wi-Fi 转有线） | 退避重连 | 退避重连 | 无共享连接 |
| 12 | 代理变更 | 下一场生效 | 新 lease 生效 | 变更需重建 HTTP client |
| 13 | 观看暂停 | 继续 | 暂停（remux 仍跑，缓冲丢弃） | 暂停是播放器行为 |
| 14 | 应用退出 | 优雅停录，写收尾 | 全部释放 | ProcessSupervisor 统一管理 |

### 3.2 StreamBroker 契约（Rust）

```rust
pub enum Purpose { Record, View { slot: SlotId } }

pub struct StreamRequest {
    pub room: RoomRef,
    pub purpose: Purpose,
    pub quality: Option<Quality>,      // None = 用该消费者的默认值
    pub format_hint: Option<Format>,   // Record 默认 flv；View 默认 fmp4
    pub allow_fallback: bool,          // 允许平台降级（未登录常见）
}

pub struct StreamLease {
    pub lease_id: LeaseId,
    pub url: String,
    pub headers: Vec<(String, String)>,
    pub expires_at: Instant,
    pub requested_quality: Quality,
    pub actual_quality: Quality,       // 平台实际给的，可能被降级
    pub line: LineId,
    pub group: String,                 // "主线" / "备线1" ...
    pub format: Format,
}

impl StreamBroker {
    pub async fn resolve(&self, req: StreamRequest) -> Result<StreamLease, StreamError>;
    pub fn report(&self, lease_id: LeaseId, outcome: LeaseOutcome); // 只影响下次选线
}
```

五条规则：

1. **Lease 不可变**。消费者拿到后，任何其他人的操作都不会改变它。
2. **缓存两层**：房间快照（TTL 5s，全员共享）+ 播放信息（key = room + qn + 封装掩码，TTL 60s）。
3. **in-flight 去重**：同一 key 的并发请求合并成一次 HTTP，避免"录制在查、观看也在查"触发风控。
4. **每房间限速**：最小间隔 1.5s，遇 `-352`/`429` 指数退避（2s、4s、8s，上限 60s）。
5. **降级不静默**：`actual_quality != requested_quality` 时返回 warning，UI 显示"平台未提供该画质，已用 X"。

### 3.3 线路（Line）模型

```rust
pub struct Line {
    pub id: LineId,          // 稳定标识，如 "bili:cn-gotcha208"
    pub name: String,        // 展示名："主线" / "备线1" / "AL" / "TX"
    pub host: String,
    pub protocol: Protocol,  // Flv / HlsTs / HlsFmp4
    pub rtt_ms: Option<u32>, // 最近一次 TTFB 中位数
    pub success_ema: f32,    // 成功率指数滑动平均
    pub last_ok_at: Option<DateTime<Utc>>,
}
```

- **测速**：拉流首字节时间（TTFB），每线 3 次取中位数，结果缓存 1 小时；网络变化（IP/接口变化）即失效。
- **选线**：录制优先"成功率 + 稳定"，观看优先"TTFB"；同一租约内不再换线。
- **锁定**：用户可锁定某条线路，锁定后不参与自动切换；连续失败 2 次弹提示"是否解除锁定"。
- **平台事实**：虎牙直接给 3 条线路（AL/TX/HS）；B 站同格式常有 2 条（带 `b` 后缀）；抖音走自家 CDN 组。

### 3.4 观看管道（ViewSession）

```text
StreamLease
   │
   ▼
Remuxer（每路一个 ffmpeg 子进程，-c copy 不转码）
   │  输出 fMP4 分片 + m3u8 到 <data>/cache/view/<session>/
   ▼
LocalStreamServer（127.0.0.1:随机端口，路径带 token）
   │  HTTP
   ▼
hls.js → <video>（WebView 解码）
```

ffmpeg 参数基线：

```bash
ffmpeg -hide_banner -loglevel warning -rw_timeout 10000000 \
  -headers "Referer: <platform>" -user_agent "<UA>" \
  -i "<lease.url>" -c copy \
  -f hls -hls_time 1 -hls_list_size 6 \
  -hls_flags delete_segments+append_list+omit_endlist \
  -hls_segment_type fmp4 -hls_fmp4_init_filename init.mp4 \
  -hls_segment_filename "seg_%05d.m4s" index.m3u8
```

延迟预算：

| 环节 | 典型值 |
| --- | --- |
| 平台侧缓冲 | 1–2 s |
| 转封装分片（hls_time=1） | 1 s |
| 播放器起播缓冲（2 个分片） | 1–2 s |
| **端到端** | **3–5 s** |

约束与降级：

- 源为 HEVC/AV1 时先尝试 copy；若 hls.js 报解码错误，**自动改用该房间的 AVC 源**（B 站三封装都提供 avc；虎牙/抖音默认 h264）。
- remux 进程异常退出 → 重新 resolve（可能换线），播放器重建，UI 显示"重连中"。
- 缓存目录在会话结束时删除；异常退出由启动清理任务兜底。

### 3.5 音频策略

- 默认 **全部静音**（D3/O1），每格音量独立存储（会话级，不落盘）。
- **发声路数不限**（O1=B）：不做「第 3 路自动静音」这类隐式行为，避免用户刚开的声音被系统关掉。用户自己负责组合，另提供：
  - 工具栏「全部静音」一键按钮；
  - 每个格子的音量数值可视化（≥1 路发声时该格边框/音量图标高亮），让用户一眼看到哪几路在响；
  - 若同时发声 ≥3 路且检测到削波/回声，仅**提示**一次，不自动干预。
- 静音格仍然解码（用户随时可能开声），不做暂停，避免开声时重新缓冲。
- 系统音量键：若聚焦格有声则调该格音量，否则调系统音量。

### 3.6 互踢检测与"录制流回环"（D6）

```text
信号：同一房间 30s 内，录制与观看同时失败 ≥2 次
  或：录制 stderr 连续无效行达到阈值 + 观看 remux 退出码非 0
        │
        ▼
UI 横幅：「该平台限制同房间单路播放，观看已切换到录制流（720p）」
        │
        ▼
录制 ffmpeg 增开第二输出 → <data>/cache/loop/<session>/index.m3u8
观看端关闭自己的 remux，直接播该本地 m3u8
```

- 回环输出使用 `-map 0:v:0 -map 0:a:0? -c copy -f hls -hls_time 2`，只在该会话内存在。
- 回环期间：观看画质跟随录制画质，切换画质按钮置灰并注明原因。
- 录制停止 → 回环失效 → 观看提示"录制已停止，正在尝试恢复独立拉流"。

## 4. 技术架构增量

### 4.1 进程与任务模型（相对 14 文档的增量）

| 组件 | 说明 |
| --- | --- |
| 监控任务池 | 每房间 1 个 tokio task，独立取消令牌（沿用 14） |
| 录制任务池 | 每会话 1 个 ffmpeg + 1 个弹幕 WS |
| **观看任务池（新）** | 每 slot 1 个 remux ffmpeg + 1 个弹幕 WS + 1 条 HTTP 连接 |
| **LocalStreamServer（新）** | 单实例 axum，绑定 127.0.0.1:0，token 路由，无会话时零监听开销 |
| **StreamBroker（新）** | 单实例，内含缓存、限速器、线路统计 |
| 后处理队列 | 并发 2（沿用 10） |
| 清理任务 | 启动 + 每小时：清理孤儿缓存、过期 token、未完成分片 |

### 4.2 性能预算（4 路 1080p60 H.264）

| 资源 | 预算 | 超限动作 |
| --- | --- | --- |
| 网络 | 24–40 Mbps | 提示 + 自动降 720p |
| CPU（4 路 remux） | < 10% 总算力 | 无（copy 很轻） |
| 内存 | Rust 4×50 MB + WebView 4×120 MB ≈ 0.7 GB | > 1.5 GB 触发降级 |
| 磁盘写（HLS 缓存） | ≈ 16 MB/s，会话结束即删 | > 32 MB/s 告警（可能异常重连） |
| 解码 | 4 路硬解（VideoToolbox / D3D11VA） | 见下 |

自动降级规则：

1. 单路掉帧率 > 2% 持续 10s → 该路降一档（1080p→720p→480p），toast 说明。
2. 整体 CPU > 70% 持续 30s → 提示"是否全部降到 720p"（可关闭自动降级）。
3. 解码能力探测：启动时检测 `canPlayType('video/mp4; codecs="avc1.640028"')` 与 HEVC；不确定时按 AVC 处理。

### 4.6 本地 HTTP 的安全约束

- 仅绑定 `127.0.0.1`，端口随机（0），**绝不监听 0.0.0.0**。
- 路径前缀含 32 字节随机 token（`/s/<token>/index.m3u8`），会话结束即失效。
- 校验 `Host` 与 `Origin`，拒绝跨站；不设 CORS 通配。
- 不提供目录遍历，只服务已注册的会话文件。

### 8.1 i18n 落地要求（O7）

- 技术选型：`i18next` + `react-i18next`，不引入重型框架。
- 文案键按「域.组件.语义」命名，例如 `monitor.room.record_start`、`watch.slot.mute`。
- 平台特有名词不翻译（B 站、斗鱼、虎牙、抖音、原画、蓝光），保留原文。
- 语言默认跟随系统，可在设置页切换；切换即时生效，不重启。
- 新增文案必须两种语言同时补齐（CI 增加 key 一致性检查）。
