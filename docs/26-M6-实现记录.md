## 2 设置系统

### 2.1 为什么只有一层

docs/19 §2 设计的 `effective = session_override ?? room[consumer] ?? room ?? platform ?? global ?? default` 是终态。v1 里真正会被改的只有「新房间默认画质」「媒体目录」「并发上限」「通知开关」「语言」五项，全部是全局的，所以先只做全局一层，键值存在 `app_setting` 表：

```sql
CREATE TABLE IF NOT EXISTS app_setting (
    key        TEXT PRIMARY KEY,
    value      TEXT NOT NULL,
    updated_at INTEGER NOT NULL
)
```

### 2.2 键与约束

| 键 | 含义 | 归一化 |
| --- | --- | --- |
| `record.default_qn` | 新房间默认录制画质 | 100 的倍数，夹在 80..=20000，0 保持 0（自动） |
| `view.default_qn` | 新房间默认观看画质 | 同上 |
| `media.root` | 媒体库根目录 | 去空白、不能为空、不存在则 `create_dir_all` |
| `record.max_concurrent` | 同时录制上限 | 夹在 1..=8（`MAX_CONCURRENT_LIMIT`） |
| `ui.notify` | 系统通知总开关 | 布尔 |
| `ui.language` | 界面语言 | 白名单 system / zh-CN / en-US，其它回落 system |

`save()` 返回纠正过的值，前端拿返回值回填输入框——这样用户输入 99 路并发，回来会看到 8，而不是被静默丢弃。读到损坏数据（比如手改数据库写成字符串 `abc`）则整体回落默认值，不让应用起不来。

### 2.3 热生效

`save()` 之后立刻 `apply()`：媒体目录与并发上限直接改到 `Recorder` 上，已开录的会话不受影响，下一次 `start()` 才看新上限。语言与通知开关走前端，不改后端行为。

达到上限时开录返回 `User("同时录制已达上限（N 路），先停掉一路或到设置里调高上限")`。

## 3 媒体库

### 3.1 数据来源

没有新建媒体表——`record_session` 本身就是录像清单，`JOIN room` 取平台与标题即可。`media_list` 只返回 `file_path` 非空的会话，按 `started_at DESC` 取前 N（默认 200）条，并用 `Path::is_file` 现算 `has_file`：磁盘被用户手动删掉的录像仍会出现在列表里，但按钮置灰并标「文件已缺失」。

### 3.2 删除语义

`media_delete(session_id, delete_file)` 三件事按序做：先 `local.stop()`（正在回放这条就先停），再删视频与弹幕 jsonl，最后删数据库行并广播 `rooms-changed`。只删记录（`delete_file=false`）留给「文件我已经手动归档了」的场景。

前端是二次确认：第一次点变红「再点一次确认」，失焦复位，避免误删。

## 4 本地回放

### 4.1 管道

```
磁盘 .flv/.mp4 ──ffmpeg -c copy──▶ HLS 缓存目录 ──回环 HTTP──▶ hls.js ──▶ <video>
```

- 缓存目录 `~/Library/Caches/com.hivecast.desktop/play/{session}-{ms}/`，停播即整目录删除。
- 单实例：`LocalPlayer` 内部只有 `Option<Active>`，打开新的会先停旧的；`gate` 是 tokio 互斥锁，防 React StrictMode 双跑造成两个 ffmpeg 抢同一目录。
- 打开前拒绝 `status == "recording"` 的会话（「这段还在录制，先停下再处理」）。
- 起播前等 `index.m3u8` 落盘（最多 12 秒），否则 hls.js 会先拿到一次 404。

### 4.2 踩坑：fmp4 不可用，改 mpegts

第一版照抄观看端的参数（`-hls_segment_type fmp4`）用 `-re` 边读边切，结果媒体库永远停在「缓冲中」。打开 hls.js 的 fatal 回调才看到：

```
FATAL mediaSourceRequiresReset
```

把产物拿下来验：

```
$ ffprobe seg_00055.m4s
[mov,mp4,m4a,3gp,3g2,mj2] trun track id unknown, no tfhd was found
seg_00055.m4s: Invalid data found when processing input
```

分片里只有 `styp / sidx / sidx / moof / mdat`，moof 里缺 `tfhd`。用同一份录像在命令行复现，加 `+default_base_moof`、`+cmaf`、`+frag_keyframe+empty_moov` 都不解决——**ffmpeg 9.0.2 从 flv 文件转 fmp4 就是这个输出**，与观看端无关（观看端输入是网络流，路径不同）。

改成 mpegts 后一次通过：

| 参数 | 值 | 理由 |
| --- | --- | --- |
| `-hls_segment_type` | 默认（mpegts） | 兼容性最好，hls.js 直接吃 |
| `-hls_time` | 2 | 分片数减半，长录像少一堆小文件 |
| `-hls_playlist_type` | vod | 生成 `EXT-X-PLAYLIST-TYPE:VOD` 与结尾 `EXT-X-ENDLIST` |
| `-hls_flags` | independent_segments | 每个分片可独立解码，拖动进度条不花屏 |
| `-re` | 去掉 | 点播不需要按帧率读，整片尽快切完才能全片可拖 |

实测产物：

```
#EXTM3U
#EXT-X-VERSION:6
#EXT-X-TARGETDURATION:2
#EXT-X-MEDIA-SEQUENCE:0
#EXT-X-PLAYLIST-TYPE:VOD
#EXT-X-INDEPENDENT-SEGMENTS
#EXTINF:2.000000,
seg_00000.ts
...
#EXT-X-ENDLIST
```

代价：回放期间磁盘上会多出一份与录像等大的分片（8 秒录像 2.2 MB，1:54 录像约 30 MB），停播即清。长录像（1 小时以上）打开时会有一段连续 I/O，这是已知取舍，记在 §9。

## 5 前端接线

### 5.1 三段式顶栏

`TabBar` 原来只认两个值（`labels={{monitor, watch}}`），加第三个 Tab 时改成通用形态：

```tsx
<TabBar
  value={tab}
  onChange={(next) => setTab(next as TabKey)}
  items={[
    { key: "monitor", label: t("tab.monitor") },
    { key: "watch", label: t("tab.watch") },
    { key: "media", label: t("tab.media") },
  ]}
/>
```

指示块宽度用 `calc((100% - 8px) / n)`、位移用 `translateX(index * 100%)`，加 Tab 不用改动画代码。

### 5.2 设置抽屉

右侧 430px 抽屉（`fixed inset-0 z-50`），背景点击与 Esc 都能关。目录选择走 `@tauri-apps/plugin-dialog` 的 `open({ directory: true })`——为此新装了 `tauri-plugin-dialog`（2.8.4）并在 capabilities 里加 `dialog:default`。

保存成功后用返回值回填（§2.2 的「纠正过的值」），并顺手 `setLanguage()`，不用重启。

### 5.3 顶栏语言切换要写回设置

原来的写法只调 `setLanguage()`，是会话级的；现在设置里也有语言，两处不同步会出现「点了中，重启又变回英文」。所以顶栏切换改成「先读设置再写回」：

```tsx
const pickLanguage = (code: Language) => {
  setLanguage(code);
  void settingsGet()
    .then((settings) => settingsUpdate({ ...settings, language: code }))
    .catch(() => undefined);
};
```

读写失败一律静默——语言是体验项，不能因为它弹错误挡路。

### 5.4 媒体库页面

- 卡片：平台徽标（B 站天蓝 / 斗鱼橙 / 虎牙琥珀 / 抖音品红）、标题、主播、时长、大小、弹幕条数。
- 回放面板固定在上方，`aspect-video` + `max-h-[52vh]`；点同一张卡片的「停止播放」或切走页面都会 `mediaStop()`。
- 删除是二次确认，按钮在确认态变红。
- 文件缺失的卡片半透明、播放按钮禁用、标「文件已缺失」。

## 6 打包与首次打开

按用户裁决，**不做 Apple 公证、不做 Windows 签名**，产物给用户自己点放行。

### 6.1 命令

```bash
CI=true pnpm tauri build
```

产物：

```
src-tauri/target/release/bundle/dmg/HIVECAST_0.1.0_aarch64.dmg   9.23 MiB
```

`CI=true` 不是习惯，是本机的必需品，原因见 §6.2。只出 `.app` 用 `pnpm tauri build --bundles app`。

### 6.2 踩坑：不加 CI 就打不出 dmg

第一次 `pnpm tauri build` 编到 90% 后死在打包阶段：

```
execution error: “Finder”遇到一个错误：AppleEvent已超时。 (-1712)
Failed running AppleScript
Error failed to bundle project: error running bundle_dmg.sh
```

Tauri 的 dmg 分两步：`hdiutil` 做镜像（成功），然后跑一段 AppleScript 让 Finder 摆图标、设窗口大小（失败）。这段脚本要「控制 Finder」的自动化权限，本机没授过，AppleEvent 只能等到超时。`bundle_dmg.sh` 自己带 `--skip-jenkins` 开关跳过这段美化，而 Tauri 只在检测到 `CI` 环境变量时才传它——所以 `CI=true` 就通了。

代价：dmg 打开后图标是默认排布，没有背景图、没有「拖到 Applications」的箭头。功能完全一致，对未签名产物来说不值当为它去申请权限。

### 6.3 壳内是什么

```
$ hdiutil attach -nobrowse -readonly .../HIVECAST_0.1.0_aarch64.dmg
HIVECAST.app            22 MB
Applications -> /Applications
.VolumeIcon.icns
```

`CFBundleShortVersionString = 0.1.0`；`codesign -dv` 显示 `flags=0x20002(adhoc,linker-signed)`，即链接器顺手做的临时签名——不是开发者 ID 签名，别拿它当公证通过。注意 dmg 成功后 `bundle/macos/HIVECAST.app` 会被清掉，要单独的 `.app` 必须用 `--bundles app` 再跑一次。

macOS 首次打开被 Gatekeeper 拦住时，两条路任选：

1. 右键（或 Control + 点）图标 →「打开」→ 再点「打开」；
2. 命令行去隔离属性：

```bash
xattr -dr com.apple.quarantine /Applications/HIVECAST.app
```

Windows 未签名安装包会被 SmartScreen 拦，点「更多信息」→「仍要运行」。

> 注：§7 的实测是开发态 `pnpm tauri dev` 与 release `.app` 直接拉起，**没有走一遍「从 dmg 拖进 /Applications 再双击」**——本机没有签名身份，装上去也还是要放行一次。

## 8 踩坑

1. **fmp4 缺 tfhd**（§4.2）：ffmpeg 9 从 flv 文件转 fmp4 会写出非法 moof，hls.js 报 `mediaSourceRequiresReset`。换 mpegts 解决。
2. **`i64` 到前端的类型**：`MediaItem` 的数值字段加了 `#[ts(type = "number")]`，但 `Playback.duration_ms` 漏了，ts-rs 生成 `bigint`，`formatDuration(playback.durationMs)` 直接编译失败。补齐并用 `pnpm gen:bindings` 重新导出。
3. **i18n 键名对不上**：媒体库文案一开始复用了 `monitor.danmakuCount`，实际这个键不存在（监控页是把条数拼在别处的），界面上会直接显示键名。改成 `media.danmakuCount` 并在中英两侧补齐。
4. **抽屉截图连拍两次都对不上**：HMR 每次整页重载都会重跑临时定时器，「1.2 秒开、4.2 秒关」的时序在多次重载下不可靠。最后改成「只开不关」，截完再删补丁。
5. **删除要先停回放**：如果先删文件，正在跑的 ffmpeg 会读到 EOF 后报错退出，界面上是一串 ffmpeg 错误。顺序必须是 stop → 删文件 → 删行。
6. **dmg 打包要 `CI=true`**（§6.2）：Finder 的 AppleScript 美化步骤没有自动化权限会 -1712 超时，整个 bundle 失败，但此时 `hdiutil` 早已成功，容易误判成镜像有问题。

## 9 已知缺口

| 缺口 | 影响 | 下一步 |
| --- | --- | --- |
| 本地回放同时只允许一路 | 媒体库里点第二条会顶掉第一条 | 需要就和观看端一样改成多实例 + 引用计数 |
| 长录像开播要整片重封装 | 1 小时录像约多占等大磁盘，起播有几秒 I/O | 可换成按需分段（只切已看部分）或直接 remux 成 mp4 + Range |
| 并发上限没有端到端截图 | 只验证了「写入 / 重启后读回」，拒绝新开录的路径靠代码审查 | 手动开 9 路验证 |
| 设置只有全局一层 | 同一房间不能单独设画质 | docs/19 §2 的四级覆盖留到真有需求 |
| 媒体库没有搜索 / 按平台筛选 / 排序切换 | 录像多了会难找 | M7 打磨 |
| 未做从 dmg 安装的验收 | 只跑了 `.app` | 出包后手动装一遍 |
