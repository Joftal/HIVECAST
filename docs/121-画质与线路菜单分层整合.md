# 121-画质与线路菜单分层整合

> 状态：v1 已实施（2026-11-09）；`?player-lab` 浅色主题完成默认画质、线路二级视图与返回复看。
> 范围：观看页播放器画质/线路菜单与线路缓存刷新。

## 0. 结论速览

- 画质菜单默认只显示画质，不再把 8 条线路和 6 个画质堆成一张长列表。
- 画质列表底部新增「线路 · 当前线路」入口，点击后在同一菜单内切换到线路列表；顶部「‹ 观看画质」可返回。
- 线路选择完成后菜单关闭，画质入口标签仍显示当前画质。
- 实际依赖方向是 **画质 → 线路**：`room_lines(id, qn)` 按画质档位取线路组。现在画质变化后线路缓存按 qn 失效，下次展开重新获取。
- 换线路不重新选画质：`view_set_line` 用当前 `requested_qn` + 新线路重启观看管线；该线路缺少对应档位时由后端回退到可用候选。
- 当前没有“每条线路的完整画质列表”接口，画质选项仍是应用统一的 qn 集合；若以后需要按线路动态列画质，需要后端暴露线路组内的 candidates。

## 3. 缓存与刷新

`src/features/watch/WatchPage.tsx` 的线路缓存从 `LineInfo[]` 改为 `{ qn, items }`：

```ts
const [lineCache, setLineCache] = useState<{ qn: number; items: LineInfo[] } | null>(null);
const lines = lineCache?.qn === session.requestedQn ? lineCache.items : null;

const loadLines = useCallback(async () => {
  if (lineCache?.qn === session.requestedQn) return;
  const qn = session.requestedQn;
  setLineCache({ qn, items: await roomLines(session.roomId, qn || undefined) });
}, [lineCache, session.roomId, session.requestedQn]);
```

- 同一画质下重复展开菜单不会重复触网。
- 画质改变后 `lineCache.qn` 与 `requestedQn` 不一致，线路立即视为未加载；下次展开重新调用 `room_lines`。
- 旧请求返回时也只写入它自己的 qn，不会把新画质的线路显示出来。

## 4. 为什么换线路不重新取画质

后端数据流是：

1. `room_lines(id, qn)` 按 qn 解析出若干线路组，每组内的 candidates 才是该线路可用的画质。
2. `view_set_line(slot, line)` 保留当前 `requested_qn`，用新线路重启观看管线。
3. 若新线路没有该 qn 的地址，后端按该线路的 candidates 回退到可用档位；前端通过 `degraded` 与「↓ 实际画质」提示。

因此线路切换不需要重新请求画质列表；需要刷新的反而是线路列表（它依赖 qn）。

## 5. 组件改动

- `src/components/arc/dropdown-menu/dropdown-menu.tsx`：`DropdownItem` 新增 `keepOpen`；选择时按需 `event.preventDefault()`，让画质/线路二级切换不关闭菜单。
- `src/features/watch/Player.tsx`：新增 `lineMode` 状态；菜单项按模式生成画质列表或线路列表；打开菜单时强制回到画质视图。
- `src/features/watch/WatchPage.tsx`：线路缓存按 qn 分区，画质变化后自动失效。

## 6. 局限

- 线路视图里的域名是 `LineInfo.name`，不是完整的画质清单。
- 画质选项来自前端统一 qn 集合，不随线路变化；若要展示“该线路实际可用的画质”，需要新增后端命令返回每个 `StreamGroup` 的 candidates。
- 换线路后的实际画质由后端回退决定，入口标签仍显示用户请求的画质，回退信息由标题栏的降级标记体现。
