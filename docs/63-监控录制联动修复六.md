一句话结论：**62 里需要动代码的四条（F2 / F1 / F6 / F4）全部改完，真机验收通过。最要紧的 F2 现在有硬证据：录制中把房间软删，1 秒内按「用户停录」收尾成 `finished/stopped`，没有续录、没有「直播已结束」通知、只留一条会话；F1/F6 合起来让坏房间从「每拍一条 WARN + 一次前端全量刷新」变成「一条 WARN，之后按 2、4、8、16、32 秒退避」；F4 让关闭再开启自动检测不再丢在途结果、也不会把同一房间查两次。**

### 1.1 F2：删除房间的兜底要在录制侧

删除房间的流程本身会先 `stop("stopped")`，但停录请求可能因为并发或异常丢掉；旧代码只有一个「续录时读不到房间行」的兜底，而软删**不删行**，所以那条兜底永远不触发。结果是：用户删了房间，录制还在跑，续录三次用尽后收尾时 `platform_state` 把 `removed_at` 当离线，于是 `confirmed_end=true`，记成 `finished/stream_ended`，满足 `mark_ended` 与 `emit_notice("ended")` 的条件，给一条已经不存在的房间弹「直播已结束」。

现在 watcher 在 `poll_exit` **之前**先查一次 `removed_at`：命中就 `kill_and_wait` + `finalize(..., Some("stopped"), false)`，然后 return。选 `stopped` 而不是 `stream_ended` 是有意的：`stopped` 不满足结束通知条件，也不会写 10 分钟静默；`confirmed_end=false` 则避免任何「平台确认下播」的副作用。`respawn` 里再查一次只是兜底（正常路径 1 秒内就收尾了，走不到续录）。

### 1.2 F1：去重不能借用开录错误的槽位

`errors` 这个 map 同时被「检测失败」和「自动开录失败（如并发已满）」写，而 UI 通过 `last_error` 读它。如果直接在成功检测时 `clear_error`，每拍都会把 C7 好不容易去重掉的「同时录制已达上限」清掉，下一次失败又变成「文案变化」，于是每秒一条 WARN，等于把 C7 改回去了。

所以去重信息单独放 `detect_errors`，只由检测路径写：

- 失败：`note_detect_error` 返回「与上次不同」才 WARN + `set_error` + `emit`；
- 成功：`clear_detect_error` 返回「真的清掉了」才 `clear_error` + `emit`。

这样「坏房间反复失败」只推一次事件，「恢复」推一次，「换了原因再失败」再推一次，而开录失败的那条告警完全不受影响。

### 1.3 F6：坏房间也要退避

62 里只把 `Outcome::Throttled` 接进了退避，`Failed`（房间不存在、接口字段解析失败、检测任务 panic）仍是固定 `now + base`。这类房间在平台上大概率永远不会恢复，按 1 秒间隔打接口纯属浪费，还会把同一条错误反复写日志。

现在 `Failed` 走同一套 `backoff_wait`：`error_count` 累加，`base` 乘 2 的 n 次方，封顶 `monitor.backoff_cap_sec`，抖动 ±10%，并且 `grid_at` 跟着重试时刻走（避免补考式连发）。成功一次就清零，回到正常网格。

### 1.4 F4：关闭检测不等于清空排期

旧实现 `base == 0` 时 `schedule.clear()` 再 `while rx.try_recv().is_ok() {}` 把在途结果倒掉。清表顺手把 `inflight` 标记一起抹掉了，于是「关掉再打开」这段时间里同一房间可能被查两次（旧任务的结果被丢弃，新排期又从 0 开始算），而 `inflight` 若恰好留在新表上，这一路就再也不被检测。

改法是把「关掉」当成「这一拍不发起新检测」，而不是「重置调度」：排期表保留、结果照收（用最后一次有效间隔推进网格），只有 `tick` 在 `base <= 0` 时早退。重开时排期已经过期，会立刻补一拍，且不会重复，因为 `inflight` 一直是准的。

## 3. 真机验收

环境：macOS 27.0.1 arm64、DB `~/Library/Application Support/com.hivecast.desktop/hivecast.db`、二进制按当前源码重建。时间均为本地时间（UTC+8），日志里是 UTC。为了不让真实平台带宽干扰，录制侧用一个假 `ffmpeg`（放在 `PATH` 前面，识别 `-version`，向 `part0000.ts` 写 120 KB 后每秒追加 40 KB）。房间用真实哔哩哔哩 6（在播）真实解析线路。

### 3.1 录制中删房间（F2）

`interval=30`，房间 `rm-f2` 自动开录后，在 `22:55:11` 直接改库置 `removed_at`（等价于 UI 删除，只是跳过 IPC）：

```text
22:54:45.803 INFO 开始录制 room=F2 主播 file=/tmp/hc-f2/哔哩哔哩/F2 主播/...2026-11-07_06-54-45.mp4
22:55:11.877 INFO 房间已删除，结束本次录制 room_id="rm-f2"
22:55:11.998 INFO 录制结束 room_id="rm-f2" status="finished" reason="stopped" file_size=1120000
```

- 从改库到收尾 **0.87 秒**（watcher 1 秒轮询的下一拍）；
- DB 只有这一条会话，`finished/stopped`，不是 `stream_ended`；
- 全程没有 `断流后续录`、没有 `续录次数用尽`、没有 `未能确认平台已下播`、没有「直播已结束」通知；
- 进程表里没有残留 ffmpeg。

### 3.2 坏房间：一条 WARN + 指数退避（F1 / F6）

插入一个不存在的房间（哔哩哔哩 `999999999`，平台返回可解析失败的响应），`interval=1`，观察 45 秒：

```text
22:55:36.467 WARN  刷新房间失败 room=F6 主播 hint=响应解析失败：...room_id=999999999
22:55:39.474 DEBUG 刷新房间仍失败 room=F6 主播 ...
22:55:44.488 DEBUG 刷新房间仍失败
22:55:53.513 DEBUG 刷新房间仍失败
22:56:13.567 DEBUG 刷新房间仍失败
22:56:46.668 DEBUG 刷新房间仍失败
```

- `WARN 刷新房间失败` 全程 **1 条**（F1）；之后每次失败只记 debug，不再推事件；
- 失败时刻间隔 3、5、9、20、33 秒，严格按 2/4/8/16/32 秒翻倍（含 ±10% 抖动与 1 秒 tick 粒度），说明 F6 生效；
- 若按旧逻辑，45 秒内会发出 40 余次请求、40 余条 WARN 与 40 余次 `EVENT_ROOMS_CHANGED`。

### 3.3 关闭再开启自动检测（F4）

把 `monitor.backoff_enabled` 临时设为 false（让失败房间按 1 秒节奏出日志，便于观察），然后 `interval` 从 1 切到 0 保持 10 秒再切回 1：

- `22:57:18` 到 `22:57:28` 关闭期间**没有任何**新的检测日志；
- 重开后的第一条失败在 `22:57:28.786`，随后按约 1.5 秒一拍继续（1 秒基础间隔 + 抖动 + tick 粒度）；
- 全程没有出现同一秒两条检测记录（排期没有重复），也没有出现「重开后再也不检测」（`inflight` 没有被丢结果卡住）。

## 4. 行为变化与边界

| 项 | 变化 |
| --- | --- |
| 删除房间 | 即使停录请求丢了，watcher 也会在 1 秒内按「用户停录」收尾；不会续录、不会弹结束通知 |
| 检测失败 | 同一句失败只告警/推事件一次；恢复时清掉行内错误并推一次 |
| 坏房间 | 按 2 倍、4 倍、8 倍封顶退避，不再按检测间隔硬打平台 |
| 日志 | 坏房间从「每拍一条 WARN」变成「一条 WARN + 每拍一条 debug」 |
| 关闭自动检测 | 排期与在途结果都保留；重开时补一拍，不会重复检测 |
| 平台侧下播确认 | 仍依赖检测节奏（F5 的取舍不变）：间隔越大，「平台已下播」确认越慢 |

## 5. 验收结论

- F2 有真机证据（1 秒内 `finished/stopped`、无通知、单会话）；
- F1 / F6 有真机证据（1 条 WARN、3、5、9、20、33 秒退避）；
- F4 有真机观察（关闭期间零请求、重开后无重复、无卡死），精确的「在途结果恰好跨过开关」时序仍以代码路径为准；
- F3 / F5 / F7 按 62 的结论只做文档化，不改代码：F3 是调大间隔后多跑一拍已排上的检测（无害），F5 是「平台下播确认依赖检测节奏」的取舍，F7 是并发上限挡住时的 debug 日志量（WARN 已不重复）。
- 未覆盖：真实 429、真实平台下播、睡眠唤醒、Windows、4 路以上并发。

现场已清理：`room=0`、`record_session=0`、设置回到 10 项默认值（删除临时加的 `monitor.*` 行）、`/tmp/fakebin` 与 `/tmp/hc-f2` 已删、无 hivecast/ffmpeg 残留进程。
