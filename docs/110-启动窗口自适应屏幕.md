# 110-启动窗口自适应屏幕

> 状态：v1 已实施（2026-11-09）；Rust 检查通过，需在不同分辨率屏幕上复看实际窗口大小。
> 范围：应用启动时按当前显示器工作区计算主窗口尺寸并居中，替代固定 1320×860。
> 前置阅读：`92-四页结构统一.md`。

## 0. 结论速览

- 启动时读取主窗口所在显示器（取不到则用主显示器）的工作区。
- 以工作区逻辑尺寸的 **86% 宽、88% 高**作为目标窗口。
- 宽度限制在 1040–1680，高度限制在 680–1040；再确保不超出工作区（留 32px）。
- 设置尺寸后调用 `center()`，窗口始终居中。
- 仍受 `tauri.conf.json` 的 `minWidth/minHeight` 约束。

## 1. 实现

`lib.rs` 的 `setup` 里，在窗口事件/托盘逻辑之前：

```rust
if let Ok(Some(monitor)) = window.current_monitor().or_else(|_| window.primary_monitor()) {
    let work = monitor.work_area();
    let scale = monitor.scale_factor().max(1.0);
    let logical_w = work.size.width as f64 / scale;
    let logical_h = work.size.height as f64 / scale;
    let width = (logical_w * 0.86).clamp(1040.0, 1680.0)
        .min((logical_w - 32.0).max(1040.0));
    let height = (logical_h * 0.88).clamp(680.0, 1040.0)
        .min((logical_h - 32.0).max(680.0));
    window.set_size(tauri::LogicalSize::new(width, height));
    window.center();
}
```

- 使用 `work_area()` 而不是整块屏幕，避免被任务栏/ Dock 挡住。
- 用 `scale_factor()` 把物理像素换算成逻辑像素，高 DPI 下窗口不会过大。
- 取不到当前显示器时回退 `primary_monitor()`；再取不到就保留配置文件尺寸。

## 2. 典型结果

| 屏幕工作区（逻辑） | 目标窗口 |
| --- | --- |
| 1920×1040 | 1651×915 |
| 1440×860 | 1238×757 |
| 1366×728 | 1175×680 |
| 1280×680 | 1100×680 |

实际会被 1040–1680 / 680–1040 的 clamp 和 `minWidth/minHeight` 再约束一次。

## 3. 验证

- `cargo check --all-targets`、`cargo fmt --check` 通过。
- 启动日志新增「启动窗口已按屏幕工作区缩放」，包含目标逻辑尺寸和屏幕工作区尺寸。
- 待复看：1080p / 2K / 高 DPI 缩放 125%/150% 下的窗口大小、任务栏遮挡和居中位置。

## 4. 已知限制

- **窗口先按配置尺寸创建再调整**：极端慢的机器上可能有一帧默认 1320×860 的闪动；如需完全消除，可把配置改为 `visible:false`，调整后再 `show()`。
- **最小尺寸优先**：屏幕工作区小于 1040×680 时，`minWidth/minHeight` 会让窗口大于屏幕；这是为了保证四页布局可用。
- **只在启动时计算**：拖动到另一块显示器后不会自动重算；用户手动调整的尺寸由系统记忆。
